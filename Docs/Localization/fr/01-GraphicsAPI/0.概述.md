# Vue d’ensemble des API graphiques

Avant de commencer à apprendre, vous devez réaliser clairement que C/C++ n’est qu’un **outil** pour **matérialiser** des **théories réalistes** dans un **ordinateur**, et vous devez être capable de l’utiliser avec maîtrise. Sinon, vous devriez continuer à vous perfectionner : l’auteur estime que vous n’êtes pas capable, voire pas qualifié, de poursuivre vos études avant d’avoir construit un système de connaissances fondamentales complet et une bonne culture de code.

> Définir ce point est assez difficile. On peut le comparer à la réflexion lors de la partie de [Spider Solitaire](https://baike.baidu.com/item/%E8%9C%98%E8%9B%9B%E7%BA%B8%E7%89%8C/877244) : il est préférable de demander une nouvelle distribution de cartes seulement quand on pense n’avoir plus de solution. Parce que l’entrée dans un nouveau domaine peut fournir des points de départ, mais elle expose aussi à de plus grands défis, voire à des impasses.

De plus, vous devez réfléchir à la nécessité d’apprendre ces connaissances. Si votre orientation professionnelle future est l’une des suivantes :

- Moteur de jeu, graphismes
- VR, AR, XR
- Logiciels industriels 3D
- Audio et vidéo

Alors l’apprentissage des **API graphiques bas niveau** est une étape obligatoire. Mais si vous vous concentrez davantage sur les effets artistiques et l’intérêt des graphismes, commencer directement par les moteurs de jeu et les logiciels de traitement 3D sera une meilleure option.

### Rasterisation

Qu’est-ce qu’un graphisme ?

Un triangle, un rectangle, un cercle, une forme comme une tasse... Si nous devons prendre en compte autant de choses, l’ordinateur aurait une infinité de règles à définir. Par conséquent, nous devons simplifier en utilisant des unités de base minimales pour englober tous les graphismes de la nature, et l’ordinateur n’aura qu’à traiter le rendu de ces unités de base. Ces unités de base (primitives) sont :

- Point
- Ligne
- Triangle

Elles peuvent être décrites à l’aide des structures de données suivantes :

```c++
struct Point {
    int x, y;
};

struct Line {
    std::array<Point, 2> points;
};

struct Triangle {
    std::array<Point, 3> vertices;
};
```

Si vous voulez dessiner un point sur le `FrameBuffer`, c’est très simple :

```c++
void drawPoint(std::vector<std::vector<char>>& frameBuffer, const Point& point) {
    frameBuffer[point.x][point.y] = '1';
}
```

Et si vous voulez dessiner une ligne sur le `FrameBuffer` ?

Une ligne est composée d’une série de points, mais il faut noter qu’une ligne contient un nombre infini de points, tandis que le nombre de points sur le `FrameBuffer` est fini. Par conséquent, une partie de la précision sera perdue lors du rendu, et nous n’avons qu’à calculer les coordonnées des points correspondants selon la précision. Ce processus est précisément la **rasterisation** ([Rasterisation](https://en.wikipedia.org/wiki/Rasterisation)).

Une ligne peut être représentée par une équation de droite : y = kx + b.

On peut résoudre les valeurs de `k` et `b` à partir des coordonnées de deux points. Si la précision est fixée à 1, il est facile de calculer les autres points entre les extrémités. Mais il faut noter que l’équation de droite ne peut pas représenter une ligne垂直e à l’axe x, donc il faut éviter le calcul de la pente. Cette méthode est la **DDA** ([Digital Differential Analyzer](https://en.wikipedia.org/wiki/Digital_differential_analyzer_(graphics_algorithm))). Voici une implémentation simplifiée :

```c++
void drawLine(std::vector<std::vector<char>>& frameBuffer, Line line) {
    int dx = line.points[1].x - line.points[0].x;
    int dy = line.points[1].y - line.points[0].y;

    if (dx == 0 && dy == 0) {            // Les extrémités se chevauchent, dessiner directement le point
        drawPoint(frameBuffer, line.points[0]);
    }

    int steps = abs(dx) > abs(dy) ? abs(dx) : abs(dy);

    float xInc = dx / (float)steps;      // Incrément de x
    float yInc = dy / (float)steps;      // Incrément de y

    float x = line.points[0].x;          // Valeur initiale de x
    float y = line.points[0].y;          // Valeur initiale de y

    for (int i = 0; i <= steps; i++) {   //
        drawPoint(frameBuffer, Point(round(x), round(y)));
        x += xInc;
        y += yInc;
    }
}
```

De plus, il existe d’autres algorithmes de rasterisation de lignes, que nous ne présenterons pas ici :

- [Algorithme de ligne de Bresenham](https://en.wikipedia.org/wiki/Bresenham's_line_algorithm)
- [Algorithme de ligne de Xiaolin Wu](https://en.wikipedia.org/wiki/Xiaolin_Wu's_line_algorithm)

Testez dans `renderFrame` :

```c++
void renderFrame(std::vector<std::vector<char>>& frameBuffer) {
    std::vector<Line> lines = {
        {0,0,39,0},
        {0,0,39,19}
    };

    for (const auto& line : lines) {
        drawLine(frameBuffer, line);
    }
}
```

La rasterisation d’un triangle est relativement plus complexe. Voici quelques algorithmes :

- Méthode de division
- Algorithme de Bresenham
- Algorithme barycentrique

La méthode de division est assez courante. Son principe central est simple : diviser un triangle en deux triangles dont la base est parallèle à l’axe X, puis remplir progressivement les lignes dans le sens vertical :

![img](../../../01-GraphicsAPI/Resources/generalTriangle.png)

Pour les détails de la démarche, veuillez lire :

- http://www.sunshine2k.de/coding/java/TriangleRasterization/TriangleRasterization.html

Voici une implémentation simplifiée :

```c++
void drawTriangle(std::vector<std::vector<char>>& frameBuffer, Triangle triangle) {
    std::sort(triangle.vertices.begin(), triangle.vertices.end(), [](const Point& a, const Point& b) {
        return a.y < b.y;
    });
    if (triangle.vertices[0] == triangle.vertices[1]    // Ne pas dessiner si les sommets se chevauchent
        || triangle.vertices[1] == triangle.vertices[2]
        || triangle.vertices[0] == triangle.vertices[2]
        )
        return;

    auto fillBottomFlatTriangle = [&](const Point& v1, const Point& v2, const Point& v3) {
        float invslope1 = (v2.x - v1.x) / (v2.y - v1.y);
        float invslope2 = (v3.x - v1.x) / (v3.y - v1.y);

        float curx1 = v1.x;
        float curx2 = v1.x;

        for (int scanlineY = v1.y; scanlineY <= v2.y; scanlineY++) {
            Line scanLine = {
             (int)curx1, scanlineY ,
             (int)curx2, scanlineY 
            };
            drawLine(frameBuffer, scanLine);
            curx1 += invslope1;
            curx2 += invslope2;
        }
    };

    auto fillTopFlatTriangle = [&](const Point& v1, const Point& v2, const Point& v3) {
        float invslope1 = (v3.x - v1.x) / (float)(v3.y - v1.y);
        float invslope2 = (v3.x - v2.x) / (float)(v3.y - v2.y);

        float curx1 = v3.x;
        float curx2 = v3.x;

        for (int scanlineY = v3.y; scanlineY > v1.y; scanlineY--) {
            Line scanLine = {
             (int)curx1, scanlineY ,
             (int)curx2, scanlineY
            };
            drawLine(frameBuffer, scanLine);
            curx1 -= invslope1;
            curx2 -= invslope2;
        }
    };
    if (triangle.vertices[1].y == triangle.vertices[2].y) {
        fillBottomFlatTriangle(triangle.vertices[0], triangle.vertices[1], triangle.vertices[2]);
    }
    else if (triangle.vertices[0].y == triangle.vertices[1].y) {
        fillTopFlatTriangle(triangle.vertices[0], triangle.vertices[1], triangle.vertices[2]);
    }
    else {
        Point mid = Point({
            (int)(triangle.vertices[0].x + ((float)(triangle.vertices[1].y - triangle.vertices[0].y) / (float)(triangle.vertices[2].y - triangle.vertices[0].y)) * (triangle.vertices[2].x - triangle.vertices[0].x))
            , triangle.vertices[1].y
        });
        fillBottomFlatTriangle(triangle.vertices[0], triangle.vertices[1], mid);
        fillTopFlatTriangle(triangle.vertices[1], mid, triangle.vertices[2]);
    }
}
```

### Pipeline de traitement

Dans un ordinateur, en plus de représenter des graphismes géométriques simples et statiques, il faut parfois dessiner des effets graphiques dynamiques et traités. Cela nécessite :

- Pouvoir effectuer des traitements sur chaque sommet, comme le déplacement, la rotation par rapport à l’origine des coordonnées, le redimensionnement, etc.
- Pouvoir effectuer des traitements supplémentaires sur les pixels du FrameBuffer, comme le coloriage, l’ajout de divers filtres, etc.

En combinant avec le `SwapChain` de la section précédente, on peut réaliser un petit programme comme celui-ci :

![18](../../../01-GraphicsAPI/Resources/18.gif)

Dans l’image ci-dessus, la taille du triangle est redimensionnée dynamiquement et une bordure `*` est ajoutée. Le code complet est le suivant :

```c++
#include <iostream>
#include <vector>
#include <algorithm>
#include <functional>
#include <array>
#include <Windows.h>

double GTime = 0;

struct Point {
    int x, y;
    bool operator == (const Point& other) { return x == other.x && y == other.y; }
};

struct Line {
    std::array<Point, 2> points;
};

struct Triangle {
    std::array<Point, 3> vertices;
};

void drawPoint(std::vector<std::vector<char>>& frameBuffer, const Point& point) {
    frameBuffer[point.x][point.y] = '1';
}

void drawLine(std::vector<std::vector<char>>& frameBuffer, Line line) {
    int dx = line.points[1].x - line.points[0].x;
    int dy = line.points[1].y - line.points[0].y;

    if (dx == 0 && dy == 0) {            // Les extrémités se chevauchent, dessiner directement le point
        drawPoint(frameBuffer, line.points[0]);
    }

    float steps = abs(dx) > abs(dy) ? abs(dx) : abs(dy);

    float xInc = dx / (float)steps;      // Incrément de x
    float yInc = dy / (float)steps;      // Incrément de y

    float x = line.points[0].x;          // Valeur initiale de x
    float y = line.points[0].y;          // Valeur initiale de y

    for (int i = 0; i <= steps; i++) {
        drawPoint(frameBuffer, Point(round(x), round(y)));
        x += xInc;
        y += yInc;
    }
}

void drawTriangle(std::vector<std::vector<char>>& frameBuffer, Triangle triangle) {
    std::sort(triangle.vertices.begin(), triangle.vertices.end(), [](const Point& a, const Point& b) {
        return a.y < b.y;
    });
    if (triangle.vertices[0] == triangle.vertices[1]    // Ne pas dessiner si les sommets se chevauchent, ignorer temporairement le cas de colinéarité
        || triangle.vertices[1] == triangle.vertices[2]
        || triangle.vertices[0] == triangle.vertices[2]
        )
        return;

    auto fillBottomFlatTriangle = [&](const Point& v1, const Point& v2, const Point& v3) {
        float invslope1 = (v2.x - v1.x) / (v2.y - v1.y);
        float invslope2 = (v3.x - v1.x) / (v3.y - v1.y);

        float curx1 = v1.x;
        float curx2 = v1.x;

        for (int scanlineY = v1.y; scanlineY <= v2.y; scanlineY++) {
            Line scanLine = {
             (int)curx1, scanlineY ,
             (int)curx2, scanlineY 
            };
            drawLine(frameBuffer, scanLine);
            curx1 += invslope1;
            curx2 += invslope2;
        }
    };

    auto fillTopFlatTriangle = [&](const Point& v1, const Point& v2, const Point& v3) {
        float invslope1 = (v3.x - v1.x) / (float)(v3.y - v1.y);
        float invslope2 = (v3.x - v2.x) / (float)(v3.y - v2.y);

        float curx1 = v3.x;
        float curx2 = v3.x;

        for (int scanlineY = v3.y; scanlineY > v1.y; scanlineY--) {
            Line scanLine = {
             (int)curx1, scanlineY ,
             (int)curx2, scanlineY
            };
            drawLine(frameBuffer, scanLine);
            curx1 -= invslope1;
            curx2 -= invslope2;
        }
    };
    if (triangle.vertices[1].y == triangle.vertices[2].y) {
        fillBottomFlatTriangle(triangle.vertices[0], triangle.vertices[1], triangle.vertices[2]);
    }
    else if (triangle.vertices[0].y == triangle.vertices[1].y) {
        fillTopFlatTriangle(triangle.vertices[0], triangle.vertices[1], triangle.vertices[2]);
    }
    else {
        Point mid = Point({
            (int)(triangle.vertices[0].x + ((float)(triangle.vertices[1].y - triangle.vertices[0].y) / (float)(triangle.vertices[2].y - triangle.vertices[0].y)) * (triangle.vertices[2].x - triangle.vertices[0].x))
            , triangle.vertices[1].y
        });
        fillBottomFlatTriangle(triangle.vertices[0], triangle.vertices[1], mid);
        fillTopFlatTriangle(triangle.vertices[1], mid, triangle.vertices[2]);
    }
}

/* Traitement par sommet
* Redimensionner dynamiquement la position du sommet selon le temps
*/
Point processVertex(const Point& point) {
    Point newPoint = point;
    double scaleFactor = 0.5 + 0.4 * std::sin(GTime);        // Assurer que le facteur de redimensionnement est dans [0.1, 0.9]
    newPoint.x *= scaleFactor;
    newPoint.y *= scaleFactor;
    return newPoint;
}

/* Traitement par pixel
* Contournement simple
*/
char processPixel(const std::vector<std::vector<char>>& frameBuffer, int x,int y) {
    static int direction[4][2] = { {0,1},{0,-1},{1,0},{-1,0} };    // Quatre directions
    for (int i = 0; i < 4; i++) {
        int xOff = x + direction[i][0];
        int yOff = y + direction[i][1];
        if (xOff >= 0                                            // Vérifier si le pixel est à l’intérieur de la bordure du frame, le pixel courant est 0 et les pixels周边 ont 1
            && xOff < frameBuffer.size()
            && yOff >= 0 
            && yOff < frameBuffer[0].size()
            && frameBuffer[x][y] == '0'
            && frameBuffer[xOff][yOff] == '1') {
            return '*';
        }
    }
    return frameBuffer[x][y];
}

void renderFrame(std::vector<std::vector<char>>& frameBuffer) {
    std::vector<Triangle> triangles = { 
        {0,0,40,0,20,19},
    };

    /* Traitement des sommets */
    for (auto& triangle : triangles) {
        for (auto& vertex : triangle.vertices) {
            vertex = processVertex(vertex);
        }
    }

    for (const auto& triangle : triangles) {
        drawTriangle(frameBuffer,triangle);
    }

    /* Traitement des pixels */
    std::vector<std::vector<char>> newFrameBuffer(frameBuffer);
    for (int x = 0; x < frameBuffer.size(); x++) {
        for (int y = 0; y < frameBuffer[x].size(); y++) {
            newFrameBuffer[x][y] = processPixel(frameBuffer, x, y);
        }
    }
    frameBuffer = newFrameBuffer;
}

int main() {
    HANDLE frontendBuffer = GetStdHandle(STD_OUTPUT_HANDLE);        // Obtenir le tampon par défaut
    HANDLE backendBuffer = CreateConsoleScreenBuffer(               // Créer un nouveau tampon comme tampon arrière-plan
        GENERIC_READ | GENERIC_WRITE,
        FILE_SHARE_READ | FILE_SHARE_WRITE,
        NULL,
        CONSOLE_TEXTMODE_BUFFER,
        NULL
    );
    // Cacher les curseurs des deux tampons
    CONSOLE_CURSOR_INFO cci;
    cci.bVisible = 0;
    cci.dwSize = 1;
    SetConsoleCursorInfo(frontendBuffer, &cci);
    SetConsoleCursorInfo(backendBuffer, &cci);

    const int width = 40;
    const int height = 20;
    const char clearCh = '0';
    const int MaxBufferSize = width * height * 10;

    char bufferData[MaxBufferSize];     // Zone de stockage temporaire des données du tampon
    DWORD bufferLength = 0;
    COORD zeroCoord = { 0,0 };
    while (true) {
        GTime += 0.01;
        bufferLength = 0;
        CONSOLE_SCREEN_BUFFER_INFO backendBufferInfo;      
        GetConsoleScreenBufferInfo(backendBuffer, &backendBufferInfo);
        int lineWidth = backendBufferInfo.srWindow.Right - backendBufferInfo.srWindow.Left + 1;

        std::vector<std::vector<char>> frameBuffer(width, std::vector<char>(height, clearCh));
        renderFrame(frameBuffer);

        for (int y = 0; y < height; y++) {
            for (int x = 0; x < width; x++) {
                bufferData[bufferLength++] = frameBuffer[x][y];
            }
            while (bufferLength % lineWidth != 0) {             // Remplir de caractères pour obtenir l’effet de saut de ligne
                bufferData[bufferLength++] = ' ';
            }
        }

        WriteConsoleOutputCharacterA(backendBuffer, bufferData, bufferLength, zeroCoord, &bufferLength);
        SetConsoleActiveScreenBuffer(backendBuffer);           
        std::swap(backendBuffer, frontendBuffer);              
    }
    return 0;
}
```

En plus des traitements par sommet et par pixel mentionnés ci-dessus, le pipeline de rendu graphique moderne prend en charge d’autres étapes programmable, qui seront expliquées en détail dans les chapitres suivants.

Le rendu graphique 3D consiste simplement à projeter des sommets 3D sur des coordonnées d’écran 2D par des calculs numériques, puis à dessiner. Nous recommandons vivement de parcourir intégralement :

- [Fondamentaux des mathématiques 3D - Graphismes et développement de jeux (2e édition)](https://baike.baidu.com/item/3D%E6%95%B0%E5%AD%A6%E5%9F%BA%E7%A1%80%EF%BC%9A%E5%9B%BE%E5%BD%A2%E5%92%8C%E6%B8%B8%E6%88%8F%E5%BC%80%E5%8F%91%EF%BC%88%E7%AC%AC2%E7%89%88%EF%BC%89)

Maintenant que nous avons la théorie du rendu, nous devons encore考虑 la performance dans l’ordinateur, car cela détermine le nombre maximum de triangles que l’on peut dessiner dans un laps de temps donné.

En résumant le code ci-dessus, nous pouvons constater :

- Le code contient de nombreux calculs numériques
- Le traitement des sommets, le traitement des pixels et le rendu des primitives n’influencent pas les uns les autres, ce qui signifie que ces opérations peuvent être parallélisées

Pour accélérer ce processus, l’architecture moderne des ordinateurs a ajouté un processeur spécialisé dans le rendu graphique : le GPU (**Graphics Processing Unit**, unité de traitement graphique).

### GPU

Le GPU moderne est très efficace dans la manipulation des [graphismes informatiques](https://en.wikipedia.org/wiki/Computer_graphics) et du [traitement d’images](https://en.wikipedia.org/wiki/Image_processing). ## API graphiques

> [ **API graphique** ](https://en.wikipedia.org/wiki/List_of_3D_graphics_libraries) fournit un moyen d’accès abstrait au matériel GPU, simplifiant les différentes étapes de génération des graphismes informatiques, de sorte que les développeurs n’ont pas besoin de connaître les détails du matériel, mais se concentrent sur la construction des graphismes.
>
> Elle peut être entièrement réalisée en [logiciel](https://en.wikipedia.org/wiki/Computer_software) et exécutée sur le [CPU](https://en.wikipedia.org/wiki/Central_processing_unit), ce qui est courant dans les [systèmes embarqués](https://en.wikipedia.org/wiki/Embedded_system), ou accélérée par le [GPU](https://en.wikipedia.org/wiki/Graphics_processing_unit) en [matériel](https://en.wikipedia.org/wiki/Hardware_acceleration), ce qui est plus courant dans les [PC](https://en.wikipedia.org/wiki/Personal_computer) et principalement utilisé dans les [jeux vidéo](https://en.wikipedia.org/wiki/Video_game) et les [simulations](https://en.wikipedia.org/wiki/Simulation_video_game).
>

Les API graphiques 3D主流 actuelles sont :

- DX11, [DX12](https://www.nvidia.com/en-sg/geforce/technologies/dx12/) : Interface de programmation graphique 3D développée par la société [Microsoft](https://zh.wikipedia.org/wiki/微軟) sur le système [Windows](https://zh.wikipedia.org/wiki/Microsoft_Windows)
- [OpenGL](https://www.opengl.org/) : OpenGL est un ensemble d’API multiplateformes et multilingues. Son implémentation existe sur Windows, certaines versions d’UNIX et Mac OS. Ces implémentations sont généralement fournies par les fabricants de cartes graphiques et dépendent fortement du matériel qu’ils fournissent.
- [Vulkan](https://www.vulkan.org/) : La prochaine génération d’OpenGL. En comparaison, Vulkan est plus proche du niveau bas et peut bien distribuer les cœurs CPU pour exécuter des tâches parallèles.
- [Metal](https://developer.apple.com/metal/) : L’API Metal est fournie par Apple. Elle vise à fournir un accès bas niveau au matériel GPU pour les applications sur [iOS](https://en.wikipedia.org/wiki/IOS), [iPadOS](https://en.wikipedia.org/wiki/IPadOS), [macOS](https://en.wikipedia.org/wiki/MacOS) et [tvOS](https://en.wikipedia.org/wiki/TvOS) afin d’améliorer les performances. Elle appartient, comme Vulkan et DX12, aux API de bas niveau.

Beaucoup d’entre vous ont probablement une première réaction face à elles :

- Parmi ces API, laquelle est la plus puissante ? Laquelle faut-il apprendre ?

Sur cette question, chacun a sa propre opinion, par exemple :

### QRhi

L’un des principaux objectifs de Qt6 est de faire sortir Qt de l’utilisation directe d’OpenGL et, grâce à une abstraction appropriée, de permettre des opérations sur une gamme plus large d’API graphiques, telles que [Vulkan](https://www.khronos.org/vulkan/), [Metal](https://developer.apple.com/metal/) et [Direct3D](https://docs.microsoft.com/en-us/windows/win32/direct3d). [OpenGL](https://www.khronos.org/opengl/) (et [OpenGL ES](https://www.khronos.org/opengles/)) : la motivation principale derrière cela n’est pas d’obtenir des performances, mais de garantir que **Qt est omniprésent** sur les plateformes et les appareils où OpenGL n’est pas disponible ou n’est plus nécessaire, et ce sera le cas à l’avenir. En même temps, pouvoir construire sur des API modernes, de bas niveau et explicites peut aussi améliorer les performances (par exemple, réduire l’utilisation du CPU grâce à une overhead API moindre). C’est le moteur de rendu derrière [Qt Quick](https://doc.qt.io/qt-5/qtquick-index.html#) et d’autres modules. Son architecture est la suivante :

![rhiarch-3](../../../01-GraphicsAPI/Resources/68747470733a2f2f7777772e71742e696f2f68732d66732f68756266732f726869617263682d332e706e673f77696474683d383030266e616d653d726869617263682d332e706e67.png)

> Dans la branche actuelle des développeurs officiels, QRhi prend déjà en charge DX12, et il est prévu qu’il soit mis en ligne avec Qt6.6.

Dans Qt6, il n’utilise plus de code shader GLSL compatible avec OpenGL, mais écrit en GLSL de style Vulkan, puis il est réfléchi et traduit en d’autres langages de shader (HLSL, MSL), enfin empaqueté dans un objet QShader sérialisable pour être utilisé par QRhi. Son flux de travail est le suivant :

![Conditionnement du shader](../../../01-GraphicsAPI/Resources/shaderconditioning.pngwidth=1280&name=shaderconditioning.png)

Vous pouvez trouver son code source à l’emplacement suivant :

![image-20230224200924150](../../../01-GraphicsAPI/Resources/image-20230224200924150.png)

Les fichiers clés sont :

- qrhi_p.h : Définit les structures et les opérations des différentes ressources graphiques
- qrhi.cpp : Implémentation de la planification de QRhi, avec de nombreuses notes explicatives
- qrhi_p_p.h : Définit le squelette structurel complet de QRhi

Les autres fichiers commençant par `qrhi` sont des implémentations spécifiques à des API graphiques particulières.
