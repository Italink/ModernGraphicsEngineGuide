**Texture Graph** est un plugin expérimental introduit dans UE 5.4, principalement utilisé pour la génération procédurale de textures.

## Vue d'ensemble

Si vous êtes un développeur graphique, vous savez que nous utilisons de nombreux **pipelines de rendu graphique (Graphics Rendering Pipeline)** pour dessiner des formes géométriques **(Primitive)** sur une **cible de rendu (Render Target)** (que l'on peut comprendre comme une texture ou une image). Ce processus s'appelle généralement **Base Pass** (ou **Mesh Pass**, **Primitives Pass**) :

![image-20231006120654050](../../../04-UnrealEngine/Resources/image-20231006120654050.png)

Pour l'image finale présentée au public, nous devons souvent ajouter des effets supplémentaires (tels que l'éclairage global, le post-traitement...) sur la base de l'image sortie par le Base Pass :

![image-20231006114116772](../../../04-UnrealEngine/Resources/image-20231006114116772.png)

Ces effets sont généralement générés à l'aide d'une série de Render Pass. Un Render Pass nécessite souvent des textures en entrée et génère finalement des RT (Render Target). Ces RT générés peuvent ensuite être utilisés comme textures d'entrée pour un autre Render Pass. En considérant ces Render Pass comme des nœuds et en connectant leurs entrées et sorties par des lignes, nous obtenons finalement une structure graphique :

![image-20240921164132083](../../../04-UnrealEngine/Resources/image-20240921164132083.png)

Nous l'appelons généralement **Render Graph / Frame Graph**.

Le Texture Graph que nous utilisons suit un processus similaire, sauf que le Render Graph est utilisé pour dessiner une frame d'image de jeu, tandis que le Texture Graph **généralement** est utilisé pour **générer des actifs de texture pendant la phase de l'éditeur**.

## Utilisations

Bien que Texture Graph soit essentiellement destiné à la création de textures procédurales, son ensemble de fonctionnalités est bien moins complet que les outils de texture procédurale matures (comme [Substance Designer](https://www.adobe.com/hk_en/products/substance3d/apps/designer.html)). Il convient mieux à des personnes comme moi qui n'ont pas une connaissance approfondie des textures procédurales, qui ne maîtrisent pas bien Photoshop, mais qui savent écrire du code et possèdent des connaissances de base en traitement d'images.

Je l'utilise pour ces tâches :

1. Faire glisser des nœuds pour écrire rapidement la logique de traitement d'images simples. Pour les développeurs, quand les entrées et sorties sont claires, écrire du code est souvent plus intuitif et efficace que manipuler l'éditeur.

2. Construire des pipelines de génération de textures réutilisables, c'est-à-dire la modularisation. Cela est très utile si il existe une grande quantité de textures sources (entrées) ou si les textures sources sont fréquemment mises à jour au fil du temps.

### Petit outil de traitement d'images

Il y a quelque temps, j'ai regardé *Ashes of Time* et il y a un plan super cool 0.0

![微信图片_20240817215316](../../../04-UnrealEngine/Resources/%E5%BE%AE%E4%BF%A1%E5%9B%BE%E7%89%87_20240817215316.png)

J'ai pensé à l'utiliser comme arrière-plan, mais le style est un peu gras. Transformer en noir et blanc pourrait être plus beau, donc j'ai fait une conversion en niveaux de gris :

![82770255820153](../../../04-UnrealEngine/Resources/82770255820153.png)

Ça semble pas mal, mais le brillant sur le bout du nez me semble bizarre. J'ai donc ouvert Photoshop :

- J'ai essayé le pinceau d'effacement, ça ne marche pas, ça devient flou.
- J'ai utilisé l'outil lasso pour sélectionner la zone brillante et ajuster la plage de luminosité. Oh non, les bords ne peuvent pas être lissés après ajustement.

C'est une logique très simple : je voulais juste que le bout du nez ne soit pas aussi brillant. Après avoir gaspillé du temps, j'ai ouvert Qt et écrit un pipeline de rendu, résolu en quelques lignes de code. Le code du shader de fragment ressemble à ceci (les valeurs ne sont pas exactes) :

``` c++
void main(){
    vec4 TextureColor = texture(Texture, UV);
    float Gray = (TextureColor.r + TextureColor.g + TextureColor.b) / 3;		// Conversion en niveaux de gris
    if( UV.x > 0.53 && UV.x < 0.56 && UV.y > 0.45 && UV.y < 0.51)					// Sélection de la zone
    {
        if(Gray > 0.2)															// Sélection des parties avec valeur de gris supérieure à 0.2
        {
            Gray = 0.2 + (Gray - 0.2) * 0.1; 									// Réduire la valeur de gris des parties dépassant 0.2 à 10% de l'original.
        }
    }
    OutFragColor = vec4(Gray, Gray, Gray, 1);
}
```

Le résultat final est pas mal :

![26b522e2fa38b897c6e61bb8b4d5042](../../../04-UnrealEngine/Resources/26b522e2fa38b897c6e61bb8b4d5042.jpg)

Bien sûr, on peut aussi l'implémenter rapidement avec Python et OpenCV, mais beaucoup d'utilisateurs d'UE ne savent pas écrire de code ni utiliser ces logiciels complexes (apprendre UE est déjà difficile). Mais ils savent généralement créer des matériaux, donc l'intérêt de Texture Graph est de permettre aux utilisateurs d'UE de faire du traitement d'images simple sans avoir à apprendre un logiciel complexe pour une demande simple.

Il est également très simple de modifier Texture Graph pour réaliser la même fonction :
