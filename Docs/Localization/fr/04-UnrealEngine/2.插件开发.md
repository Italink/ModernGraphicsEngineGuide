Les plugins existent en dehors du code du moteur et du projet. Ils sont le principal moyen d'étendre les fonctionnalités du programme dans Unreal Engine (UE).

Un plugin est essentiellement une conception de code modulaire. Suivre cette conception réduit les dépendances entre les codes, facilitant ainsi l'itération et la maintenance ultérieures.

Dans UE, la structure de fichiers standard d'un plugin est la suivante :

![image-20230525143413268](../../../04-UnrealEngine/Resources/image-20230525143413268.png)

-   `Binaries` : Stocke les fichiers générés par la compilation
-   `Content` : Stocke le contenu des actifs du plugin
-   `Intermediate` : Stocke les fichiers intermédiaires générés pendant la compilation
-   `Resources` : Stocke les fichiers ressources du plugin, tels que les icônes (non des actifs UE)
-   `Source` : Stocke les fichiers sources du code, pouvant contenir plusieurs modules

-   `*.uplugin` : Fichier d'organisation de la structure du plugin

Le contenu de base de `*.uplugin` est le suivant :

``` c++
{
	"FileVersion": 3,				// Version du fichier
	"Version": 1,					// Numéro de version
	"VersionName": "1.0",			// Nom de la version
	"FriendlyName": "CustomPlugin",	// Nom convivial
	"Description": "",				// Description
	"Category": "Other",			// Catégorie
    "CreatedBy": "",				// Auteur
	"CreatedByURL": "",				// Lien de l'auteur
	"DocsURL": "",					// Lien de documentation
	"MarketplaceURL": "",			// Lien de la Marketplace
	"SupportURL": "",				// Lien de support
	"CanContainContent": false,		// Indique si le plugin peut contenir un répertoire de contenu
	"IsBetaVersion": false,			// Indique si c'est une version bêta
	"IsExperimentalVersion": false,	// Indique si c'est une version expérimentale
	"Installed": false,				// Indique si le plugin est intégré
	"Modules": [					// Définition des modules
		{
			"Name": "CustomPlugin",		// Nom du module
			"Type": "Editor",			// Type du module
			"LoadingPhase": "Default"	// Phase de chargement
		}
        //,								// Autres modules
        //{
        //	...    
        //}
	]
}
```

Pour la configuration de ces paramètres, consultez la documentation détaillée :

-   https://docs.unrealengine.com/5.2/en-US/unreal-engine-modules

-   Créez un plugin vide

Une fois que vous maîtrisez leur fonctionnement, vous pouvez simplement ajouter les éléments nécessaires au plugin vide.

Voici les fichiers indispensables dans un plugin C++ :

``` c++
// MyPlugin.h

#pragma once

#include "CoreMinimal.h"
#include "Modules/ModuleManager.h"

class FMyPluginModule : public IModuleInterface
{
public:

	/** Implémentation de IModuleInterface */
	virtual void StartupModule() override;
	virtual void ShutdownModule() override;
};
```

``` c++
// MyPlugin.cpp

#include "MyPlugin.h"

#define LOCTEXT_NAMESPACE "FMyPluginModule"

void FMyPluginModule::StartupModule()
{
	// Ce code s'exécutera après le chargement du module en mémoire ; le timing exact est spécifié dans le fichier .uplugin par module
}

void FMyPluginModule::ShutdownModule()
{
	// Cette fonction peut être appelée pendant l'arrêt pour nettoyer le module. Pour les modules qui prennent en charge le rechargement dynamique,
	// nous appelons cette fonction avant de décharger le module.
}

#undef LOCTEXT_NAMESPACE
	
IMPLEMENT_MODULE(FMyPluginModule, MyPlugin)		// Définition de l'entrée du plugin
```

UE appelle `StartupModule()` lors du chargement du plugin et `ShutdownModule()` lors de son déchargement.

Le flux de travail de développement du plugin est principalement le suivant :

-   Dans `StartupModule()`, appelez les interfaces de fonction des modules core ou utilisez les singletons globaux des modules core pour effectuer des opérations, ou montez certaines logiques sur les points d'entrée des modules core pour étendre les fonctionnalités.
-   Dans `ShutdownModule()`, nettoyez les opérations effectuées dans `StartupModule()`.

Les singletons globaux courants sont :

-   `GEngine`, `GEditor`, `GWorld` : Singletons globaux courants dans le moteur
-   `FModuleManager::LoadModuleChecked<FAssetToolsModule>("AssetTools").Get()` : Création, suppression, renommage, importation/exportation des actifs...

## Extension de la barre de menu et de la barre d'outils

Pendant le développement du moteur, il est souvent nécessaire d'étendre la barre de menu et la barre d'outils de l'éditeur du moteur en ajoutant un bouton pour effectuer des opérations pratiques, comme ceci :

![image-20220526100322912](../../../04-UnrealEngine/Resources/image-20220526100322912.png)

![image-20220526115630692](../../../04-UnrealEngine/Resources/image-20220526115630692.png)

Dans UE4, la principale méthode pour étendre les menus est via **FExtender**. Dans UE5, une nouvelle méthode plus facile à utiliser a été introduite : **UToolMenus**.

**UToolMenus** est une classe singleton, et vous pouvez obtenir une instance singleton via le code suivant :

``` c++
UToolMenus* ToolMenus = UToolMenus::Get();
```

Dans UE5, tous les menus et barres d'outils extensibles appellent la fonction `UToolMenus::RegisterMenu` pour s'enregistrer lors de leur initialisation :

```c++
UToolMenu* UToolMenus::RegisterMenu(const FName InName,
                                    const FName InParent = NAME_None,
                                    EMultiBoxType InType = EMultiBoxType::Menu,
                                    bool bWarnIfAlreadyRegistered = true)
```

![image-20230524155859423](../../../04-UnrealEngine/Resources/image-20230524155859423.png)

Cette fonction est utilisée pour enregistrer un `ToolMenu` extensible. Les paramètres de la fonction sont les suivants :

-   `InName` : Champ chaîné utilisé pour l'enregistrement, sous la forme `LevelEditor.LevelEditorToolBar.User`. Vous pouvez ensuite utiliser ce champ comme clé pour obtenir `UToolMenu`.
-   `InParent` : Spécifie le parent du menu d'outils.
-   `InType` : Spécifie le type du `ToolMenu`, qui détermine comment le menu peut être étendu. Il peut prendre les valeurs suivantes :
    -   `MenuBar` : Barre de menu, prend en charge l'extension des menus
    -   `ToolBar` : Barre d'outils, permet d'ajouter des boutons d'outils
    -   `VerticalToolBar` : Barre d'outils verticale
    -   `SlimHorizontalToolBar` : Barre d'outils horizontale, version simplifiée de la barre d'outils, permettant d'aligner horizontalement les icônes et les éléments de texte
    -   `UniformToolBar` :
    -   `Menu` : Menu, permet d'ajouter des éléments de menu
    -   `ButtonRow` : Boutons arrangés en lignes, chaque ligne ayant un nombre maximum de boutons, similaire à une barre d'outils mais pouvant avoir plusieurs lignes
-   `bWarnIfAlreadyRegistered` : Valeur booléenne, émet un avertissement si le champ est déjà enregistré.

Lorsqu'il est nécessaire de `prévisualiser le menu`, la fonction `UToolMenus::GenerateWidget` est appelée pour générer le contrôle `ToolMenu` :

```c++
TSharedRef<SWidget> UToolMenus::GenerateWidget(const FName Name, const FToolMenuContext& InMenuContext)
```

![image-20230524154628869](../../../04-UnrealEngine/Resources/image-20230524154628869.png)

Après l'enregistrement du `ToolMenu` et à tout moment avant la prévisualisation, nous pouvons étendre le contenu de la barre de menu via la fonction `UToolMenus::ExtendMenu`.

``` c++
UToolMenu* UToolMenus::ExtendMenu(const FName InName)
```

![image-20230524160554125](../../../04-UnrealEngine/Resources/image-20230524160554125.png)

Le code ci-dessus contient de nombreuses références d'extension, et voici un exemple simple d'extension de plugin :

``` c++
#pragma once

#include "Modules/ModuleManager.h"

class FCustomPluginModule : public IModuleInterface
{
public:
	virtual void StartupModule() override {
		// Ajoute un callback au démarrage de UToolMenus lors du lancement du plugin
		UToolMenus::RegisterStartupCallback(FSimpleMulticastDelegate::FDelegate::CreateRaw(this, &FCustomPluginModule::RegisterMenus));
	}

	virtual void ShutdownModule() override {
		// Supprime le callback de démarrage de UToolMenus et réinitialise certains états
		UToolMenus::UnRegisterStartupCallback(this);
		UToolMenus::UnregisterOwner(this);
	}
private:
	void RegisterMenus() {
		FToolMenuOwnerScoped OwnerScoped(this);
		UToolMenu* Menu = UToolMenus::Get()->ExtendMenu("LevelEditor.LevelEditorToolBar.PlayToolBar");
		FToolMenuSection& Section = Menu->FindOrAddSection("PluginTools");
		FToolMenuEntry& MenuEntry = Section.AddEntry(
			FToolMenuEntry::InitToolBarButton(			// Ajoute un bouton à la barre d'outils
				"CustomToolbarButton",
				FUIAction
				(
					FExecuteAction::CreateLambda([]() {
						FMessageDialog::Open(EAppMsgType::Ok, NSLOCTEXT("CustomNs", "HelloWorld", "Hello World!"));
					})
				)
			)
		);
		MenuEntry.InsertPosition = FToolMenuInsert(NAME_None, EToolMenuInsertType::First);
	}
};
```

Ce code ajoute un bouton à la barre d'outils du panneau principal de l'éditeur de niveaux. Lorsque vous cliquez sur ce bouton, une boîte de dialogue affichant `Hello World` s'ouvre :

![image-20230524163937497](../../../04-UnrealEngine/Resources/image-20230524163937497.png)

### Annulation et rétablissement

UObject possède un mécanisme de transaction. Si UObject possède le drapeau `RF_Transactional`, vous pouvez utiliser le code suivant :

```C++
GEditor->BeginTransaction(NSLOCTEXT("NS", "Transaction", "Transaction"));       // Démarre la transaction
Object->Modify();               // Cette opération stocke l'état actuel de Object dans la transaction

SomeChange(Object);             // Modifie certaines propriétés de Object

GEditor->EndTransaction();      // Termine la transaction et soumet le nouvel état de Object
```

L'opération ci-dessus permet à `SomeChanged` d'être annulée ou rétablie.

> Pour plus de détails, consultez : https://blog.csdn.net/qq_29523119/article/details/96778797

Pendant le développement de l'éditeur, il est souvent nécessaire qu'un objet ou une fenêtre réponde aux changements lors de l'annulation ou du rétablissement (par exemple, pour effectuer une reconstruction). UE fournit l'interface **FEditorUndoClient** pour écouter les événements d'annulation et de rétablissement. Voici un exemple simple de code :

```C++
class FUndoRedoListener: public FEditorUndoClient{
public:
    FUndoRedoListener(){
        if (GEditor)
            GEditor->RegisterForUndo(this);     // Enregistre le listener au bon moment, pas nécessairement dans le constructeur
    }
    ~FUndoRedoListener(){
        if (GEditor)
            GEditor->UnregisterForUndo(this);   // Annule l'enregistrement
    }
protected:
    virtual void PostUndo(bool bSuccess) override{      // Appelé après que l'éditeur a effectué une annulation
        RebuildSomething();
    }
    virtual void PostRedo(bool bSuccess) override{      // Appelé après que l'éditeur a effectué un rétablissement
        RebuildSomething();
    }
};
```

#### TCHAR

> En général, les chaînes de caractères dans le code sont encodées en **ANSI**, mais comme **ANSI** prend en charge peu de caractères, vous devriez utiliser la macro **TEXT()** lors de la définition de littéraux de variables de chaîne pour convertir les littéraux **ANSI** en **TCHAR** (encodage Unicode natif).

``` c++
TCHAR* ThisIsTChars = TEXT("This is Raw String");

#### [FName](https://docs.unrealengine.com/4.27/en-US/ProgrammingAndScripting/ProgrammingWithCPP/UnrealArchitecture/StringHandling/FName/)

> Utilisé pour la nomination, il n'est pas sensible à la casse. Pour faciliter la localisation rapide d'une ressource, FName calcule une valeur de hachage en fonction du contenu de la chaîne lors de sa création, de sorte que la comparaison se fait directement via la valeur de hachage au lieu de comparer le contenu de la chaîne.

> ### Conversions mutuelles
>
> ```c++
> TestString = TestName.ToString();
> TestString = TestText.ToString();
> 
> TestName = FName(*TestString);
> TestName = TestText	 // La conversion de FText à FName n'existe pas, mais vous pouvez passer par FString puis FName, mais cela n'est pas fiable car FName n'est pas sensible à la casse.
> 
> TestText = FText::FromName(TestName)
> TestText = FText::FromString(TestString)
> ```

void UBPLibrary::SetStaticMeshPivot(UStaticMesh* InStaticMesh, EStaticMeshPivotType PivotType)
{
	if(InStaticMesh == nullptr)
		return;
	auto InteractiveToolsContext = NewObject<UEditorInteractiveToolsContext>();
	InteractiveToolsContext->InitializeContextWithEditorModeManager(&GLevelEditorModeTools(), nullptr);
	UE::TransformGizmoUtil::RegisterTransformGizmoContextObject(InteractiveToolsContext);

	InteractiveToolsContext->ToolManager->RegisterToolType("EditPivotTool", NewObject<UEditPivotToolBuilder>());
	UStaticMeshComponent* StaticMeshComp = NewObject<UStaticMeshComponent>();
	StaticMeshComp->SetStaticMesh(InStaticMesh);

	InteractiveToolsContext->TargetManager->AddTargetFactory(NewObject<UStaticMeshComponentToolTargetFactory>());
	UToolTarget* Target = InteractiveToolsContext->TargetManager->BuildTarget(StaticMeshComp, FToolTargetTypeRequirements());

	InteractiveToolsContext->ToolManager->SelectActiveToolType(EToolSide::Left, "EditPivotTool");
	GLevelEditorModeTools().SelectNone();
	GLevelEditorModeTools().GetSelectedComponents()->Select(StaticMeshComp);

	InteractiveToolsContext->ToolManager->ActivateTool(EToolSide::Left);
	if (auto EditTool = Cast<UEditPivotTool>(InteractiveToolsContext->ToolManager->ActiveLeftTool))
	{
		EditTool->SetTargets({ Target });
		EditTool->RequestAction((EEditPivotToolActions)PivotType);
		EditTool->Tick(0.1);
		EditTool->Shutdown(EToolShutdownType::Accept);
	}
}
```
