## Base

Dans UE, pour utiliser Slate, il faut connaître trois structures clés :

-   **FSlateApplication** : Singleton global, centre de distribution de toutes les UI.
-   **SWindow** : Fenêtre de niveau supérieur, qui détient une instance de fenêtre multiplateforme (FGenericWindow) et fournit des configurations et opérations relatives à la fenêtre.
-   **SWidget** : Widget, qui divise la zone de la fenêtre et traite les événements d'interaction et de rendu dans sa propre zone.

### Utilisation de base

Voici un exemple simple d'utilisation de Slate dans UE :

```C++
auto Window = SNew(SWindow)							//Créer une fenêtre
    .ClientSize(FVector2D(600, 600))				//Définir la taille de la fenêtre
    [												//Remplir le contenu de la fenêtre
        SNew(SHorizontalBox)						//Créer une boîte horizontale
        + SHorizontalBox::Slot()					//Ajouter un slot de sous-contrôle
        [											
            SNew(STextBlock)						//Créer un bloc de texte
            .Text(FText::FromString("Hello"))		//Définir le contenu du bloc de texte
        ]
        + SHorizontalBox::Slot()					//Ajouter un slot de sous-contrôle
        [
            SNew(STextBlock)						//Créer un bloc de texte
            .Text_Lambda([](){ 						//Définir le contenu du bloc de texte	
                return FText::FromString("Slate");
            })		
        ]
	];
FSlateApplication::Get().AddWindow(Window, true);	//Enregistrer la fenêtre et l'afficher immédiatement
```

Le style de code de Slate est le suivant :

-   Les classes des contrôles Slate sont généralement nommées avec un préfixe `S`
-   On peut construire rapidement des contrôles Slate via les fonctions suivantes :
    -   `SNew( WidgetType, ... )` : Mode de construction générique
    -   `SAssignNew( ExposeAs, WidgetType, ... )` : Après construction, assigner le contrôle à `ExposeAs`
    -   `SArgumentNew( InArgs, WidgetType, ... )` : Construction à l'aide d'un jeu de paramètres

-   Dans l'expression de code de construction, on peut définir les paramètres de construction des contrôles via certaines fonctions. Comme ces fonctions retournent toutes une référence au contrôle lui-même, on peut effectuer des appels en chaîne
    -   On peut appeler des fonctions via `operator .` pour définir les propriétés et événements des contrôles
    -   Pour les sous-classes de **SPanel**, on peut utiliser `operator +SPanelType::Slot` pour ajouter des slots de sous-contrôles 
    -   Pour **SCompoundWidget** et **SPanel::Slot**, on peut utiliser `operator []` pour remplir les sous-contrôles
    -   Pour les propriétés et événements de Slate, on peut les lier de plusieurs manières. Par exemple, `.Text(...)` définit une valeur statique, mais on peut aussi lier une fonction pour obtenir dynamiquement la valeur de la propriété :
        -   `Text_Lambda(...)`
        -   `Text_Raw(...)`
        -   `Text_Static(...)`
        -   `Text_UObject(...)`

Dans le développement de contrôles, on peut s'appuyer sur certaines expériences (ce qui est raisonnable existe) et l'assistance de l'IDE pour écrire le code.

### Concepts de base

Pour le développement UI, il faut connaître les concepts de base suivants :

-   **États de base de la fenêtre** : Activé (Active), Focus, Visible, Modal, Transform
-   **Stratégies de layout et concepts associés** :
    -   Layout en boîte (HBox, VBox), layout en flux (Flow), layout en grille (Grid), layout en ancrage (Anchors), layout en chevauchement (Overlap), Canevas (Canvas)
    -   Padding, Margin, Spacing, Alignment
-   **Gestion des styles** : Icône (Icon), Style, Pinceau (Brush)
-   **Gestion des polices** : Type de police (Font Family), Mesure de la largeur du texte (Font Measure)
-   **Calcul des dimensions** : Stratégie de calcul des dimensions des contrôles
-   **Événements d'interaction** : Souris, clavier, glisser-déposer, événements de focus, mécanisme de traitement des événements, capture de la souris
-   **Événements de rendu** : Éléments de rendu, découpe de zone
-   **Contrôles de base** : Étiquette (Label), Bouton (Button), Case à cocher (Check), Liste déroulante (Combo), Curseur (Slider), Barre de défilement (Scroll Bar), Champ de texte (Text), Boîte de dialogue (Dialog), Sélection de couleur (Color), Barre de menu (Menu Bar), Menu (Menu), Barre d'état (Status Bar), Panneau de défilement (Scroll), Panneau de pile (switch) (Stack/Switcher), Panneau de liste (List), Panneau arborescent (Tree)...
-   **Internationalisation** : Traduction de localisation du texte (Localization)

### Processus de développement

La majeure partie du travail de développement Slate peut être résumée comme suit :

-   **Définir les propriétés des contrôles**
-   **Lier la logique des événements**
-   **Organiser la hiérarchie**

SWidget est une classe abstraite de base. UE l'a dérivée selon différents modes d'utilisation, en la divisant en quatre grandes catégories :

-   **SCompoundWidget** : Peut définir ChildSlot

    >   Principal moyen d'extension fourni par Slate aux développeurs. On hérite généralement de lui pour utiliser des SWidget existants afin d'organiser une série de Widget.

-   **SPanel** : Peut être considéré comme un conteneur de SWidget, peut contenir un ou plusieurs ChildSlot, utilisé pour ajouter des SWidget.

    > Slate a déjà dérivé suffisamment de SPanel pour organiser le layout de Slate et diverses opérations. En général, on dérive rarement de lui.

- **SLeafWidget** : Contrôle feuille, ne contient pas de ChildSlot

    >   On le dérive principalement pour personnaliser certains contrôles possédant un mécanisme de rendu et de traitement des dimensions unique

- **SWeakWidget** : Définit l'appartenance logique plutôt que l'événementiel.

    > Les SWidget dans SPanel ont une relation hiérarchique sur le plan des événements, mais parfois des cas spéciaux se produisent, par exemple, cliquer sur un bouton pour ouvrir un menu. Le menu peut être considéré comme appartenant à ce bouton, mais本质上 le menu ouvre une nouvelle fenêtre, et ils n'ont pas de relation hiérarchique sur le plan de la transmission des événements. Donc il faut compter sur SWeakWidget pour résoudre ce problème. En général, on l'utilise rarement.

La plupart du temps, on ajoute une classe C++ qui hérite de **SCompoundWidget**, et on remplit les sous-contrôles dans la fonction `Construct`, comme ceci :

``` c++
class SCustomWidget: public SCompoundWidget
{
public:
	SLATE_BEGIN_ARGS(SCustomWidget) {}				//Définir les paramètres Slate
	SLATE_END_ARGS()
public:
	void Construct(const FArguments& InArgs){		//Utiliser SNew revient essentiellement à appeler cette fonction
        ChildSlot									//Remplir les sous-contrôles
        [
            SNew(STextBlock)
            .Text(FText::FromString("This is body"))
        ];
    }
};
```

Ainsi, on peut utiliser le code suivant pour créer ce contrôle :

``` c++
auto MyWidget = SNew(SCustomWidget);
```

Si on veut ajouter un **paramètre (Argument)**, par exemple permettre de définir le contenu textuel, on peut modifier la définition comme suit :

``` c++
class SCustomWidget : public SCompoundWidget
{
public:
	SLATE_BEGIN_ARGS(SCustomWidget)							
		: _Text(FText::FromString("Default")) {		//Initialiser la valeur par défaut du paramètre, le nom de la variable est le nom du paramètre défini avec un underscore devant
		}				
		SLATE_ARGUMENT(FText,Text)					//Utiliser la macro SLATE_ARGUMENT pour définir le paramètre
	SLATE_END_ARGS()
public:
	void Construct(const FArguments& InArgs) {		
		Text = InArgs._Text;						//Recevoir le paramètre transmis
		ChildSlot									
        [
            SNew(STextBlock)
            .Text(Text)								//Transmettre le contenu textuel
        ];
	}
private:
	FText Text;
};
```

Ainsi, on peut utiliser le code suivant pour définir le contenu du contrôle :

``` c++
auto MyWidget = SNew(SCustomWidget)
    				.Text(FText::FromString("Hello"));
```

Bien sûr, on peut aussi ne pas passer par FArguments, directement comme ceci :

```c++
class SCustomWidget : public SCompoundWidget
{
public:
	SLATE_BEGIN_ARGS(SCustomWidget){}				
	SLATE_END_ARGS()
public:
	void Construct(const FArguments& InArgs, FText InText) {	//Transmettre directement via les paramètres de la fonction Construct
		Text = InText;						
		ChildSlot									
		[
            SNew(STextBlock)
            .Text(Text)
		];
	}
private:
	FText Text;
};

```

``` c
auto MyWidget = SNew(SCustomWidget,FText::FromString("Hello"));	  //Transmettre Text via la liste de paramètres de SNew
```

Si on veut que le paramètre ci-dessus puisse lier un délégué, il faut utiliser le mécanisme **d'attribut (Attribute)** de Slate :

``` c++
class SCustomWidget : public SCompoundWidget
{
public:
	SLATE_BEGIN_ARGS(SCustomWidget)							
		: _Text(FText::FromString("Default")) {		
		}				
		SLATE_ATTRIBUTE(FText,Text)							//Utiliser la macro SLATE_ATTRIBUTE pour définir le paramètre
	SLATE_END_ARGS()
public:
	void Construct(const FArguments& InArgs) {		
		Text = InArgs._Text;								//Recevoir le paramètre transmis
		ChildSlot									
			[
				SNew(STextBlock)
				.Text(Text)									//Transmettre l'attribut textuel
			];
	}
private:
	TAttribute<FText> Text;									//Utiliser TAttribute pour envelopper l'attribut
};
```

Puis on peut utiliser ce code :

```C++
auto MyWidget = SNew(SCustomWidget)
		.Text_Lambda([](){
			return FText::FromString("Hello");
		});
```

Si on veut ajouter des rappels de traitement des événements du contrôle, par exemple faire quelque chose lorsque le texte ci-dessus change, on peut utiliser le mécanisme **d'événement (Event)** de Slate :

``` c++
class SCustomWidget : public SCompoundWidget
{
public:
	SLATE_BEGIN_ARGS(SCustomWidget)							
		: _Text(FText::FromString("Default")) {		
		}				
		SLATE_ATTRIBUTE(FText,Text)							
		SLATE_EVENT(FSimpleDelegate, OnTextChanged)	//Utiliser la macro SLATE_EVENT pour déclarer l'événement
	SLATE_END_ARGS()
public:
	void Construct(const FArguments& InArgs) {		
		Text = InArgs._Text;	
		OnTextChanged = InArgs._OnTextChanged;		//Transmettre le délégué de l'événement
		ChildSlot									
		[
			SNew(STextBlock)
			.Text(Text)
		];
	}
	void SetText(FText InText) {
		Text = InText;
		OnTextChanged.ExecuteIfBound();				//Exécuter le délégué
	}
	FText GetText(){
		return Text.Get();
	}
private:
	FSimpleDelegate OnTextChanged;					//Définir le délégué
	TAttribute<FText> Text;
};
```

``` c++
auto MyWidget = SNew(SCustomWidget)
    .Text_Lambda([](){
        return FText::FromString("Hello");
    })
    .OnTextChanged_Lambda([](){						//Afficher un journal lorsque le texte change
        UE_LOG(LogTemp,Warning,TEXT("Oh, Text is changed!"));
    });
```

De plus, il existe d'autres macros utilisables entre `SLATE_BEGIN_ARGS(...)` et `SLATE_END_ARGS()`, mais leur fréquence d'utilisation est faible, donc on ne les développe pas ici. Pour plus de détails, on peut consulter :

-   `Engine\Source\Runtime\SlateCore\Public\Widgets\DeclarativeSyntaxSupport.h`

En résumé, le processus de développement de Slate est基本上 comme ça.

## Personnalisation avancée

Les compétences ci-dessus peuvent répondre à la plupart des besoins de développement UI, mais lorsqu'il faut impliquer des mécanismes d'interaction complexes et de logique de rendu, il faut personnaliser SLeafWidget

Voici un excellent exemple qui implémente un contrôle déplaçable par glisser-déposer :

![13](../../../04-UnrealEngine/Resources/13.gif)

Le code est le suivant :

``` c++
#pragma once
#include "Styling/StyleColors.h"
#include "Brushes/SlateColorBrush.h"

class SCustomSlateWidget :public SLeafWidget {
	SLATE_DECLARE_WIDGET(SCustomSlateWidget, SLeafWidget)	//Utiliser la macro SLATE_DECLARE_WIDGET pour déclarer le contrôle Slate
public:
	SLATE_BEGIN_ARGS(SCustomSlateWidget) {}
	SLATE_END_ARGS()
	void Construct(const SCustomSlateWidget::FArguments InArgs) {
		SetCursor(EMouseCursor::GrabHand);					//Définir le style de la souris lors de l'entrée dans la zone du contrôle
	}
protected:
	FReply OnMouseButtonDown(const FGeometry& MyGeometry, const FPointerEvent& MouseEvent) override {
		if (MouseEvent.IsMouseButtonDown(EKeys::LeftMouseButton)) {
			LastMouseDownPosition = MyGeometry.AbsoluteToLocal(MouseEvent.GetScreenSpacePosition());//Convertir la position de la souris de l'espace écran à l'espace local du contrôle
			return FReply::Handled().CaptureMouse(SharedThis(this));								//Commencer à capturer les mouvements de la souris globalement à haute fréquence
		}
		return FReply::Handled();
	}
	FReply OnMouseMove(const FGeometry& MyGeometry, const FPointerEvent& MouseEvent) override{
		if (MouseEvent.IsMouseButtonDown(EKeys::LeftMouseButton)) {
			auto Window = FSlateApplication::Get().FindWidgetWindow(SharedThis(this));					//Obtenir la fenêtre du contrôle
			auto CurrentMousePosition = MyGeometry.AbsoluteToLocal(MouseEvent.GetScreenSpacePosition());
			auto CurrWindowPosition = Window->GetPositionInScreen();
			auto TargetPosition = CurrentMousePosition + CurrWindowPosition - LastMouseDownPosition;	//Calculer le déplacement de position	
			Window->MoveWindowTo(TargetPosition);
		}
		return FReply::Handled();
	}
	FReply OnMouseButtonUp(const FGeometry& MyGeometry, const FPointerEvent& MouseEvent) override {
		LastMouseDownPosition = FVector2D::ZeroVector;
		return FReply::Handled().ReleaseMouseCapture();											//	Relâcher la capture de la souris
	}
	int32 OnPaint(const FPaintArgs& Args, const FGeometry& AllottedGeometry, const FSlateRect& MyCullingRect, FSlateWindowElementList& OutDrawElements, int32 LayerId, const FWidgetStyle& InWidgetStyle, bool bParentEnabled) const override {
		static FSlateFontInfo FontInfo = FCoreStyle::GetDefaultFontStyle("Bold",30);
		static const FSlateBrush* Bursh = FAppStyle::GetBrush("WhiteBrush");
		FLinearColor BackgroundColor = IsHovered()? FLinearColor(0.6f, 0.5f, 0.9f) : FLinearColor(0.1f, 0.5f, 0.9f);
		FSlateDrawElement::MakeBox(OutDrawElements, LayerId, AllottedGeometry.ToPaintGeometry(), Bursh, ESlateDrawEffect::None, BackgroundColor);		//Dessiner l'arrière-plan
		FSlateDrawElement::MakeText(OutDrawElements, LayerId, AllottedGeometry.ToPaintGeometry(), FText::FromString("Hello Slate"), FontInfo);			//Dessiner le texte
		return LayerId;
	}
	FVector2D ComputeDesiredSize(float LayoutScaleMultiplier) const override {
		return FVector2D::ZeroVector;															// Utiliser un vecteur nul remplira le contenu du contrôle parent
	}
private:
	FVector2D LastMouseDownPosition = FVector2D::ZeroVector;
};

// Le code ci-dessous doit être placé dans le cpp
SLATE_IMPLEMENT_WIDGET(SCustomSlateWidget)							// Utiliser la macro SLATE_IMPLEMENT_WIDGET pour générer l'implémentation du code
void SCustomSlateWidget::PrivateRegisterAttributes(FSlateAttributeInitializer& AttributeInitializer) 	//Cette fonction doit être implémentée
{
}
```

Le processus de travail pour personnaliser **SLeafWidget** est :

-   Utiliser la macro **SLATE_DECLARE_WIDGET(WidgetType, ParentType)** pour déclarer le contrôle
-   Utiliser la macro **SLATE_IMPLEMENT_WIDGET(WidgetType)** dans le cpp pour définir l'implémentation du code, et implémenter la fonction :
    -   `void WidgetType::PrivateRegisterAttributes(FSlateAttributeInitializer& AttributeInitializer)`
-   Surcharger la fonction de calcul des dimensions du contrôle :
    -   `virtual FVector2D SWidget::ComputeDesiredSize(float LayoutScaleMultiplier) const = 0`
-   Surcharger diverses événements d'interaction.
-   Ajuster la machine à états des propriétés du contrôle
-   Selon la machine à états des propriétés, ajouter des éléments de rendu dans la `fonction de rendu (OnPaint)`

### Événements de rendu

La fonction de rendu réel de SWidget est `Paint`, mais由于 le processus de rendu contient certaines étapes fixes, Slate expose l'événement de rendu `OnPaint` pour nous permettre de personnaliser la logique de rendu. Sa définition est la suivante :

``` c++
virtual int32 OnPaint(const FPaintArgs& Args, 
                      const FGeometry& AllottedGeometry,
                      const FSlateRect& MyCullingRect, 
                      FSlateWindowElementList& OutDrawElements, 
                      int32 LayerId,
                      const FWidgetStyle& InWidgetStyle,
                      bool bParentEnabled) const = 0;
```

Description des paramètres :

- `const FPaintArgs&` Args : Paramètres de l'événement de rendu, on peut obtenir l'heure actuelle du rendu, l'intervalle, la fenêtre parent...
- `const FGeometry& ` AllottedGeometry : Taille géométrique allouée au SWidget (par rapport à la fenêtre parent)
- `  const FSlateRect&` MyCullingRect : Rectangle de découpe du SWidget, on peut abandonner les éléments de rendu selon ce rectangle lors du rendu
- `FSlateWindowElementList&` OutDrawElements : Liste des éléments de rendu de la SWindow entière, notre rendu consiste à modifier cet objet.
- `int32` LayerId : ID de la couche de rendu, généralement utilisé pour stratifier l'UI, afin de traiter uniformément les éléments de rendu du même niveau.
- `const FWidgetStyle&` InWidgetStyle : Style transmis par la fenêtre parent
- `bool` bParentEnabled : La fenêtre parent est-elle en état activé.

Dans la fonction `OnPaint`, on crée principalement des éléments de rendu via de nombreuses fonctions statiques de **FSlateDrawElement** dont les noms commencent par `Make`, parmi lesquelles :

### Optimisation des performances

Pour optimiser les performances `Paint` et `Tick` de l'UI, Slate fournit un contrôle **SInvalidationPanel** qui permet de mettre en cache les opérations coûteuses dans les sous-contrôles. Seules les opérations spécifiques qui entraînent une **invalidation du cache (Invalidate)** déclenchent une nouvelle exécution.

Pour plus de détails : [Comprendre l'architecture Slate d'Unreal Engine - Flux de données de polling et délégués | Documentation Unreal Engine 5.2](https://docs.unrealengine.com/5.2/zh-CN/understanding-the-slate-ui-architecture-in-unreal-engine/#轮询数据流和委托)

On peut appeler manuellement la fonction `Invalidate()` du sous-contrôle pour invalider le cache :

``` c++
void SWidget::Invalidate(EInvalidateWidgetReason InvalidateReason);
```

Les valeurs de **EInvalidateWidgetReason** peuvent être :

``` c++
enum class EInvalidateWidgetReason : uint8
{
	None = 0,
	Layout = 1 << 0,		//Si vous avez besoin de changer la taille nécessaire du Widget, invalidez le layout. C'est une opération d'invalidation coûteuse, donc n'utilisez pas cela si vous avez seulement besoin de redessiner un widget
	Paint = 1 << 1,				//Invalider le rendu
	Volatility = 1 << 2,		//Déclenché lorsque Volatility change
	ChildOrder = 1 << 3,		//Déclenché lors de l'ajout ou de la suppression de sous-contrôles, l'invalidation reconstruira l'ordre des Child
	RenderTransform = 1 << 4,	//Déclenché lorsque RenderTransform change
	Visibility = 1 << 5,		//Déclenché lorsque la visibilité change
	AttributeRegistration = 1 << 6,		//Déclenché lors de la liaison des attributs
	Prepass = 1 << 7,					//Invalider le Prepass

	/**
	 * Utilisez l'invalidation Paint si vous changez une propriété normale impliquant le rendu ou le dimensionnement.
	 * De plus, si la propriété modifiée affecte Volatility de quelque manière que ce soit, il est important
	 * de invalider la volatilité afin qu'elle puisse être recalculée et mise en cache.
	 */
```

-   Utiliser **TSlateAttribute** pour envelopper l'attribut (différent de l'utilisation de **TAttribute** ). L'attribut enveloppé par **TSlateAttribute** doit transmettre le paramètre `(*this)` lors de l'initialisation de la construction

## De Slate à UMG

La programmation logique d'UE est basée sur UObject, tandis que Slate n'utilise pas le mécanisme lourd d'UObject pour gérer les objets UI afin de追求极致的性能.

Dans Slate, c'est la **Shared Pointer (pointeur partagé)** qui est utilisée pour gérer le cycle de vie des objets UI.

Pour améliorer l'efficacité des développeurs de jeux dans la création d'UI, UE a enveloppé les contrôles Slate avec UObject, exposé certaines propriétés et fonctions des contrôles Slate via la réflexion, et pris en charge la conception d'UI visuelle. Cette couche d'interface est ce que nous connaissons sous le nom de **UMG**.

Concernant **UMG**, la documentation officielle contient une présentation détaillée :

-   https://docs.unrealengine.com/5.2/zh-CN/umg-ui-designer-for-unreal-engine/

Ce code court illustre bien la relation entre Slate et UMG :

``` c++
#pragma once

#include "UObject/ObjectMacros.h"
#include "Widgets/Text/STextBlock.h"
#include "Components/Widget.h"
#include "CustomUWidget.generated.h"

UCLASS(meta = (DisplayName = "CustomWidget"))					// DisplayName est le nom du contrôle
class UMGEXTENDUTILITIES_API UCustomWidget : public UWidget
{
	GENERATED_BODY()
protected:
	virtual TSharedRef<SWidget> RebuildWidget() override {						// Reconstruire le contrôle et l'assigner à la variable membre
		return SAssignNew(MyTextBlock, STextBlock);
	}
	virtual void SynchronizeProperties() override {								// Synchroniser les propriétés d'UObject avec le contrôle Slate
		MyTextBlock->SetText(Text);
		Super::SynchronizeProperties();
	}
	virtual void ReleaseSlateResources(bool bReleaseChildren) override {		// Libérer les ressources Slate
		MyTextBlock.Reset();
	}

#if WITH_EDITOR
	virtual const FText GetPaletteCategory() override {							// Catégorie du contrôle dans l'éditeur
		return FText::FromString("CustomCategory");
	}
#endif

public:
	UFUNCTION(BlueprintCallable)		// Exposer la fonction au Blueprint
	FText GetText() const {
		return Text;
	}
	UFUNCTION(BlueprintCallable)
	void SetText(FText InText) {
		Text = InText;
		if (MyTextBlock) {				// Définir la propriété : si le contrôle est déjà créé, assigner directement la valeur au contrôle
			MyTextBlock->SetText(Text);
		}
	}
protected:
	UPROPERTY(EditAnywhere, BlueprintGetter = "GetText", BlueprintSetter = "SetText")
	FText Text;							// Exposer la propriété à l'éditeur

	TSharedPtr<STextBlock> MyTextBlock;	// Contrôle Slate réel
};
```

### Gestion du cycle de vie

**UWidget** utilise le **Garbage Collection (GC)** d'UObject. Il détient un Shared Pointer vers le contrôle Slate. Pour garantir que UWidget ne soit pas collecté par le GC tant que le contrôle est affiché (tant que `TSharedPtr<SWidget>` existe), UMG utilise un contrôle **SObjectWidget** héritant de **FGCObject** pour ajouter une référence à UWidget.

![image-20230602103618309](../../../04-UnrealEngine/Resources/image-20230602103618309.png)

Revenant au code exemple ci-dessus, on comprend que le contrôle obtenu via `UWidget::TakeWidget()` n'est pas celui créé dans `UWidget::RebuildWidget()`, mais un contrôle enveloppé par **SObjectWidget**. Leur relation hiérarchique lors de la création est la suivante :

![图片2](../../../04-UnrealEngine/Resources/%E5%9B%BE%E7%89%872.png)

Lors de la destruction, l'ordre de libération est le suivant :

![图片3](../../../04-UnrealEngine/Resources/%E5%9B%BE%E7%89%873.png)

-   **SObjectWidget** hérite de **FGCObject**, il ajoute une référence à UWidget pour garantir que UWidget ne soit pas collecté par le GC tant que SObjectWidget existe.
-   Lorsque le contrôle commence à être détruit, le compteur de références de **SObjectWidget** devient 0 et il est détruit, ce qui délie la référence à **UWidget**.
-   Lorsque le compteur de références de **UWidget** devient 0, il est libéré lors de la prochaine collecte de garbage, et c'est à ce moment que le Shared Pointer vers **SWidget** qu'il détient est libéré.
