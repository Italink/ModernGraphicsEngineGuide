# Traitement géométrique

Récemment, un ami m'a invité à participer à la **5e Compétition nationale d'intelligence artificielle** organisée à Shenzhen, et nous avons obtenu le troisième prix. Pendant cette compétition, j'ai travaillé avec des étudiants spécialisés en recherche académique et appris beaucoup de connaissances et d'expériences que je n'aurais pas接触ées dans mon travail. Le seul regret est que je n'ai pu participer qu'en tant que compétiteur : comme je n'ai pas pu voir les processus et stratégies des autres équipes, il m'a été difficile d'apprendre et d'échanger avec eux. Dommage ! J'avais d'ailleurs l'intention d'approcher les experts pour leur remettre mon CV directement T.T

Pour revenir à nos affaires, la tâche du concours était la suivante :

- Prendre un ensemble d'images, sélectionner des objets spécifiques, puis reconstruire un modèle de haute qualité.

Au début, nous avons testé de nombreuses solutions pour cette tâche. Après avoir finalisé notre stratégie, nous l'avons divisée en deux phases principales :

1. Sélectionner les objets spécifiques dans les images et les convertir en modèles.
2. Optimiser les modèles pour répondre aux exigences de production industrielle.

La première phase était gérée par un autre étudiant, et comme elle concerne son domaine de recherche, je ne peux pas en révéler les détails 0.0.

Quant à la partie d'optimisation géométrique, c'était mon rôle. Au début, mon plan était d'utiliser des SDK de traitement géométrique, comme ceux que j'ai souvent mentionnés :

- [Simplygon - Définir la norme de l'optimisation du contenu 3D pour les jeux](https://link.zhihu.com/?target=https%3A//www.simplygon.com/)
- [InstaLOD - Tout ce dont vous avez besoin pour produire et optimiser automatiquement du contenu 3D](https://link.zhihu.com/?target=https%3A//instalod.com/zh/)

Mais ces SDK sont commerciaux et liés à l'environnement. Comme le programme de compétition devait être soumis dans un environnement virtuel, nous ne pouvions pas les utiliser. Bien qu'il existe des algorithmes et bibliothèques géométriques open source, elles ne sont souvent pas complètes. C'est alors que j'ai eu l'idée d'utiliser Unreal Engine 0.0. Après avoir terminé le projet, je ne peux que dire :

- C'est incroyable !

Si nous voulons effectuer une opération **Remesh** sur un maillage, il suffit d'écrire le code suivant :

```c++
void UMinimalEngineCommandlet::Remesh(UStaticMesh* StaticMesh, int TargetPercentage, float InSmoothingStrength, int MaxRemeshIterations, bool bSplitEdge)
{
    // Créer les outils de mode éditeur
	FCommandletEditorModeTools CommandletTools;   
    
    // Créer le contexte de l'outil interactif
	auto InteractiveToolsContext = NewObject<UEditorInteractiveToolsContext>();                  
	
    // Initialiser le contexte avec le gestionnaire de modes de l'éditeur
    InteractiveToolsContext->InitializeContextWithEditorModeManager(&CommandletTools, nullptr);   
	
    // Enregistrer le contexte de l'outil de transformation
    UE::TransformGizmoUtil::RegisterTransformGizmoContextObject(InteractiveToolsContext);         

    // Créer le constructeur de l'outil Remesh
	auto ToolBuilder = NewObject<URemeshToolBuilder>();											  
	
    // Enregistrer le type d'outil dans le contexte avec le nom "MyTool"
    InteractiveToolsContext->ToolManager->RegisterToolType("MyTool", ToolBuilder);	
    
    // Ajouter la fabrique de cibles de sélection dans le contexte
	InteractiveToolsContext->TargetManager->AddTargetFactory(NewObject<UStaticMeshComponentToolTargetFactory>());  
	
    // Sélectionner l'outil "MyTool" dans le contexte
    InteractiveToolsContext->ToolManager->SelectActiveToolType(EToolSide::Left, "MyTool");

    // Créer un composant StaticMesh temporaire et définir son asset sur le StaticMesh à modifier
	UStaticMeshComponent* StaticMeshComp = NewObject<UStaticMeshComponent>();
	StaticMeshComp->SetStaticMesh(StaticMesh);

    // Sélectionner le composant temporaire dans les outils de l'éditeur
	CommandletTools.SelectComponents({ StaticMeshComp });

    // Activer l'outil de gauche, correspondant à "MyTool"
	InteractiveToolsContext->ToolManager->ActivateTool(EToolSide::Left);
    
    // Récupérer l'outil activé
	if (auto Tool = Cast<URemeshTool>(InteractiveToolsContext->ToolManager->ActiveLeftTool)) {
		
        // Transmettre les paramètres de configuration pour l'exécution de l'outil
        Tool->SetSettings(TargetPercentage, InSmoothingStrength, MaxRemeshIterations, bSplitEdge);
		
        // Simuler une boucle de rendu
        InteractiveToolsContext->ToolManager->Render(nullptr);
        
        // Simuler la boucle d'exécution de la tâche de l'outil
		while (!Tool->CanAccept()) {
			Tool->Tick(0.01f);
		}
        
        // Simuler la demande d'acceptation du résultat de l'outil
		Tool->Shutdown(EToolShutdownType::Accept);
	}
}
```

```c++
#include "CommandletEditorModeTools.h"
#include "Engine/Selection.h"

FCommandletEditorModeTools::FCommandletEditorModeTools()
{
	CommandletWorld = UWorld::CreateWorld(EWorldType::Editor, true);
	CommandletWorld->AddToRoot();

	UTypedElementSelectionSet* ActorAndComponentsSelectionSet = NewObject<UTypedElementSelectionSet>(GetTransientPackage(), NAME_None, RF_Transactional);
	ActorSet = USelection::CreateActorSelection(GetTransientPackage(), NAME_None, RF_Transactional);
	ActorSet->SetElementSelectionSet(ActorAndComponentsSelectionSet);
	ActorSet->AddToRoot();

	ComponentSet = USelection::CreateComponentSelection(GetTransientPackage(), NAME_None, RF_Transactional);
	ComponentSet->SetElementSelectionSet(ActorAndComponentsSelectionSet);
	ComponentSet->AddToRoot();

	ObjectSet = USelection::CreateObjectSelection(GetTransientPackage(), NAME_None, RF_Transactional);
	ObjectSet->SetElementSelectionSet(NewObject<UTypedElementSelectionSet>(ObjectSet, NAME_None, RF_Transactional));
	ObjectSet->AddToRoot();
}

FCommandletEditorModeTools::~FCommandletEditorModeTools()
{
	if (UObjectInitialized()){
		CommandletWorld->RemoveFromRoot();
		ActorSet->RemoveFromRoot();
		ComponentSet->RemoveFromRoot();
		ObjectSet->RemoveFromRoot();
	}
}

	return ActorSet;
}

USelection* FCommandletEditorModeTools::GetSelectedObjects() const

	return ObjectSet;
}

USelection* FCommandletEditorModeTools::GetSelectedComponents() const

void FCommandletEditorModeTools::SelectActors(TArray<AActor*> Actors)
{
	ActorSet->DeselectAll();
	for (auto Actor : Actors) {
		ActorSet->Select(Actor);

	ComponentSet->DeselectAll();
	for (auto Component : Components) {

	}
```

La classe **URemeshToolBuilder** n'est pas fournie par le moteur. Nous l'avons dérivée simplement de **URemeshMeshToolBuilder**, car la plupart des variables et fonctions de **URemeshMeshTool** sont `protected` — la dérivation nous permet de les utiliser :

```c++
UCLASS()
class URemeshToolBuilder : public URemeshMeshToolBuilder
{
	GENERATED_BODY()
public:
	virtual UMultiSelectionMeshEditingTool* CreateNewTool(const FToolBuilderState& SceneState) const override{
    	return NewObject<URemeshTool>(SceneState.ToolManager);
    }
};

UCLASS()
class URemeshTool : public URemeshMeshTool
{
	GENERATED_BODY()
public:
	void SetSettings(int TargetPercentage, float InSmoothingStrength = 0.25f, int MaxRemeshIterations = 20, bool bSplitEdge = true){
        this->BasicProperties->SmoothingStrength = InSmoothingStrength;
        this->BasicProperties->MaxRemeshIterations = MaxRemeshIterations;
        this->BasicProperties->TargetTriangleCount *= TargetPercentage / 100.0f;
        this->BasicProperties->bSplits = bSplitEdge;
        this->Preview->InvalidateResult();          // Invalider le résultat actuel de l'outil, ce qui réactive l'exécution de la tâche de l'outil
    }
};
```

Pour d'autres outils, la méthode d'utilisation est essentiellement la même. Cependant, lors de la simulation de `Tick`, certains détails nécessitent attention. Par exemple, nous avons simulé manuellement une boucle de rendu ci-dessus :

```c++
InteractiveToolsContext->ToolManager->Render(nullptr);
```

Pour certains outils, l'absence de scène de prévisualisation réelle peut causer un crash. Vous pouvez donc le supprimer directement — cela n'affecte généralement pas le résultat. Si cela a un impact, vous devrez compléter l'environnement d'entrée de l'outil. Par exemple, **UHoleFillTool** nécessite de sélectionner les trous à remplir. Vous pouvez appeler manuellement la fonction suivante avant de configurer les paramètres :

```c++
void UHoleFillTool::SelectAll()
```

Pour des tâches complexes impliquant des mises à jour d'état asynchrones, en plus de simuler `Tick` de l'outil, vous devrez peut-être simuler `Tick` du moteur. Dans ce cas, vous pouvez appeler la fonction suivante :

```c++
while (!Tool->CanAccept()) {
    Tool->Tick(0.01f);
    FakeEngineTick(CommandletTools.GetWorld(), 0.01f, 1); 
}
```

```c++
void FakeEngineTick(UWorld* InWorld, float InDelta /*= 0.03f*/, int InCount /*= 1*/)
{
	for (int i = 0; i < InCount; i++) {
		if (IsRunningCommandlet()) {
			GEngine->EmitDynamicResolutionEvent(EDynamicResolutionStateEvent::EndFrame);
			CommandletHelpers::TickEngine(InWorld);
			GEngine->EmitDynamicResolutionEvent(EDynamicResolutionStateEvent::EndFrame);
		}
		else if (FSlateApplication::IsInitialized()) {
			FApp::SetDeltaTime(InDelta);
			bool bIsTicking = FSlateApplication::Get().IsTicking();
			GEngine->EmitDynamicResolutionEvent(EDynamicResolutionStateEvent::EndFrame);
			GEngine->Tick(FApp::GetDeltaTime(), false);
			FSlateApplication::Get().PumpMessages();
			FSlateApplication::Get().Tick();
			GFrameCounter++;

			if (!bIsTicking && GIsRHIInitialized) {
				if (FSceneInterface* Scene = InWorld->Scene) {
					ENQUEUE_RENDER_COMMAND(BeginFrame)([](FRHICommandListImmediate& RHICmdList) {
						GFrameNumberRenderThread++;
						GFrameCounterRenderThread++;
						FCoreDelegates::OnBeginFrameRT.Broadcast();
						});

					ENQUEUE_RENDER_COMMAND(EndFrame)([](FRHICommandListImmediate& RHICmdList) {
						FCoreDelegates::OnEndFrameRT.Broadcast();
						RHICmdList.EndFrame();
						});
					FlushRenderingCommands();
				}
				ENQUEUE_RENDER_COMMAND(VirtualTextureScalability_Release)([](FRHICommandList& RHICmdList) {
					GetRendererModule().ReleaseVirtualTexturePendingResources();
					});
			}

			FTaskGraphInterface::Get().ProcessThreadUntilIdle(ENamedThreads::GameThread);

			FSlateApplication::Get().GetRenderer()->Sync();

			FThreadManager::Get().Tick();

			FTSTicker::GetCoreTicker().Tick(FApp::GetDeltaTime());

			GEngine->TickDeferredCommands();

			GEngine->EmitDynamicResolutionEvent(EDynamicResolutionStateEvent::EndFrame);

			FAssetCompilingManager::Get().FinishAllCompilation();
		}
	}
}
```

Une fois ces points compris, Unreal Engine devient un véritable outil magique !

Nous pouvons ajuster les paramètres dans l'éditeur et visualiser les résultats de chaque étape de manière intuitive, ce qui nous permet de rapidement définir une stratégie optimale. Enfin, nous encapsulons la stratégie ajustée et la packagons en un programme de ligne de commande indépendant, destiné à être appelé par le côté algorithme.

Un petit coup de gueule sur le module éditeur d'Unreal : pour créer un programme de ligne de commande incluant (plugin de modélisation -> cadre d'outils interactifs -> module éditeur), nous avons dû créer une nouvelle boucle de démarrage du moteur et ajuster la configuration de UBT. Cependant, le package par défaut présente de nombreuses dépendances étranges. Même après avoir effectué des réductions, le package final pèse plus de 1 Go+.

En vérifiant attentivement, j'ai découvert que plus de 400 modules étaient déjà chargés lors de l'entrée dans la boucle du moteur. En consultant le code, j'ai été pris de larmes T.T :

Quelques réflexions :

Dans mon expérience professionnelle, j'ai souvent rencontré des problèmes difficiles d'optimisation des performances. Un cas courant est le suivant :

- Les modèles obtenus par reconstruction 3D, voire certains modèles créés manuellement, ne peuvent souvent pas être utilisés directement dans le moteur. Ils doivent satisfaire certaines spécifications, qui évoluent avec le temps et la taille du projet.

À la fois les créateurs et les gestionnaires de modèles sont torturés par ce problème.

Au début, j'ai essayé de mettre en place un pipeline de traitement géométrique pour résoudre ce problème. Bien qu'il s'agisse d'une entrée paramétrée, obtenir de bons résultats nécessite souvent une jugement subjectif humain.

C'est aussi une lacune de notre stratégie de compétition : manque d'innovation. Nous nous sommes essentiellement appuyés sur des algorithmes et outils existants, et la plupart des problèmes étaient liés au code et à l'ingénierie.

En quittant le front de développement opérationnel et en participant à cette compétition, j'ai découvert de nombreuses orientations technologiques de pointe. Par exemple, la technologie de reconstruction 3D est déjà très mature, et elle semble n'être qu'un pont loin du rendu en temps réel. L'IA, quant à elle, excelle dans ce type de problèmes quantifiables.

Mais dommage ! Je ne maîtrise pas ces compétences T.T. Les camarades intéressés peuvent essayer ~
