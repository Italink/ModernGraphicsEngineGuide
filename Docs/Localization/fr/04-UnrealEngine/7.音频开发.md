Mais en réalité, l'audio non seulement peut augmenter l'expérience interactive immersive, mais aussi améliorer davantage l'expressivité de l'image :

## Connaissance de l'audio

### Qu'est-ce que l'audio ?

Comme tout le monde le sait, le son est produit par des vibrations, comme ceci :

![How Does Sound Travel From One Medium To Another?](../../../04-UnrealEngine/Resources/OIP-C.jpeg)

> Image source : [How Does Sound Travel From One Medium To Another? (scienceabc.com)](https://www.scienceabc.com/pure-sciences/movement-of-sound-waves-through-different-media.html)

Voici deux vidéos qui expliquent bien la nature du son :

- [What is Sound-The Dr. Binocs Show](https://www.bilibili.com/video/BV16C4y187Xy)
- [What is Sound-BranchEducation](https://www.bilibili.com/video/BV1pR4y1L7WD)

Nous considérons généralement le son comme une onde continue, comme ceci :

![image-20240204102619133](../../../04-UnrealEngine/Resources/image-20240204102619133.png)

La précision de stockage de l'ordinateur est limitée (il y a une infinité de décimales entre 0 et 1). Si nous voulons stocker les données audio dans l'ordinateur, nous serons confrontés à des problèmes de traitement de précision sur deux dimensions :

- Temps
- Amplitude

Pour cela, nous utilisons la [technique de modulation d'impulsion codée (Pulse Code Modulation, PCM)](https://baike.baidu.com/item/脉冲编码调制/5143788?fromModule=lemma_inlink) pour convertir le **signal continu (Continuous Signal)** du son en **signal discret (Discrete Signal)**.

Tout d'abord, nous traitons la division de précision sur la dimension temporelle par **échantillonnage (Sampling)** :

![image-20240204103616957](../../../04-UnrealEngine/Resources/image-20240204103616957.png)

Le paramètre de précision d'échantillonnage sur la dimension temporelle est le **taux d'échantillonnage (Sample Rate)**, qui représente le nombre d'échantillonnages du signal audio par unité de temps (1s). Les taux d'échantillonnage courants sont `44100 Hz`, `48000 Hz`...

Après avoir obtenu les données échantillonnées, nous traitons la division de précision sur la dimension de l'amplitude par **quantification (Quantize)** :

![image-20240204104205505](../../../04-UnrealEngine/Resources/image-20240204104205505.png)

La précision d'échantillonnage sur la dimension de l'amplitude est la **profondeur de bit (Bits Per Sample)**, qui représente la précision de stockage en bits d'un échantillon audio. Les profondeurs de bit courantes sont `8 bit`, `16 bit`, `24 bit`, `32 bit`. Par exemple, `8 bit` équivaut à `1 octet`, peut représenter `256 (2^8)` nombres, et compte tenu du bit de signe, sa plage de valeurs est `[-128, 127]`, ce qui peut être considéré comme ayant 128 gradients d'amplitude.

Concernant l'échantillonnage et la quantification, voici un excellent article :

- [音视频开发基础入门｜声音的采集与量化、音频数字信号质量、音频码率 - 知乎 (zhihu.com)](https://zhuanlan.zhihu.com/p/577850804)

Les données que nous obtenons finalement sont généralement appelées **tableau d'onde (Wave Table)**. Si nous ne considérons pas la précision de stockage de la profondeur de bit et utilisons des nombres flottants pour représenter l'amplitude, en C++, nous pouvons la représenter comme cette structure de stockage :

``` c++
std::vector<float> WaveTable = {
    sample0,sample1,sample2,sample3,sample4...
}
```

En ouvrant les paramètres de son de l'ordinateur, nous pouvons constater que chaque périphérique audio (entrée ou sortie) a des configurations associées :

![image-20240204105850144](../../../04-UnrealEngine/Resources/image-20240204105850144.png)

Dans le monde réel, la **source sonore (Sound Source)** émet un grand nombre de particules en mouvement dans toutes les directions. Une partie des particules entre directement dans l'oreille humaine, et une autre partie entre dans l'oreille après une ou plusieurs collisions avec des objets environnants. Dans un environnement périphérique complexe comme celui-ci, il se produit généralement que les deux oreilles humaines reçoivent des données audio différentes, ce qui crée également la soi-disant **sensation spatiale** pour l'audio.

Par conséquent, afin de conserver cette sensation spatiale lorsque l'audio est stocké dans l'ordinateur, nous stockons plusieurs copies de données audio. Le nombre de copies est généralement appelé **nombre de canaux (Number Of Channels)**. Un audio avec un seul canal est appelé **mono (Mono)**, et un audio avec `2 canaux` est appelé **stéréo (Stereo)**.

Les échantillons audio de plusieurs canaux sont combinés de manière croisée, et chaque combinaison est appelée **bloc audio (Block)**.

Pour le stéréo, sa structure de stockage est la suivante :

``` c++
std::vector<float> WaveTable = {
    channel0_sample0, channel1_sample0,    	// Block 0
    channel0_sample1, channel1_sample1,		// Block 1
    channel0_sample2, channel1_sample2,		// Block 2
    channel0_sample3, channel1_sample3,		// Block 3
    channel0_sample4, channel1_sample4,		// Block 4
    ...
}
```

Il en va de même pour le 4.1 surround :

``` c++
std::vector<float> WaveTable = {
    channel0_sample0, channel1_sample0, channel2_sample0, channel3_sample0,		// Block 0
    channel0_sample1, channel1_sample1, channel2_sample1, channel3_sample1,		// Block 1
    channel0_sample2, channel1_sample2, channel2_sample2, channel3_sample2,		// Block 2
    channel0_sample3, channel1_sample3, channel2_sample3, channel3_sample3,		// Block 3
    channel0_sample4, channel1_sample4, channel2_sample4, channel3_sample4,		// Block 4
    ...
}
```

En général, le Wave Table ne peut pas être directement lu par un périphérique audio, car ce sont des données d'onde sans informations de format audio, c'est-à-dire le taux d'échantillonnage, la profondeur de bit, le nombre de canaux...

Pour qu'il puisse être lu, nous devons encore l'encoder en fichier audio.

### WAV

`*.WAV` est l'un des formats de fichier audio les plus courants. C'est un format de fichier audio numérique standard développé par Microsoft spécialement pour Windows. Contrairement à des formats audio comme `*.mp3`, `*.flac`, `*.aac`, c'est un audio non compressé qui ne stocke que le format audio avant les données du WaveTable :

![The structure of .wav file format. | Download Scientific Diagram](../../../04-UnrealEngine/Resources/The-structure-of-wav-file-format.png)

Voici un document complet :

- [WAV文件格式解析及处理 - 简书 (jianshu.com)](https://www.jianshu.com/p/63d7aa88582b)

Veuillez lire attentivement l'article ci-dessus pour comprendre la signification de chaque donnée dans le format WAV.

Ensuite, nous pouvons décrire la structure de l'en-tête WAV dans C++ en utilisant l'alignement de mémoire comme ceci :

``` c++
struct WavFmtChunk {
	uint8_t chunkID[4] = { 'f','m','t',' ' };
	int32_t chunkSize;
	int16_t audioFormat;
	int16_t numChannels;
	int32_t sampleRate;
	int32_t byteRate;
	int16_t blockAlign;
	int16_t bitsPerSample;
};

struct WavDataChunkHeader {
	uint8_t chunkID[4] = { 'd','a','t','a' };
	int32_t chunkSize;
};

struct WavRiffChunk {
	uint8_t chunkID[4] = { 'R','I','F','F' };
	int32_t chunkSize;
	uint8_t format[4] = { 'W','A','V','E' };
	WavFmtChunk fmtChunk;
	WavDataChunkHeader dataChunkHeader;
};

typedef WavRiffChunk WavHeader;
```

En C++, pour stocker un segment de données, nous utilisons généralement `std::vector<uint8_t>`. Si nous voulons écrire un segment de données d'onde dans un fichier Wav, nous pouvons utiliser une fonction comme celle-ci :

``` c++
void writeWavFile(std::string filePath, int numChannels, int sampleRate, int bitsPerSample, std::vector<uint8_t> waveTable) {
	WavHeader header;
	header.fmtChunk.audioFormat = 0x0001;			// La valeur correspondant au format PCM est 0x0001
	header.fmtChunk.chunkSize = 16;					// Le format audio PCM occupe 16 octets. Pour d'autres formats, il peut être >16, ce qui entraînera une taille totale de l'en-tête de fichier >44
	header.fmtChunk.numChannels = numChannels;
	header.fmtChunk.bitsPerSample = bitsPerSample;
	header.fmtChunk.sampleRate = sampleRate;
	header.fmtChunk.blockAlign = header.fmtChunk.numChannels * header.fmtChunk.bitsPerSample / 8;
	header.fmtChunk.byteRate = header.fmtChunk.sampleRate * header.fmtChunk.blockAlign;
	header.dataChunkHeader.chunkSize = waveTable.size();
	header.chunkSize = sizeof(header.format) + sizeof(header.fmtChunk) + sizeof(header.dataChunkHeader) + waveTable.size();
	std::ofstream out(filePath, std::ios::out | std::ios::binary);		//Il est impératif d'utiliser std::ios::binary, sinon les données seront déformées
	assert(out.is_open() && "Can`t Write File");
	out.write(reinterpret_cast<char*>(&header), sizeof(WavHeader));
	out.write(reinterpret_cast<char*>(waveTable.data()), waveTable.size());
	out.close();
}

```

Ensuite, nous allons générer un segment d'onde audio. La **onde sinusoïdale (Sine Wave)** est l'une des ondes de base, et sa fonction est la suivante :
$$
y(Time) = Amplitude * sin(2 * PI * Frequency * Time + PhaseOffset) + Bias
$$

Selon la fonction, nous pouvons écrire la fonction suivante :

```C++
const double M_PI = 3.1415926535;
std::vector<uint8_t> generateSineWave(int timeLengthSec,	// Durée de l'onde sinusoïdale en secondes
                                            int frequency, 		// Fréquence de l'onde sinusoïdale
                                            float amplitude,	// Amplitude de l'onde sinusoïdale
                                            int numChannels, 	// Nombre de canaux audio
                                            int sampleRate, 	// Taux d'échantillonnage audio
                                            int bitsPerSample	// Profondeur de bit audio
                                           ) {
	int numBlocks = timeLengthSec * sampleRate;							// Nombre de blocs audio
	amplitude = std::clamp(amplitude, 0.01f, 1.0f);						// Limiter la taille de l'amplitude, std::clamp nécessite C++17
	std::vector<uint8_t> waveTable;								
	waveTable.resize(numBlocks * numChannels * bitsPerSample / 8);		// Calculer la taille de mémoire nécessaire pour les données audio
	int step = bitsPerSample / 8;
	for (int i = 0; i < numBlocks; i++) {
		float time = i / (float)numBlocks * timeLengthSec;		// Point temporel
		float sampleValue = amplitude * std::sin(2 * M_PI * frequency * time);		// Calculer la valeur échantillonnée au point temporel correspondant
        // Nous devons trouver un moyen d'écrire sampleValue dans waveTable
	}
	return waveTable;
}
```

Dans le code ci-dessus, nous sommes confrontés à un problème :

- Par la fonction de l'onde sinusoïdale, nous obtenons une valeur échantillonnée de type `float`, mais la profondeur de bit peut être `8 bit`, `16 bit`, `24 bit`, `32 bit`. Comment convertir le float en données correspondant à la profondeur de bit ?

Une méthode courante est d'utiliser les types de données existants pour affecter les bits correspondants, comme ceci :

``` c++
const int PCMS16MaxAmplitude = 32767;	 // La plage de valeurs de 16 bits est [-32768, 32767]. Ici, nous prenons la valeur absolue minimale (32767) pour éviter le dépassement
void write16BitSampleValue(uint8_t* dataPtr, float sampleValue) {
	(*reinterpret_cast<int16_t*>(dataPtr)) = sampleValue * PCMS16MaxAmplitude;
}
```

Nous pouvons également utiliser des opérations de bits pour le remplissage :

``` c++
const int PCMS24MaxAmplitude = 8388607;
void write24BitSampleValue(uint8_t* dataPtr, float sampleValue) {
    int value = sampleValue * PCMS24MaxAmplitude;
    dataPtr[0] = value & 0xFF;
    dataPtr[1] = (value >> 8) & 0xFF;
    dataPtr[2] = (value >> 16) & 0xFF;
}
```

En résumé, nous pouvons organiser une table de fonctions de conversion comme celle-ci :

``` c++
const int PCMS8MaxAmplitude = 127;
const int PCMS16MaxAmplitude = 32767;
const int PCMS24MaxAmplitude = 8388607;
const int PCMS32MaxAmplitude = 2147483647;

typedef std::function<void(uint8_t*, float)> SampleValueWriteFunction;
static std::map<uint8_t, SampleValueWriteFunction> SampleValueWriteFunctions = {
	{8,[](uint8_t* dataPtr, float sampleValue) {
         // Je ne sais pas pourquoi il faut ajouter un décalage ici pour que l'onde soit correcte =.=
		(*reinterpret_cast<int8_t*>(dataPtr)) = sampleValue * PCMS8MaxAmplitude + PCMS8MaxAmplitude;  
	}},
	{16,[](uint8_t* dataPtr, float sampleValue) {
		(*reinterpret_cast<int16_t*>(dataPtr)) = sampleValue * PCMS16MaxAmplitude;
	}},
	{24,[](uint8_t* dataPtr, float sampleValue) {
		int value = sampleValue * PCMS24MaxAmplitude;
		dataPtr[0] = value & 0xFF;
		dataPtr[1] = (value >> 8) & 0xFF;
		dataPtr[2] = (value >> 16) & 0xFF;
	}},
	{32,[](uint8_t* dataPtr, float sampleValue) {
		(*reinterpret_cast<int32_t*>(dataPtr)) = sampleValue * PCMS32MaxAmplitude;
	}}
};

typedef std::function<float(uint8_t*)> SampleValueReadFunction;
static std::map<uint8_t, SampleValueReadFunction> SampleValueReadFunctions = {
	{8,[](uint8_t* dataPtr) {
		return ((*reinterpret_cast<int8_t*>(dataPtr)) - PCMS8MaxAmplitude) / float(PCMS8MaxAmplitude);
	}},
	{16,[](uint8_t* dataPtr) {
		return (*reinterpret_cast<int16_t*>(dataPtr)) / float(PCMS16MaxAmplitude);
	}},
	{24,[](uint8_t* dataPtr) {
		int value = dataPtr[2];
		value <<= 8;
		value |= dataPtr[1];
		value <<= 8;
		value |= dataPtr[0];
		return value / float(PCMS24MaxAmplitude);
	}},
	{32,[](uint8_t* dataPtr) {
		return (*reinterpret_cast<int32_t*>(dataPtr)) / float(PCMS32MaxAmplitude);
	}}
};
```

``` c++
#include <stdint.h>
#include <assert.h>
#include <map>
#include <vector>
#include <functional>
#include <string>
#include <fstream>
#include <algorithm>
#include <iostream>

	int32_t chunkSize;
	int16_t audioFormat;
	int16_t numChannels;
	int32_t sampleRate;
	int32_t byteRate;
	int16_t blockAlign;
	int16_t bitsPerSample;
};

	uint8_t chunkID[4] = { 'd','a','t','a' };

};

	uint8_t chunkID[4] = { 'R','I','F','F' };

	uint8_t format[4] = { 'W','A','V','E' };

const int PCMS16MaxAmplitude = 32767;
const int PCMS24MaxAmplitude = 8388607;

const double M_PI = 3.1415926535;

std::vector<uint8_t> generateSineWave(int timeLengthSec, int frequency, float amplitude, int numChannels, int sampleRate, int bitsPerSample) {
	int numBlocks = timeLengthSec * sampleRate;							// Nombre de blocs audio
	amplitude = std::clamp(amplitude, 0.01f, 1.0f);						// Limiter la taille de l'amplitude, std::clamp nécessite C++17
	std::vector<uint8_t> waveTable;								
	waveTable.resize(numBlocks * numChannels * bitsPerSample / 8);
	int step = bitsPerSample / 8;										// Calculer l'écart en octets par échantillon
	uint8_t* waveTablePtr = waveTable.data();
	SampleValueWriteFunction writer = SampleValueWriteFunctions.at(bitsPerSample);
	for (int i = 0; i < numBlocks; i++) {
		float time = i / (float)numBlocks * timeLengthSec;				// Temps correspondant au bloc audio actuel
		float sampleValue = amplitude * std::sin(2 * M_PI * frequency * time);		// Valeur sinusoïdale correspondant au temps actuel
		for (int channelIndex = 0; channelIndex < numChannels; channelIndex++) {	// Tous les canaux utilisent la même valeur
			writer(waveTablePtr, sampleValue);
			waveTablePtr += step;
		}
	}
	return waveTable;
}

	header.chunkSize = sizeof(header.format) + sizeof(header.fmtChunk) + sizeof(header.dataChunkHeader) + waveTable.size();
	std::ofstream out(filePath, std::ios::out | std::ios::binary);		//Il est impératif d'utiliser std::ios::binary, sinon les données seront déformées
	assert(out.is_open() && "Can`t Write File");
	out.write(reinterpret_cast<char*>(&header), sizeof(WavHeader));
	out.write(reinterpret_cast<char*>(waveTable.data()), waveTable.size());
	out.close();

int main() {
	assert(sizeof(WavHeader) == 44 && "WAV Header Size Error");

	int numChannels = 2;			// Mono
	int sampleRate = 48000;			// Taux d'échantillonnage de 48000 Hz
	int bitsPerSample = 16;			// Chaque échantillon audio occupe 16 bits, soit 2 octets

std::vector<uint8_t> generateSineSurroundWave(int timeLengthSec, int frequency, float amplitude, int numChannels, int sampleRate, int bitsPerSample) {

	int numBlocks = timeLengthSec * sampleRate;							// Nombre de blocs audio

	uint8_t* waveTablePtr = waveTable.data();
	SampleValueWriteFunction writer = SampleValueWriteFunctions.at(bitsPerSample);

	float leftEarPos[2]	 = { -5,0 };									// Position de l'oreille gauche (X, Y)
	float rightEarPos[2] = {  5,0 };									// Position de l'oreille droite (X, Y)
	float radiusOfSurround = 10;										// Rayon de l'audio surround
	float audioAttenuationFactor = 0.7;									// Facteur d'atténuation du son, par exemple 0.7, ce qui signifie que toutes les unités de longueur, l'audio s'atténuera à 0.7 fois la valeur originale
	float periodSec = 2;												// Temps nécessaire pour une rotation complète, en secondes, 2 signifie une rotation toutes les deux secondes

	for (int i = 0; i < numBlocks; i++) {
		float time = i / (float)numBlocks * timeLengthSec;							// Temps correspondant au bloc audio actuel
		float sampleValue = amplitude * std::sin(2 * M_PI * frequency * time);		// Valeur sinusoïdale correspondant au temps actuel

		float angle = 2 * M_PI * time / periodSec;									// Calculer l'angle de rotation actuel
		float audioSourcePos[2] = {													// Calculer la position actuelle de la source sonore
			radiusOfSurround * std::cos(angle),
			radiusOfSurround * std::sin(angle)
		};

		float leftEarDistance  = sqrt(pow(leftEarPos[0] - audioSourcePos[0], 2) + pow(leftEarPos[1] - audioSourcePos[1], 2));		// Distance entre la source sonore et l'oreille gauche
		float leftSampleValue = sampleValue * pow(audioAttenuationFactor, leftEarDistance);											// Calculer la valeur échantillonnée audio après atténuation selon la distance
		writer(waveTablePtr, leftSampleValue);																						// Écrire dans le canal gauche
		waveTablePtr += step;

		float rightEarDistance = sqrt(pow(rightEarPos[0] - audioSourcePos[0], 2) + pow(rightEarPos[1] - audioSourcePos[1], 2));		// Distance entre la source sonore et l'oreille droite
		float rightSampleValue = sampleValue * pow(audioAttenuationFactor, rightEarDistance);										// Calculer la valeur échantillonnée audio après atténuation selon la distance
		writer(waveTablePtr, rightSampleValue);																						// Écrire dans le canal droit
		waveTablePtr += step;
	}
	return waveTable;
}

int main() {
	assert(sizeof(WavHeader) == 44 && "WAV Header Size Error");
	int numChannels = 2;            // Mono
	int sampleRate = 48000;         // Taux d'échantillonnage de 48000 Hz
	int bitsPerSample = 16;         // Chaque échantillon audio occupe 16 bits, soit 2 octets
	int auidoLengthSec = 2;         // Générer une onde sinusoïdale de 2 secondes
	int sineFrequency = 150;        // Fréquence de l'onde sinusoïdale
	float sineAmplitude = 0.8f;     // Amplitude de l'onde sinusoïdale
	std::vector<uint8_t> waveTable = generateSineSurroundWave(auidoLengthSec, sineFrequency, sineAmplitude, numChannels, sampleRate, bitsPerSample);
	writeWavFile("./sineWave.wav", numChannels, sampleRate, bitsPerSample, waveTable);
	std::vector<uint8_t> readData = readWavFile("./sineWave.wav");
	assert(readData == waveTable && "Audio Data Error");
	return 0;
}

class ISubmixBufferListener
{
public:
	virtual ~ISubmixBufferListener() = default;
	
	/**
	Appelé lorsqu'un nouveau tampon a été rendu pour un sous-mélange donné
	@param OwningSubmix		L'objet sous-mélange qui a rendu un nouveau tampon
	@param AudioData		Ptr au tampon audio
	@param NumSamples		Le nombre d'échantillons audio dans le tampon audio
	@param NumChannels		Le nombre de canaux audio dans le tampon (par exemple, 2 pour stéréo, 6 pour 5.1, etc.)
	@param SampleRate		Le taux d'échantillonnage du tampon audio
	@param AudioClock		Valeur double de l'horloge audio, depuis le début du rendu audio.
	*/
	virtual void OnNewSubmixBuffer(const USoundSubmix* OwningSubmix, float* AudioData, int32 NumSamples, int32 NumChannels, const int32 SampleRate, double AudioClock) = 0;

	/**
	 * Appelé si le sous-mélange évalue la désactivation de lui-même pour le prochain tampon audio dans FMixerSubmix::IsRenderingAudio()
	 * si cela retourne true, FMixerSubmix::IsRenderingAudio() retournera true.
	 * Sinon, le sous-mélange évaluera les sons en cours de lecture, les sous-mélanges enfants, etc. pour voir s'il doit être désactivé automatiquement
	 *
	 * Ceci est appelé à chaque évaluation.
	 * Les ISubmixListeners qui rendent l'audio de manière intermittente ne doivent retourner true que lorsqu'ils ont du travail à faire.

```

Nous n'avons qu'à dériver **ISubmixBufferListener** , surcharger `OnNewSubmixBuffer` pour traiter les données audio, et l'enregistrer dans le **USoundSubmix** dont le **FAudioDevice** doit être capturé. Ce code a beaucoup de dépendances et serait trop désordonné à coller dans l'article. Pour la mise en œuvre spécifique, vous pouvez vous référer à **FNiagaraSubmixListener** .

### DSP 

UE intègre un module DSP très complet : **SignalProcessing**

Vous trouverez presque tout ce que vous voulez dedans :

![image-20240204204639645](../../../04-UnrealEngine/Resources/image-20240204204639645.png)

Voici quelques structures et fonctions couramment utilisées :

- **Audio::TCircularAudioBuffer** : Tampon circulaire, souvent utilisé pour le stockage d'audio en flux continu.
- **Audio::TSampleBuffer** : Permet de convertir les données RawPCM en données échantillonnables correspondant à la profondeur de bit, similaire à la `SampleValueWriteFunction` que nous avons fournie précédemment, mais ne prend en charge que `int16` et `float`.
- **Audio::FResampler** : Rééchantillonneur, utilisé pour modifier le taux d'échantillonnage de l'audio.
- **Audio::FWindow** : Permet de générer des fonctions de fenêtrage, avec support pour `Hamming`, `Hann` et `Blackman`.
- **Audio::TSlidingWindow** : Fenêtre glissante.
- **Audio::IFFTAlgorithm** : Fournit un algorithme FFT de base, créé via `FFFTFactory::NewFFTAlgorithm(...)`.
- **Audio::FBiquadFilter** : Filtre biquadratique.
- **Audio::FSpectrumAnalyzer** : Analyseur de spectre, avec support pour le spectre d'amplitude et le spectre CQT.
- **Audio::FAsyncSpectrumAnalyzer** : Analyseur de spectre exécuté dans un thread asynchrone, avec les mêmes fonctionnalités que ci-dessus.
- `ConstantQ.h` : Fournit une série de structures prenant en charge la transformation Q constante (CQT). Le CQT est souvent utilisé pour la visualisation spectrale de la musique ; il offre une meilleure représentation rythmique que la FFT.

Pour l'analyse spectrale, UE dispose également d'un module `AudioSynesthesia` pour étendre les fonctionnalités associées.

![image-20240205104528872](../../../04-UnrealEngine/Resources/image-20240205104528872.png)

Il prend en charge l'analyse de **CQT** , **Onset (début)** , **Loudness (loudité)** et **Meter** . Malheureusement, la plupart des interfaces sont **NRT (non en temps réel)** , qui exigent que les données audio soient des actifs importés lors de l'édition. Cependant, de nombreuses structures algorithmiques peuvent être référencées.

Le graphique de MetaSound est un graphe de flux de données, exécuté à chaque frame. Chaque nœud est un bloc de fonction, qui reçoit des entrées (Input), combine le contexte actuel d'exécution de MetaSound pour remplir les données de sortie (Output). L'audio généré à chaque frame est stocké dans le AudioBuffer de MetaSoundSource, en attente de lecture par le moteur audio.

> La broche Trigger (déclencheur) peut être simplement considérée comme une variable booléenne. Le nœud de sortie la mettra à true, et le nœud d'entrée lira sa valeur pour déterminer si la logique du nœud doit être exécutée.

            /** Paramètres de l'environnement disponibles. */
            const FMetasoundEnvironment& Environment;
        };
    
        virtual ~IOperator() {}

         *
         * Toutes les références de données d'entrée doivent être liées à InVertexData pour prendre en charge
         * d'autres systèmes MetaSound tels que l'API MetaSound BP, le cache des opérateurs, 
         * et l'audition en direct.

         * purement virtuelle lorsque IOperator::GetInputs() sera supprimé à partir de la version 5.5 ou ultérieure.

         * Note : La liaison d'une référence de données peut mettre à jour l'objet sous-jacent
         * auquel la référence pointe. Tout opérateur qui met en cache des pointeurs ou des valeurs
         * à partir de références de données doit mettre à jour ses pointeurs mis en cache dans l'appel à
         * BindInputs(...). Les opérateurs qui ne mettent pas en cache le pointeur sous-jacent
         * d'une référence de données n'ont pas besoin de mettre à jour quoi que ce soit après BindInputs(...).

         * Exemple :
         * 	FMyOperator::FMyOperator(TDataReadReference<float> InGain, TDataReadReference<FAudioBuffer> InAudioBuffer)
         * 	: Gain(InGain)
         * 	, AudioBuffer(InAudioBuffer)

         * 		MyBufferPtr = AudioBuffer->GetData();		
         * 	}

         * 	void FMyOperator::BindInputs(FInputVertexInterfaceData& InVertexData)
         * 	{
         * 		InVertexData.BindReadVertex("Gain", Gain);
         * 		InVertexData.BindReadVertex("Audio", AudioBuffer);
         *
         * 		// Mettre à jour MyBufferPtr au cas où AudioBuffer référence un nouveau FAudioBuffer.
         * 		MyBufferPtr = AudioBuffer->GetData();

         *
         * Toutes les références de données de sortie doivent être liées à InVertexData pour prendre en charge
         * d'autres systèmes MetaSound tels que l'API MetaSound BP, le cache des opérateurs, 
         * et l'audition en direct. 
         *

         * purement virtuelle lorsque IOperator::GetOutputs() sera supprimé à partir de la version 5.5 ou ultérieure.
         *
         * Note : La liaison d'une référence de données peut mettre à jour l'objet sous-jacent
         * auquel la référence pointe. Tout opérateur qui met en cache des pointeurs ou des valeurs
         * à partir de références de données doit mettre à jour ses pointeurs mis en cache dans l'appel à
         * BindOutputs(...). Les opérateurs qui ne mettent pas en cache le pointeur sous-jacent
         * d'une référence de données n'ont pas besoin de mettre à jour quoi que ce soit après BindOutputs(...).
         *
         * Exemple :
         * 	FMyOperator::FMyOperator(TDataWriteReference<float> InGain, TDataWriteReference<FAudioBuffer> InAudioBuffer)
         * 	: Gain(InGain)
         * 	, AudioBuffer(InAudioBuffer)
         * 	{
         * 		MyBufferPtr = AudioBuffer->GetData();		
         * 	}

         * 		MyBufferPtr = AudioBuffer->GetData();

         *
         * @param IOperator* - L'opérateur associé au pointeur de fonction.
         */

         *
         * L'argument IOperator* de FExecutionFunction sera la même instance IOperator
         * qui a retourné la fonction d'exécution.
         *
         * Les valeurs de retour nullptr sont valides et indiquent un IOperator qui n'a pas besoin d'être
         * réinitialisé.
         */

         */

         * qui a retourné la fonction d'exécution.
         *
         * Les valeurs de retour nullptr sont valides et indiquent un IOperator qui n'a pas besoin d'être
         * exécuté.
         */
        virtual FExecuteFunction GetExecuteFunction() = 0;
    
        /** Pointeur vers la fonction post-exécution d'un opérateur.
         *
         * @param IOperator* - L'opérateur associé au pointeur de fonction.

        virtual FPostExecuteFunction GetPostExecuteFunction() = 0;

#### Interaction avec Blueprint

**MetaSound** n'est pas identique à Blueprint ; les variables qu'il prend en charge sont relativement limitées :

![image-20240205152805417](../../../04-UnrealEngine/Resources/image-20240205152805417.png)

Vous pouvez également étendre ces variables en C++, à condition de trouver des références appropriées.

Ces paramètres ne sont pas directement exposés dans l'éditeur de propriétés, et modifier leurs valeurs est un peu complexe. Nous pouvons utiliser **UAudioComponent** pour simplifier ce processus : il dérive de **IAudioParameterControllerInterface** , qui fournit de nombreuses interfaces pratiques pour configurer les paramètres audio :

![image-20240205154502428](../../../04-UnrealEngine/Resources/image-20240205154502428.png)

Si vous ne voulez pas utiliser **UAudioComponent** , vous pouvez référencer la mise en œuvre spécifique des fonctions associées.

Il faut mentionner spécifiquement `Trigger` dans le système audio UE : il n'est pas identique au `Delegate` couramment utilisé dans le code C++. Nous pouvons simplement le considérer comme une variable booléenne, par exemple avec ce graphique :

![image-20240205155420006](../../../04-UnrealEngine/Resources/image-20240205155420006.png)

On sait que chaque nœud est exécuté selon le tri topologique des relations de dépendance. Lors de l'exécution de l'Input, le délégué de sortie `Lors de la lecture` est mis à true. Lors de l'exécution de `AD Envelope`, le délégué d'entrée `Déclenchement` lié au nœud (c'est-à-dire `Lors de la lecture`) est lu. Si sa valeur est true, le nœud est exécuté. Après l'exécution de `AD Envelope`, le délégué de sortie `Lors de l'achèvement` est mis à `true`. À ce moment, lors de l'exécution du nœud `Output`, si le délégué d'entrée `Lors de l'achèvement` est true, il notifie `MetaSoundSource` de terminer la lecture, c'est-à-dire ici :
