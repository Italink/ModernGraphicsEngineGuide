# Cosmos 開発ログ - 起源

開発者にとって、ユーザーから称賛される製品を作ることは、夢であり使命でもある。

しかし製品の規模には差があり、目標が宏大なビジネス領域や複雑な技術アーキテクチャに触れる場合、個人開発者の薄力だけでは蟻が木を撼くようなものだ。

プロジェクト規模が指数関数的に拡大するにつれ、大量の人材を投入して生産性を向上させざるを得なくなる。そしてこの巨大な工業用生産ラインの中で、各参加者は精密機器上の標準化された部品に異化され、プロセスの歯車のかみ合いの中で創作の自主性を失い、要件の反復とKPI評価に深く巻き込まれ、次第にデジタル洪水の中の冷たい統計単位になっていく。

例えばUP（アップ主）の場合、近年の仕事内容は主にパイプライン（大きな穴を掘る）と最適化（尻拭い）に集中している。これは比較的核心的な職責ではあるが、否応なくUPを製品の内容とユーザー体験を追求する当初の意図から遠ざけ、甚だしきに至っては技術を学び始めた当初の原動力を徐々に失っている。

## 位置づけ

このような背景の下、無数の選択を経て、UPは決心し、現在の人生段階でおそらく最後の長期的な「自由な時間」を確保し、独立した「作品」——**Cosmos**を作ることにした。

- CosmosはUnreal Engine上に構築されたメタバースデモである。

効果面では、UPは可能な限りクールなユーザー体験に向けてイテレーションを重ねる。

技術面では、Cosmosの技術体系は必ず非常にハードコアになる。

それはUPの多くの期待を抱えているが、まずお詫びしたいのは、CosmosがSpecinkerの継続ではないということだ。それを放棄した理由も非常に直感的だ：

- オーディオ可視化は今や新しいものではなくなっている。UPが開発を始めた当初、専門ソフトウェア内のスペクトル可視化を除き、ユーザー層ではRainmeterを使うことが多かったが、それは過度に古く、制限も大きかった。これがUPがSpecinkerの開発を選んだ理由——面白くて挑戦的だったからだ。しかし現在に至っては、オーディオと関連する場所ならどこにでもスペクトルが見られるようになった。例えば一部のプレーヤーには現在スペクトルが搭載され、Steam上にも多くのスペクトルツールが増え、甚だしきに至ってはUPよりも良く、よりクールに作られているものもある。
