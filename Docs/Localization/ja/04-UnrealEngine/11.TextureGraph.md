## 概要

グラフィックス開発者であれば、多くの**グラフィックスレンダリングパイプライン（Graphics Rendering Pipeline）**を使用して、ジオメトリ**（Primitive）**を**レンダーターゲット（Render Target）**（テクスチャや画像と理解できます）に描画することを知っているはずです。このプロセスは一般的に**Base Pass**（または**Mesh Pass**、**Primitives Pass**）と呼ばれます：

![image-20231006120654050](../../../04-UnrealEngine/Resources/image-20231006120654050.png)

最終的に視聴者に提示される画面には、通常、Base Passから出力された画像に基づいて、グローバルイルミネーションやポストプロセッシングなどの追加効果を加えます：

![image-20231006114116772](../../../04-UnrealEngine/Resources/image-20231006114116772.png)

これらの効果は通常、複数のRender Passを使用して生成されます。Render Passは通常いくつかのテクスチャを入力として必要とし、最終的にいくつかのRTを生成します。生成されたRTはさらに別のRender Passのテクスチャ入力として使用でき、これらのRender Passをノードと見なし、その入出力を線で接続すると、最終的にグラフ構造が得られます：

![image-20240921164132083](../../../04-UnrealEngine/Resources/image-20240921164132083.png)

これは通常**Render Graph / Frame Graph**と呼ばれます。

私たちが使用するTexture Graphも同様のフローですが、Render Graphがゲームの1フレームの画面描画を完了するためのものであるのに対し、Texture Graph**通常**は**エディタ段階でテクスチャアセットを生成する**ためのものです。

## 用途

Texture Graphは本質的にプロシージャルテクスチャを作成するものですが、実際の機能セットは成熟したプロシージャルテクスチャツール（例えば [Substance Designer](https://www.adobe.com/hk_en/products/substance3d/apps/designer.html)）には遠く及びません。これは、プロシージャルテクスチャを深く理解しておらず、PSの使い方も熟知していないが、コードの書き方を知っており、一定の画像処理知識を持つ筆者のような人に適しています。

筆者はこれを以下のような用途で使用しています：

1. ノードをドラッグして簡単な画像処理のロジックを迅速に記述する。開発者にとって、入出力が明確な場合、コードを記述する方がエディタを操作するよりも直感的で効率的です。

2. 再利用可能なテクスチャ生成パイプラインを構築する、つまりテンプレート化する。大量のソース（入力）テクスチャが存在する場合、またはソーステクスチャが時間の経過とともに頻繁に更新される場合、非常に有用です。

### 画像処理小ツール

先日『東邪西毒』を見直した際、非常にカッコいいシーンがありました0.0

![微信图片_20240817215316](../../../04-UnrealEngine/Resources/%E5%BE%AE%E4%BF%A1%E5%9B%BE%E7%89%87_20240817215316.png)

これを背景にしようと思い、画風が少し脂っこいので白黒にすると良いかもしれないと考え、グレースケール化を行いました：

![82770255820153](../../../04-UnrealEngine/Resources/82770255820153.png)

結構良い感じですが、鼻の先の光沢が少し変な感じがしたのでPSを開きました：

- 消しゴムペンを試してみるが、ぼやけてしまう。
- ラッソツールで明るい部分を選択し、輝度範囲を調整するが、調整後のエッジが滑らかにならない。

非常に単純なロジックなのに、鼻の先を明るくし過ぎないようにするだけなのに、長時間苦労した後、Qtを開いてレンダリングパイプラインを記述し、数行のコードで解決しました。フラグメントシェーダのコードは以下のようなものです（数値は正確ではありません）：

``` c++
void main(){
    vec4 TextureColor = texture(Texture, UV);
    float Gray = (TextureColor.r + TextureColor.g + TextureColor.b) / 3;		// グレースケール化
    if( UV.x > 0.53 && UV.x < 0.56 && UV.y > 0.45 && UV.y < 0.51)					// 領域を選択
    {
        if(Gray > 0.2)															// グレースケール値が0.2より大きい部分を選択
        {
            Gray = 0.2 + (Gray - 0.2) * 0.1; 									// 0.2を超える部分のグレースケールを元の0.1倍にスケーリング
        }
    }
    OutFragColor = vec4(Gray, Gray, Gray, 1);
}
```

最終的な効果は非常に良かったです：

![26b522e2fa38b897c6e61bb8b4d5042](../../../04-UnrealEngine/Resources/26b522e2fa38b897c6e61bb8b4d5042.jpg)

もちろんPythonやCVでも迅速に実装できますが、多くのUEを使いこなす方はコードを書くことも、複雑なソフトウェアを使用することもできません（UEを理解するだけでも十分難しいです）。しかし彼らは通常マテリアルを作成することができるため、Texture Graphの意義は、UEを使いこなす方が簡単な画像処理を行うために、簡単な需求のためにわざわざソフトウェアを学ぶ必要がなくなることにあります。
