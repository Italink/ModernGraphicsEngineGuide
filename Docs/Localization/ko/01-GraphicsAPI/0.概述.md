# 그래픽 API 개요

학습을 시작하기 전에, C/C++가 **현실 이론**을 **컴퓨터**에서 **실현**하는 **도구**일 뿐이며 이를熟练하게 사용할 수 있어야 한다는 점을 명확히 인지해야 합니다. 그렇지 않다면 기초 지식 체계와良好한 코드 습관을 구축하기 전까지 더 깊이 공부할 능력이나 자격이 없다고 본 저자는 생각합니다.

> 어떻게界定할지 비교적 어려운 일이지만, [스파이더 카드](https://baike.baidu.com/item/%E8%9C%98%E8%9B%9B%E7%BA%B8%E7%89%8C/877244) 게임을 하듯 생각하면 좋습니다. 길이 막힌 것 같을 때만 카드를 요청하는 것이 가장 좋습니다. 왜냐하면 새로운 영역으로 들어가면 일부 진입점을 제공하지만, 더 큰 도전에 직면할 수도 있고 심지어 막다른 골목에 들어갈 수도 있기 때문입니다.

또한, 학습의 필요성도 고려해야 합니다. 만약未来의 목표 직업 방향이 다음과 같다면:

- 게임 엔진, 그래픽
- VR, AR, XR
- 3D 산업 소프트웨어
- 음성 및 영상
- 그래픽 드라이버

하위 레벨 그래픽 API 학습은 필수적인 과정입니다. 하지만 그래픽이呈现하는 예술 효과와 재미에 더 집중한다면, 게임 엔진과 3D 처리 소프트웨어를 직접 다루는 것이 더 좋은 시작점이 될 것입니다.

### 래스터화

그래픽이란 무엇인가?

삼각형, 직사각형, 사각형, 원, 컵 모양... 이렇게 많은 것들을考虑해야 한다면 컴퓨터는 정의해야 할 규칙이 무수히 많을 것입니다. 따라서 간소화가 필요하며, 자연界의 모든 그래픽을 포괄하는最小 기본 단위를 사용해야 합니다. 컴퓨터는 이러한 기본 단위의 렌더링만 처리하면 되며, 이 기본 단위(프리미티브)는 다음과 같습니다:

- 점 (Point)
- 선 (Line)
- 삼각형 면 (Triangle)

이들은 다음과 같은 데이터 구조로描述할 수 있습니다:

``` c++
struct Point {
	int x, y;
};

struct Line {
	std::array<Point, 2> points;
};

struct Triangle {
	std::array<Point, 3> vertices;
};
```

점을 `FrameBuffer`에 그리려면 매우简单합니다:

``` c++
void drawPoint(std::vector<std::vector<char>>& frameBuffer, const Point& point) {
	frameBuffer[point.x][point.y] = '1';
}
```

那么 선을 `FrameBuffer`에 그리려면 어떻게 할까요?

선은 일련의 점으로 구성되지만, 선에는 무수히 많은 점이 있지만 `FrameBuffer`의 점은有限하다는 점에 주의해야 합니다. 따라서 렌더링 시 일부 정밀도가 손실되며, 정밀도에 따라 해당 점의 좌표를 계산하기만 하면 됩니다. 이 과정이 바로 **래스터화** ([Rasterisation](https://en.wikipedia.org/wiki/Rasterisation))입니다.

선은 기울기 방정식으로 표현할 수 있습니다: y = kx+b

두 점의 좌표에 따라 `k`와 `b`의 값을 구할 수 있으며, 정밀도를 1로 설정하면端点之间의 다른 점을 쉽게 계산할 수 있습니다. 하지만 기울기 방정식은 x축에垂直한 직선을表示할 수 없으므로 기울기 계산을 피해야 합니다. 이做法就是: **DDA** ([Digital differential analyzer](https://en.wikipedia.org/wiki/Digital_differential_analyzer_(graphics_algorithm))), 간단한 구현은 다음과 같습니다:

``` c++
void drawLine(std::vector<std::vector<char>>& frameBuffer, Line line) {
	int dx = line.points[1].x - line.points[0].x;
	int dy = line.points[1].y - line.points[0].y;

	if (dx == 0 && dy == 0) {			//端点重叠时直接 점 그리기	
		drawPoint(frameBuffer, line.points[0]);
	}

	int steps = abs(dx) > abs(dy) ? abs(dx) : abs(dy);

	float xInc = dx / (float)steps;		//x 증가량
	float yInc = dy / (float)steps;		//y 증가량

	float x = line.points[0].x;			//x 시작값
	float y = line.points[0].y;			//y 시작값

	for (int i = 0; i <= steps; i++) {	//
		drawPoint(frameBuffer, Point(round(x), round(y)));
		x += xInc;
		y += yInc;
	}
}
```

此外, 다른 선 래스터화 알고리즘도 있지만 여기서는一一介绍하지 않습니다:

- [Bresenham's line algorithm](https://en.wikipedia.org/wiki/Bresenham's_line_algorithm)
- [Xiaolin Wu's line algorithm](https://en.wikipedia.org/wiki/Xiaolin_Wu's_line_algorithm) 

`renderFrame`에서 테스트할 수 있습니다:

``` c++

		{0,0,39,0},
		{0,0,39,19}
	};

		drawLine(frameBuffer, line);
	}

```

삼각형의 래스터화는相对적으로复杂하며, 다음과 같은 알고리즘이 있습니다:

- 분할法
- Bresenham 알고리즘
- Barycentric 알고리즘

其中 분할法가比较常见하며,核心思想는简单합니다. 즉 삼각형을 두 개의底边가 X축과平行한 삼각형으로 나눈 후,纵方向으로逐步 선을 채우는 것입니다:

여기 간단한 구현이 있습니다:

``` c++
void drawTriangle(std::vector<std::vector<char>>& frameBuffer, Triangle triangle) {
	std::sort(triangle.vertices.begin(), triangle.vertices.end(), [](const Point& a, const Point& b) {
		return a.y < b.y;
	});
	if (triangle.vertices[0] == triangle.vertices[1]	//重복顶点出现时绘制하지 않음
		|| triangle.vertices[1] == triangle.vertices[2]
		|| triangle.vertices[0] == triangle.vertices[2]
		)
		return;

	auto fillBottomFlatTriangle = [&](const Point& v1, const Point& v2, const Point& v3) {
		float invslope1 = (v2.x - v1.x) / (v2.y - v1.y);
		float invslope2 = (v3.x - v1.x) / (v3.y - v1.y);

		float curx1 = v1.x;
		float curx2 = v1.x;

		for (int scanlineY = v1.y; scanlineY <= v2.y; scanlineY++) {
			Line scanLine = {
			 (int)curx1, scanlineY ,
			 (int)curx2, scanlineY 
			};
			drawLine(frameBuffer, scanLine);
			curx1 += invslope1;
			curx2 += invslope2;
		}
	};

	auto fillTopFlatTriangle = [&](const Point& v1, const Point& v2, const Point& v3) {
		float invslope1 = (v3.x - v1.x) / (float)(v3.y - v1.y);
		float invslope2 = (v3.x - v2.x) / (float)(v3.y - v2.y);

		float curx1 = v3.x;
		float curx2 = v3.x;

		for (int scanlineY = v3.y; scanlineY > v1.y; scanlineY--) {
			Line scanLine = {
			 (int)curx1, scanlineY ,
			 (int)curx2, scanlineY
			};
			drawLine(frameBuffer, scanLine);
			curx1 -= invslope1;
			curx2 -= invslope2;
		}
	};
	if (triangle.vertices[1].y == triangle.vertices[2].y) {
		fillBottomFlatTriangle(triangle.vertices[0], triangle.vertices[1], triangle.vertices[2]);
	}
	else if (triangle.vertices[0].y == triangle.vertices[1].y) {
		fillTopFlatTriangle(triangle.vertices[0], triangle.vertices[1], triangle.vertices[2]);
	}
	else {
		Point mid = Point({
			(int)(triangle.vertices[0].x + ((float)(triangle.vertices[1].y - triangle.vertices[0].y) / (float)(triangle.vertices[2].y - triangle.vertices[0].y)) * (triangle.vertices[2].x - triangle.vertices[0].x))
			, triangle.vertices[1].y
		});
		fillBottomFlatTriangle(triangle.vertices[0], triangle.vertices[1], mid);
		fillTopFlatTriangle(triangle.vertices[1], mid, triangle.vertices[2]);
	}
}
```

### 처리 파이프라인

컴퓨터에서는朴素하고静态的几何图形을表示하는 것 외에도,动态적이고 처리된 그래픽 효과를绘制해야 하는 경우가 있습니다. 이를 위해 다음이 필요합니다:

- 각顶点에 대해 이동, 좌표 원점에 대한旋转,缩放等处理를 할 수 있어야 함
- FrameBuffer의 픽셀에 대해上色,各种 필터 추가等额外 가공을 할 수 있어야 함

이전 섹션의 `SwapChain`을结合하면 다음과 같은小程序을实现할 수 있습니다:

![18](../../../01-GraphicsAPI/Resources/18.gif)

위 그림에서는 삼각형의 크기를动态적으로缩放하고 *边框를 추가했습니다.完整代码는 다음과 같습니다:

``` c++
#include <iostream>
#include <vector>
#include <algorithm>
#include <functional>
#include <array>
#include <Windows.h>

double GTime = 0;

struct Point {
	int x, y;
	bool operator == (const Point& other) { return x == other.x && y == other.y; }
};

struct Line {
	std::array<Point, 2> points;
};

struct Triangle {
	std::array<Point, 3> vertices;
};

void drawPoint(std::vector<std::vector<char>>& frameBuffer, const Point& point) {
	frameBuffer[point.x][point.y] = '1';
}

void drawLine(std::vector<std::vector<char>>& frameBuffer, Line line) {
	int dx = line.points[1].x - line.points[0].x;
	int dy = line.points[1].y - line.points[0].y;

	if (dx == 0 && dy == 0) {			//端点重叠时直接 점 그리기	
		drawPoint(frameBuffer, line.points[0]);
	}

	float steps = abs(dx) > abs(dy) ? abs(dx) : abs(dy);

	float xInc = dx / (float)steps;		//x 증가량
	float yInc = dy / (float)steps;		//y 증가량

	float x = line.points[0].x;			//x 시작값
	float y = line.points[0].y;			//y 시작값

	for (int i = 0; i <= steps; i++) {
		drawPoint(frameBuffer, Point(round(x), round(y)));
		x += xInc;
		y += yInc;
	}
}

void drawTriangle(std::vector<std::vector<char>>& frameBuffer, Triangle triangle) {
	std::sort(triangle.vertices.begin(), triangle.vertices.end(), [](const Point& a, const Point& b) {
		return a.y < b.y;
	});
	if (triangle.vertices[0] == triangle.vertices[1]	//重복顶点出现时绘制하지 않음,暂时共线情况忽略
		|| triangle.vertices[1] == triangle.vertices[2]
		|| triangle.vertices[0] == triangle.vertices[2]
		)
		return;

	auto fillBottomFlatTriangle = [&](const Point& v1, const Point& v2, const Point& v3) {
		float invslope1 = (v2.x - v1.x) / (v2.y - v1.y);
		float invslope2 = (v3.x - v1.x) / (v3.y - v1.y);

		float curx1 = v1.x;
		float curx2 = v1.x;

		for (int scanlineY = v1.y; scanlineY <= v2.y; scanlineY++) {
			Line scanLine = {
			 (int)curx1, scanlineY ,
			 (int)curx2, scanlineY 
			};
			drawLine(frameBuffer, scanLine);
			curx1 += invslope1;
			curx2 += invslope2;
		}
	};

	auto fillTopFlatTriangle = [&](const Point& v1, const Point& v2, const Point& v3) {
		float invslope1 = (v3.x - v1.x) / (float)(v3.y - v1.y);
		float invslope2 = (v3.x - v2.x) / (float)(v3.y - v2.y);

		float curx1 = v3.x;
		float curx2 = v3.x;

		for (int scanlineY = v3.y; scanlineY > v1.y; scanlineY--) {
			Line scanLine = {
			 (int)curx1, scanlineY ,
			 (int)curx2, scanlineY
			};
			drawLine(frameBuffer, scanLine);
			curx1 -= invslope1;
			curx2 -= invslope2;
		}
	};
	if (triangle.vertices[1].y == triangle.vertices[2].y) {
		fillBottomFlatTriangle(triangle.vertices[0], triangle.vertices[1], triangle.vertices[2]);
	}
	else if (triangle.vertices[0].y == triangle.vertices[1].y) {
		fillTopFlatTriangle(triangle.vertices[0], triangle.vertices[1], triangle.vertices[2]);
	}
	else {
		Point mid = Point({
			(int)(triangle.vertices[0].x + ((float)(triangle.vertices[1].y - triangle.vertices[0].y) / (float)(triangle.vertices[2].y - triangle.vertices[0].y)) * (triangle.vertices[2].x - triangle.vertices[0].x))
			, triangle.vertices[1].y
		});
		fillBottomFlatTriangle(triangle.vertices[0], triangle.vertices[1], mid);
		fillTopFlatTriangle(triangle.vertices[1], mid, triangle.vertices[2]);
	}
}

/*逐顶点处理
* 시간에 따라顶点位置动态缩放
*/
Point processVertex(const Point& point) {
	Point newPoint = point;
	double scaleFactor = 0.5 + 0.4 * std::sin(GTime);		//缩放因子가 [0.1,0.9] 범위内에 있도록保证
	newPoint.x *= scaleFactor;
	newPoint.y *= scaleFactor;
	return newPoint;
}

/*逐像素处理
* 简单描边
*/
char processPixel(const std::vector<std::vector<char>>& frameBuffer, int x,int y) {
	static int direction[4][2] = { {0,1},{0,-1},{1,0},{-1,0} };	//四方向
	for (int i = 0; i < 4; i++) {
		int xOff = x + direction[i][0];
		int yOff = y + direction[i][1];
		if (xOff >= 0											//frame边界内에 있는지判断,当前像素가 0이고周边像素에 1이 있는 경우
			&& xOff < frameBuffer.size()
			&& yOff >= 0 
			&& yOff < frameBuffer[0].size()
			&& frameBuffer[x][y]=='0'
			&& frameBuffer[xOff][yOff] == '1') {
			return '*';
		}
	}
	return frameBuffer[x][y];
}

void renderFrame(std::vector<std::vector<char>>& frameBuffer) {
	std::vector<Triangle> triangles = { 
		{0,0,40,0,20,19},
	};

    /*顶点处理*/
	for (auto& triangle : triangles) {
		for (auto& vertex : triangle.vertices) {
			vertex = processVertex(vertex);
		}
	}

	for (const auto& triangle : triangles) {
		drawTriangle(frameBuffer,triangle);
	}

    /*像素处理*/
	std::vector<std::vector<char>> newFrameBuffer(frameBuffer);
	for (int x = 0; x < frameBuffer.size(); x++) {
		for (int y = 0; y < frameBuffer[x].size(); y++) {
			newFrameBuffer[x][y] = processPixel(frameBuffer, x, y);
		}
	}
	frameBuffer = newFrameBuffer;
}

int main() {
	HANDLE frontendBuffer = GetStdHandle(STD_OUTPUT_HANDLE);        //默认缓冲区获取
	HANDLE backendBuffer = CreateConsoleScreenBuffer(               //新缓冲区를后台缓冲区로创建
		GENERIC_READ | GENERIC_WRITE,
		FILE_SHARE_READ | FILE_SHARE_WRITE,
		NULL,
		CONSOLE_TEXTMODE_BUFFER,
		NULL
	);
	//两个缓冲区的光标隐藏
	CONSOLE_CURSOR_INFO cci;
	cci.bVisible = 0;
	cci.dwSize = 1;
	SetConsoleCursorInfo(frontendBuffer, &cci);
	SetConsoleCursorInfo(backendBuffer, &cci);

	const int width = 40;
	const int height = 20;
    const char clearCh = '0';
	const int MaxBufferSize = width * height * 10;

	char bufferData[MaxBufferSize];     //缓存数据暂存区
	DWORD bufferLength = 0;
	COORD zeroCoord = { 0,0 };
	while (true) {
		GTime += 0.01;
		bufferLength = 0;
		CONSOLE_SCREEN_BUFFER_INFO backendBufferInfo;      
		GetConsoleScreenBufferInfo(backendBuffer, &backendBufferInfo);
		int lineWidth = backendBufferInfo.srWindow.Right - backendBufferInfo.srWindow.Left + 1;

		std::vector<std::vector<char>> frameBuffer(width, std::vector<char>(height, clearCh));
		renderFrame(frameBuffer);

		for (int y = 0; y < height; y++) {
			for (int x = 0; x < width; x++) {
				bufferData[bufferLength++] = frameBuffer[x][y];
			}
			while (bufferLength % lineWidth != 0) {             //换行效果를达到하기 위해字符填充
				bufferData[bufferLength++] = ' ';
			}
		}

		WriteConsoleOutputCharacterA(backendBuffer, bufferData, bufferLength, zeroCoord, &bufferLength);
		SetConsoleActiveScreenBuffer(backendBuffer);           
		std::swap(backendBuffer, frontendBuffer);              
	}
	return 0;
}
```

现代 그래픽 렌더링 파이프라인은 위의逐顶点处理 및逐像素处理 외에도其他可编程阶段를支持하며, 이는后面的章节에서深入说明할 것입니다.

3D 그래픽 렌더링은 3D顶点를一些数值计算을 통해 2D屏幕坐标에投影한 후绘制하는 것에 불과합니다. 여기서는 다음을完整히 공부하는 것을推荐합니다:

- [《3D数学基础 - 图形与游戏开发（第2版）》](https://baike.baidu.com/item/3D%E6%95%B0%E5%AD%A6%E5%9F%BA%E7%A1%80%EF%BC%9A%E5%9B%BE%E5%BD%A2%E5%92%8C%E6%B8%B8%E6%88%8F%E5%BC%80%E5%8F%91%EF%BC%88%E7%AC%AC2%E7%89%88%EF%BC%89)

现在绘制的理论은 있지만, 컴퓨터에서는性能을考虑해야 합니다.因为这决定了一定时间范围内绘制할 수 있는 삼각형数量的上限입니다.

上面的代码를总结하면 다음을发现할 수 있습니다:

- 코드에许多数值计算이 있음
- 顶点之间的处理,像素之间的处理,图元之间的绘制는相互影响가 없으므로这些操作은 모두并行할 수 있음

이 과정을加速하기 위해现代 컴퓨터体系结构에서는 그래픽绘制专门용 프로세서인 GPU(G[raphics Processing Unit, 그래픽 처리 유닛](https://en.wikipedia.org/wiki/Graphics_processing_unit))을 추가했습니다.

### GPU

现代 GPU는 [컴퓨터 그래픽](https://en.wikipedia.org/wiki/Computer_graphics)과 [이미지 처리](https://en.wikipedia.org/wiki/Image_processing)를操纵하는 데非常高效합니다.大块数据를并行处理하는 알고리즘의 경우,它们的[并行结构](https://en.wikipedia.org/wiki/Parallel_computing)使得通用[中央处理器](https://en.wikipedia.org/wiki/Central_processing_unit)(CPU)보다更高效합니다.

## 그래픽 API

> [ **그래픽 API** ](https://en.wikipedia.org/wiki/List_of_3D_graphics_libraries)는 GPU 하드웨어에 대한抽象访问方式를提供하며, 컴퓨터 그래픽生成的各个阶段를简化하여 개발자가 하드웨어细节를深入了解하지 않고 그래픽构建에专注할 수 있도록 합니다.
>
> [임베디드 시스템](https://en.wikipedia.org/wiki/Embedded_system)에서常见的 [소프트웨어](https://en.wikipedia.org/wiki/Computer_software)에서纯粹히完成하고 [CPU](https://en.wikipedia.org/wiki/Central_processing_unit)에서运行할 수도 있으며, [PC](https://en.wikipedia.org/wiki/Personal_computer)에서更常见的 [GPU](https://en.wikipedia.org/wiki/Graphics_processing_unit)에 의해 [하드웨어加速](https://en.wikipedia.org/wiki/Hardware_acceleration)될 수도 있습니다. 주로 [비디오 게임](https://en.wikipedia.org/wiki/Video_game)과 [시뮬레이션](https://en.wikipedia.org/wiki/Simulation_video_game)에 사용됩니다.
>

当下主流的 3D 그래픽 API는 다음과 같습니다:

- DX11、[DX12](https://www.nvidia.com/en-sg/geforce/technologies/dx12/)：[마이크로소프트](https://zh.wikipedia.org/wiki/微軟)公司가 [Windows](https://zh.wikipedia.org/wiki/Microsoft_Windows)系统에서开发한 3D 그래픽 프로그래밍 인터페이스
- [OpenGL](https://www.opengl.org/)：OpenGL은跨语言、跨平台 API로, Windows、部分 UNIX 및 Mac OS에实现이存在하며,这些实现은一般적으로 그래픽 카드厂商가提供하며 해당厂商의 하드웨어에非常依赖합니다.
- [Vulkan](https://www.vulkan.org/)：下一代 OpenGL로,相比之下 Vulkan은更底层에接近하며 CPU 코어를并行任务执行에很好地分配할 수 있습니다.
- [Metal](https://developer.apple.com/metal/)：Metal API는 애플公司가提供하며, [iOS](https://en.wikipedia.org/wiki/IOS)、[iPadOS](https://en.wikipedia.org/wiki/IPadOS)、[macOS](https://en.wikipedia.org/wiki/MacOS) 및 [tvOS](https://en.wikipedia.org/wiki/TvOS)上的应用程序이 GPU 하드웨어에低级访问를 통해性能을提高하도록 목표로 합니다. Vulkan、DX12와 함께低级 API에属于합니다.

很多小伙伴들이这些 API를看到면 첫反应는 다음과 같을 것입니다:

- 这些 API中谁가最强일까?哪一个을学해야 할까?

이问题에 대해每个人都自己的见解가 있습니다.例如:

- [知乎：Vulkan相比于OpenGL、DX12、Metal和Mantle有什么优势、劣势？](https://www.zhihu.com/question/46536915)

过来人的 저자의看法은 다음과 같습니다:

- 其中任何一个 API를学了也高枕无忧할 수 없으며,实际工作开发中至少上述 API中的两个及以上에接触하게 될 것이며,更大的可能性는这些 API的上层接口上开发하는 것입니다.

大多数游戏引擎은这些 그래픽 API를统一的接口로封装하여不同平台上切换하여更好的 그래픽性能을追求할 수 있으며,我们一般称这套接口为 **RHI** (Rendering Hardware Interface) 

> OpenGL、Vulkan은 **绝大多数** 平台를支持하지만完美하지 않으며,此外 애플은它的操作系统上 Metal 사용을要求합니다.

相关行业에서持续发展하여底层에深入하면 DX12、Vulkan、Metal의各种疑难杂症에接触하게 될 것이지만,好在这类 API的基础结构는相差不多하여一个을会면其他는很容易触类旁通합니다.它们的细致研究는 다음을参阅하세요:

初学者而言, DX12、Vulkan、Metal은几乎令人望而生畏的天堑입니다.

### QRhi

Qt6的主要目标之一는 Qt가直接 OpenGL을使用하는 것을摆脱하고适当的抽象을 통해更广泛的 그래픽 API(例如 [Vulkan](https://www.khronos.org/vulkan/)、[Metal](https://developer.apple.com/metal/) 및 [Direct3D](https://docs.microsoft.com/en-us/windows/win32/direct3d))上에서操作할 수 있도록 허용하는 것입니다. [OpenGL](https://www.khronos.org/opengl/) (및 [OpenGL ES](https://www.khronos.org/opengles/))背後的主要动机는性能获得가 아닌 OpenGL이不可用或不再需要的平台和设备上에서도 **Qt无处不在** 를确保하고将来也如此하도록 하는 것입니다.同时,现代的、较低级别的、显式 API上에서构建할 수 있으면性能提高(例如 API 오버헤드减少로 인한 CPU使用率降低)도 가능하며,它는 [Qt Quick](https://doc.qt.io/qt-5/qtquick-index.html#)和其他模块背後的 렌더링 엔진입니다.它的架构는 다음과 같습니다:

![rhiarch-3](../../../01-GraphicsAPI/Resources/68747470733a2f2f7777772e71742e696f2f68732d66732f68756266732f726869617263682d332e706e673f77696474683d383030266e616d653d726869617263682d332e706e67.png)

>官方目前的开发者分支上에서 QRhi는 DX12를支持하며,预计 Qt6.6에서上线될 것입니다.

Qt6中에서는 OpenGL兼容 GLSL 셰이더 코드를不再使用하고 Vulkan风格的 GLSL로编写한 후反射하여其他 셰이더 언어(HLSL, MSL)로翻译한 다음序列化 가능한 QShader对象로打包하여 QRhi가使用하도록 합니다.它的工作流程는 다음과 같습니다:

![着色器调节](../../../01-GraphicsAPI/Resources/shaderconditioning.pngwidth=1280&name=shaderconditioning.png)

다음位置에서它的源码를找到할 수 있습니다:
