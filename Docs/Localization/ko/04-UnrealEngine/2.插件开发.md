플러그인은 엔진과 프로젝트 코드 외부에 존재하며, UE에서 프로그램 기능을 확장하는 주요 방식입니다.

플러그인은 본질적으로 모듈화된 코드 설계로, 이 설계를 따르면 코드 간 의존성을 줄이고 후속 반복 및 유지 관리가 더 쉬워집니다.

UE에서 플러그인의 표준 파일 구조는 다음과 같습니다:

![image-20230525143413268](../../../04-UnrealEngine/Resources/image-20230525143413268.png)

-   `Binaries`：컴파일된 생성 파일 저장
-   `Content`：플러그인의 에셋 내용 저장
-   `Intermediate`：컴파일 과정에서 생성된 중간 파일 저장
-   `Resources`：플러그인의 리소스 파일(예: 아이콘, 비UE 에셋) 저장
-   `Source`：코드 소스 파일 저장，여러 Module 포함 가능

-   `*.uplugin`：플러그인의 구조 조직 파일

其中 `*.uplugin` 的 기본 내용如下：

``` c++
{
	"FileVersion": 3,				//파일 버전
	"Version": 1,					//버전 번호

	"FriendlyName": "CustomPlugin",	//별칭
	"Description": "",				//설명
	"Category": "Other",			//분류
    "CreatedBy": "",				//작성자
	"CreatedByURL": "",				//작성자 링크
	"DocsURL": "",					//문서 링크
	"MarketplaceURL": "",			//마켓플레이스 링크
	"SupportURL": "",				//서비스 지원 링크
	"CanContainContent": false,		//콘텐츠 디렉토리 포함 여부
	"IsBetaVersion": false,			//베타 버전 여부
	"IsExperimentalVersion": false,	//실험적 버전 여부
```

>   빈 플러그인은 좋은 시작점입니다. 다른 플러그인은 일부 부가적인 코드 템플릿을 추가한 것일 뿐，만약 이에 익숙하지 않다면 추가해보고里面의 코드가具体적으로哪些内容을增加했는지了解해보세요. 그作用을掌握하면 빈 플러그인에 추가하기만 하면 됩니다.

이것은 C++ 플러그인에 필수적으로存在하는 파일입니다:

``` c++
// MyPlugin.h

#pragma once

#include "CoreMinimal.h"
#include "Modules/ModuleManager.h"

class FMyPluginModule : public IModuleInterface
{
public:

	/** IModuleInterface 구현 */
	virtual void StartupModule() override;
	virtual void ShutdownModule() override;
};
```

``` c++
// MyPlugin.cpp

#include "MyPlugin.h"

#define LOCTEXT_NAMESPACE "FMyPluginModule"

void FMyPluginModule::StartupModule()
{
	// 이 코드는 모듈이 메모리에 로드된 후 실행됩니다. 정확한 타이밍은 모듈별 .uplugin 파일에 지정됩니다.
}

void FMyPluginModule::ShutdownModule()
{
	// 이 함수는 종료 시 모듈을 정리하기 위해 호출될 수 있습니다. 동적 재로딩을 지원하는 모듈의 경우，모듈을 언로드하기 전에 이 함수를 호출합니다.
}

#undef LOCTEXT_NAMESPACE
	
IMPLEMENT_MODULE(FMyPluginModule, MyPlugin)		//플러그인 진입점 정의
```

UE는 플러그인을 로드할 때 `StartupModule()`을 호출하고，플러그인을 언로드할 때 `ShutdownModule()`을 호출합니다.

플러그인 개발의 코드 흐름은 주로 다음과 같습니다:

-   `StartupModule()`에서 **핵심 모듈의 함수 인터페이스**를 호출하거나 **핵심 모듈의 전역 싱글톤**을 사용하여 일부 작업을 수행하거나，일부 로직을 **핵심 모듈의 진입점**에 연결하여 확장 작업을 수행합니다.
-   `ShutdownModule()`에서 `StartupModule()`에서 수행한 작업을 정리합니다.

其中常見的一些 함수 모듈如下：

-   **FFileHelper** ：파일 작업

-   **FBlueprintEditorUtils** ：블루프린트 작업
-   **FKismetEditorUtilities** ：에디터 작업
-   **FEdGraphUtilities** ：그래프 작업
-   **FComponentEditorUtils** ：컴포넌트 에디터 작업
-   **FEnumEditorUtils** ：열거형 작업
-   **FStructureEditorUtils** ：구조체 작업
-   **FEditorFolderUtils** ：에디터 폴더 작업
-   **FMaterialEditorUtilities** ：머티리얼 작업
-   **FPluginUtils** ：플러그인 작업
-   **UGameplayStatics** ：Gameplay 관련 작업
-   ...

전역 싱글톤如下：

-   `GEngine`，`GEditor`，`GWorld`：엔진에서 자주 사용되는 전역 싱글톤
-   `FModuleManager::LoadModuleChecked<FAssetToolsModule>("AssetTools").Get()`：에셋의 생성，삭제，이름 변경，가져오기/내보내기...

-   ...

## 메뉴바 툴바 확장

엔진 개발过程中，经常会有一些需求，엔진 에디터의 메뉴바，툴바를 확장하여 버튼을增加하고便捷한 작업을执行하려는 경우가 있습니다.就像这样：

![image-20220526100322912](../../../04-UnrealEngine/Resources/image-20220526100322912.png)

![image-20220526115630692](../../../04-UnrealEngine/Resources/image-20220526115630692.png)

UE4에서 메뉴를 확장하는主要方式는 **FExtender**를 통해였지만，UE5에서는 더易于使用的新方式 — **UToolMenus**가 있습니다.

**UToolMenus ** 是一个 싱글톤 클래스，以下 코드를 통해 싱글톤 인스턴스를获取할 수 있습니다：

``` c++
UToolMenus* ToolMenus = UToolMenus::Get();
```

UE5에서所有可扩展的 메뉴바 툴바는 `초기화 시` 함수 `UToolMenus::RegisterMenu`를调用하여注册됩니다：

```c++
UToolMenu* UToolMenus::RegisterMenu(const FName InName,
                                    const FName InParent = NAME_None,
                                    EMultiBoxType InType = EMultiBoxType::Menu,
                                    bool bWarnIfAlreadyRegistered = true)
```

![image-20230524155859423](../../../04-UnrealEngine/Resources/image-20230524155859423.png)

该 함수는扩展 가능한`ToolMenu`를注册하는 데 사용됩니다. 함수의各个 매개변수 의미如下：

-   `InName`：注册에 사용되는链式字段，`LevelEditor.LevelEditorToolBar.User`와 같은 형식입니다.之后该字段를 Key로 사용하여`UToolMenu`를得到할 수 있습니다.
-   `InParent`：툴 메뉴의 Parent를指定합니다.
-   `InType`：该ToolMenu的 타입을指定합니다.这个 타입은该Menu를怎样扩展할 수 있는지决定합니다.以下 값을 가질 수 있습니다：
    -   `MenuBar`：메뉴바，메뉴 확장을 지원합니다.
    -   `ToolBar`：툴바，툴 버튼을添加할 수 있습니다.
    -   `VerticalToolBar`：수직 툴바
    -   `SlimHorizontalToolBar`：수평 툴바，툴바의 간소화 버전으로，아이콘과 텍스트 요소를 수평으로 정렬할 수 있습니다.
    -   `UniformToolBar`：
    -   `Menu`：메뉴，메뉴 항목을添加할 수 있습니다.
    -   `ButtonRow`：按行排列的 버튼，每行有最大数量的 버튼，툴바와类似하지만多行으로 구성할 수 있습니다.
-   `bWarnIfAlreadyRegistered`：Bool 값，该字段已注册된 경우警告을发出합니다.

当需要 `메뉴를预览하는时刻` ，则函数`UToolMenus::GenerateWidget`를调用하여`ToolMenu`的控件을生成합니다：

```c++
TSharedRef<SWidget> UToolMenus::GenerateWidget(const FName Name, const FToolMenuContext& InMenuContext)
```

![image-20230524154628869](../../../04-UnrealEngine/Resources/image-20230524154628869.png)

`ToolMenu`가 Register된之后，预览之前的任一时机，我们都可以通过函数`UToolMenus::ExtendMenu`来扩展 메뉴바的内容입니다.

``` c++
UToolMenu* UToolMenus::ExtendMenu(const FName InName)
```

![image-20230524160554125](../../../04-UnrealEngine/Resources/image-20230524160554125.png)

上方 코드中有大量的扩展参考，而这里也有一个简单的 플러그인扩展实例：

``` c++
#pragma once

#include "Modules/ModuleManager.h"

class FCustomPluginModule : public IModuleInterface
{
public:
	virtual void StartupModule() override {
		//플러그인启动时 UToolMenus的启动에回调을增加합니다.
		UToolMenus::RegisterStartupCallback(FSimpleMulticastDelegate::FDelegate::CreateRaw(this, &FCustomPluginModule::RegisterMenus));
	}

	virtual void ShutdownModule() override {
		//UToolMenus的启动回调을去除하고一些状态를重置합니다.
		UToolMenus::UnRegisterStartupCallback(this);
		UToolMenus::UnregisterOwner(this);
	}
private:
	void RegisterMenus() {
		FToolMenuOwnerScoped OwnerScoped(this);
		UToolMenu* Menu = UToolMenus::Get()->ExtendMenu("LevelEditor.LevelEditorToolBar.PlayToolBar");
		FToolMenuSection& Section = Menu->FindOrAddSection("PluginTools");
		FToolMenuEntry& MenuEntry = Section.AddEntry(
			FToolMenuEntry::InitToolBarButton(			//툴바 버튼添加
				"CustomToolbarButton",
				FUIAction
				(
					FExecuteAction::CreateLambda([]() {
						FMessageDialog::Open(EAppMsgType::Ok, NSLOCTEXT("CustomNs", "HelloWorld", "Hello World!"));
					})
				)
			)
		);
		MenuEntry.InsertPosition = FToolMenuInsert(NAME_None, EToolMenuInsertType::First);
	}
};
```

该 코드는 레벨 에디터主面板的 툴바에 버튼을添加하고，点击时`Hello World`对话框을弹出합니다：

###撤销重做

UObject는一套事务机制을拥有합니다.如果UObject가标志`RF_Transactional`을拥有하면，以下 코드를使用할 수 있습니다：

```C++
GEditor->BeginTransaction(NSLOCTEXT("NS", "Transaction", "Transaction"));       //트랜잭션开始
Object->Modify();               //此操作将Object的当前状态를事务中存储합니다.

SomeChange(Object);             //Object的一些属性를修改합니다.

GEditor->EndTransaction();      //트랜잭션结束，Object的新状态를提交합니다.
```

上述操作会使得SomeChanged能够被撤销重做합니다.

>   详细请参阅：https://blog.csdn.net/qq_29523119/article/details/96778797

에디터开发中，经常会需要某个对象或窗口在撤销重做时，变更에响应해야 하는 경우(比如说一些重建을进行)，UE는撤销重做事件监听을 위한接口 **FEditorUndoClient**를提供합니다.一个简单的 코드示例如下：

```C++
class FUndoRedoListener: public FEditorUndoClient{
public:
    FUndoRedoListener(){
        if (GEditor)
            GEditor->RegisterForUndo(this);     //合适的时机에该监听器를注册합니다.构造函数中不一定是必须입니다.
    }
    ~FUndoRedoListener(){
        if (GEditor)
            GEditor->UnregisterForUndo(this);   //注册取消
    }
protected:
    virtual void PostUndo(bool bSuccess) override{      //에디터가撤销을执行한 후该函数를调用합니다.
        RebuildSomething();
    }
    virtual void PostRedo(bool bSuccess) override{      //에디터가重做을执行한 후该函数를调用합니다.
        RebuildSomething();
    }
};
```

> 通常情况下，코드中的 문자열은 **ANSI**를 사용하여编码되지만，**ANSI**가支持하는 문자数量가很少기 때문에，문자열 변수 리터럴을设置할 때 **TEXT()** 매크로를使用하여 **ANSI** 리터럴을 **TCHAR**（본기 Unicode编码）로转换해야 합니다.

``` c++
TCHAR* ThisIsTChars = TEXT("This is Raw String");
```

TCHAR와原生 문자열编码格式을转换하려면以下 매크로를使用할 수 있습니다：

- **TCHAR_TO_ANSI** (str) 

- **TCHAR_TO_UTF8** (str) 
- **TCHAR_TO_UTF16** (str) 
- **TCHAR_TO_UTF32** (str) 
- **TCHAR_TO_WCHAR** (str) 
- **ANSI_TO_TCHAR** (str) 

- **UTF8_TO_TCHAR** (str) 
- ...

#### [FName](https://docs.unrealengine.com/4.27/en-US/ProgrammingAndScripting/ProgrammingWithCPP/UnrealArchitecture/StringHandling/FName/)

> 命名에用于됩니다.它는大小写을区分하지 않으며，某个资源를快速定位하기 위해创建时 문자열内容에 따라 Hash值를计算합니다.这样比较逻辑을实现할 때 문자열内容을比较하지 않고直接 hash值是否相等을比较할 수 있습니다.

> ### 相互转换
>
> ```c++
> TestString = TestName.ToString();
> TestString = TestText.ToString();
> 
> TestName = FName(*TestString);
> TestName = TestText	 // FText에서 FName으로转换은不存在하지만，先 FString으로转换한 후 FName으로转换할 수 있습니다.但是 FName은大小写을区分하지 않기 때문에不可靠합니다.
> 
> TestText = FText::FromName(TestName)
> TestText = FText::FromString(TestString)
> ```

``` c++
void UBPLibrary::SetStaticMeshPivot(UStaticMesh* InStaticMesh, EStaticMeshPivotType PivotType)
{
	if(InStaticMesh == nullptr)
		return;
	auto InteractiveToolsContext = NewObject<UEditorInteractiveToolsContext>();
	InteractiveToolsContext->InitializeContextWithEditorModeManager(&GLevelEditorModeTools(), nullptr);
	UE::TransformGizmoUtil::RegisterTransformGizmoContextObject(InteractiveToolsContext);

	InteractiveToolsContext->ToolManager->RegisterToolType("EditPivotTool", NewObject<UEditPivotToolBuilder>());
	UStaticMeshComponent* StaticMeshComp = NewObject<UStaticMeshComponent>();
	StaticMeshComp->SetStaticMesh(InStaticMesh);

	InteractiveToolsContext->TargetManager->AddTargetFactory(NewObject<UStaticMeshComponentToolTargetFactory>());
	UToolTarget* Target = InteractiveToolsContext->TargetManager->BuildTarget(StaticMeshComp, FToolTargetTypeRequirements());

	InteractiveToolsContext->ToolManager->SelectActiveToolType(EToolSide::Left, "EditPivotTool");
	GLevelEditorModeTools().SelectNone();
	GLevelEditorModeTools().GetSelectedComponents()->Select(StaticMeshComp);

	InteractiveToolsContext->ToolManager->ActivateTool(EToolSide::Left);
	if (auto EditTool = Cast<UEditPivotTool>(InteractiveToolsContext->ToolManager->ActiveLeftTool))
	{
		EditTool->SetTargets({ Target });
		EditTool->RequestAction((EEditPivotToolActions)PivotType);
		EditTool->Tick(0.1);
		EditTool->Shutdown(EToolShutdownType::Accept);
	}
}
```
