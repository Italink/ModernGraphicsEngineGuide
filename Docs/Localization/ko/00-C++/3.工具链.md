## IDE

**IDE（Integrated Development Environment 통합 개발 환경）** 은 현대 프로그래머가 가장 자주 접하는 도구로, 컴파일 도구를 제공할 뿐만 아니라 다음을 포함한다:

- 텍스트 편집기: 문법 강조를 통해 코드를 작성하고 읽기 쉽게 만든다.
- 지능형 제안: 코드의 일부를 입력하면 전체 코드를 제안하여 개발자의 코드 작성 속도를 향상시킨다.
- 디버거: 프로그램의 실행 단계를 지정하여 프로그램의 오류 로직을 빠르게 찾는 데 도움이 된다.
-美观한 인터페이스: 다양한 버튼, 패널, 메뉴, 창 등의 컨트롤이整齐하게 배치되어操作이 더方便하다.
- 성능 분석: CPU 사용량, 메모리 소비 등 프로그램의 각종 성능을 분석하는 도구를 제공한다.
- 프로젝트 관리 도구: 소스 파일, 이미지, 비디오, 타사 라이브러리 등 프로그램과 관련된 모든 리소스를 관리한다.
- ...

## 빌드 도구

이전 섹션에서 Visual Studio의 CL 컴파일러로 C++의 컴파일流程를简单히 살펴보았다. 실제工程开发中,一个工程은绝대多数情况下 하나의 소스 파일만 가지지 않는다.这意味着我们要写一大堆编译指令,不过好在我们可以把指令写在 **makefile** 文件里, **make** 工具을 통해构建할 수 있다.但这还有一个非常严重的问题:

> Windows下的指令를 Linux下面에放으면 인식하지 않는다.

是的, makefile은直接操作系统的指令를调用하지만各个系统之间的指令却存在差异。这也涌现出了大量的 크로스 플랫폼工程构建工具,比如:

- [cmake](https://link.zhihu.com/?target=https%3A//cmake.org/):当下主流的 크로스 플랫폼构建工具
- [qmake](https://link.zhihu.com/?target=https%3A//doc.qt.io/qt-6/qmake-manual.html): Qt提供的一个构建工具,目前Qt已全面转向Cmake, qmake已不再维护。
- [nmake](https://link.zhihu.com/?target=https%3A//docs.microsoft.com/en-us/cpp/build/reference/nmake-reference): Visual Studio的内置工具,负责执行Makefile中描述的编译链接步骤
- [xmake](https://link.zhihu.com/?target=https%3A//xmake.io/):国人编写的 Lua 기반의轻量级 크로스 플랫폼构建工具。
- UBT: Unreal Engine 中 C# 기반的构建工具

大部分C++初学者来说,项目的构建可能大多时候都是直接使用IDE的图形化界面,点击操作按钮来添加源文件,比如Visual Studio:

![image-20230113082804541](../../../00-C++/Resources/image-20230113082804541.png)

图形界面在使用起来确实方便,但也存在一些不足:

- IDE가 크로스 플랫폼을支持하지 않는다면,它的工程文件肯定也无法 크로스 플랫폼。这样的话其他平台就编译不了。
- 不同的系统上,会有不同的构建配置。图形界面를 통해只能进行静态的配置,而不能实现自动化的构建逻辑。
- 图形界面配置的工程文件,当文件路径或者系统发生变动,可能导致原先的链接丢失。
- 库的管理容易混乱,且过于繁琐...

> 话虽如此,笔者在早期没有使用构建,纯图形界面写工程也照样没什么问题（菜是原罪）
>
> 图形界面使用을放弃하게 한主要原因有:
>
> - 程序编译之前,工程中一些文件做"预处理"再交由C++ 컴파일러进行编译해야 한다（Qt的Moc抄袭: [XObject](https://github.com/Italink/XObject)）
> - 程序编译之前,一些脚本或指令를执行해야 한다.比如提前将着色器代码编译为二进制文件

那上面 **那么多构建工具该选什么呢?**

### CMake

为什么是CMake呢,它很强大吗?不,这不是主要原因。最根本的原因是: **大部分开源群体都使用CMake作为构建工具** 。它를使用하면其他三方库를很方便的引入할 수 있다.

很多小伙伴可能会吐槽Cmake难,它的语法像Shit一样。其实难的并不是Cmake,工程的体量上去之后,它的构建逻辑肯定会变复杂。任何构建工具它的主体逻辑都差不多,核心的构建语句就那么几条,多的不过是一些构建选项啊, 크로스 플랫폼配置啊,自动化脚本之类的。搞会一个构建工具,其他简单过一下就懂了。

CMake를 사용하여工程을管理하면主要会带来以下几个好处:

- CMake는各个平台IDE的工程文件를生成할 수 있다.
- CMake를使用하면逻辑代码를编写하여自动化构建를完成하고各个平台的构建细节에适配할 수 있다.
- 子工程（库）管理이方便하다.
- 工程文件具有依赖分析,编译速度极快。

初学者而言,一般只需要 CMakeGUI的使用和CmakeLists基本语法를熟悉하면 된다.

#### CMake GUI

CMake GUI는 **亲切的** 图形化界面로命令行操作를代替할 수 있다.

大家安装完Cmake 之后,注意 CMake GUI的桌面快捷方式를创建하십시오.

![image-20230108215228112](../../../00-C++/Resources/image-20230108215228112.png)

CMake项目를构建하려면直接 CMake GUI를打开하십시오:

- CMakeLists.txt를窗口里에拖入하고 `Where to build the Binaries`를设置한다.构建目录는笔者一般会在源目录后面追加`/build`한다.

- `Configure`를点击하면一个弹窗이出现한다.生成하려는 IDE工程文件와一些命令行参数를选择한다.

  ![image-20230108220004147](../../../00-C++/Resources/image-20230108220004147.png)

- `Finish`之后,这个会出现一些可供调整的配置选项。描述에 따라调整할 수 있다.

- 再点击`Generate`하면对应IDE的工程文件가生成된다.

- 最后点击`Open Project`하면直接对应IDE로工程을打开한다.

后续代码文件结构发生变动하면 Cmake GUI 中 `Generate` 一下를重新해야 한다.不过一般IDE는 **CMakeLists内容有变动** 을检测到면自动으로 `Generate`를触发한다.

>一些IDE는直接 CMakeList.txt를打开할 수 있다.比如Qt Creator和Visual Studio.对于Visual Studio,笔者更建议 CMake GUI 的方式를使用하여 VS 的工程文件（`*.sln`）를生成한다.



#### CMakeList基本语法

CMake는难하지 않다.不过是工程信息를设置하면 된다:

``` cmake
project(${ProjectName} VERSION 0.1 LANGUAGES CXX)
```

Cmake的最小版本을限制한다.

``` cmake
cmake_minimum_required(VERSION 3.5)
```

原来 【手动添加点击按钮一个源文件的操作 】换成了:

``` cmake
add_executable(${TargetName} *.h *.cpp ...)				//可执行文件创建
// add_library(${TargetName} STATIC *.h *.cpp ...)		//静态库创建
// add_library(${TargetName} SHARED *.h *.cpp ...)		//动态库创建
```

其他库를引入하려면:

``` cmake
target_link_libraries(${TargetName} PRIVATE ${LibraryName})  
//PRIVATE는 ${TargetName}만 ${LibraryName}中的代码를访问할 수 있다는 의미
//PUBLIC는 ${TargetName}을引入하는其他库也 ${LibraryName}中的代码를访问할 수 있다는 의미
```

Include路径를增加하려면:

``` cmake
target_include_directories(QEngineEditor PRIVATE ${IncludeDir}) 
```

局部变量를操作하려면直接:

```cmake
set(VarName "This is String")
messgae(Warning ${VarName})  // ${}를包裹하여变量를读取한다.这里的操作是 VarName的值를打印한다.
```

子目录를添加하려면（子目录는 CMakeLists.txt 拥有하는路径를指한다）:

``` cmake
add_subdirectory(${Subdir})
```

基础操作은无非就这么一些.只要你觉得某个配置或者功能是合理的,那么它大概率就存在한다.网上一搜,官网一查,就出来了.构建文件的改动并不频繁,只需要主体逻辑를知道하면 된다.

构建工具其实都大差不大,用啥都无所谓.它们的使用都不难,关键难的是各种平台和框架的细节配置.这个无可避免.

CMake的使用에 대해网上有很多优质的教程,不过笔者更推荐它的官方文档를阅读한다: https://cmake.org/cmake/help/latest/guide/tutorial/index.html

## 패키지 관리

python을 사용한 적이 있는小伙伴可能都 패키지 관리工具——`pip`를 사용한 적이 있다.

`pip install ...`를使用하여 python에第三方库를快速安装할 수 있다.

C++的 패키지 관리一直都比较混乱하다.如果你想给自己的工程에一个三方库（例如 OpenCV, ffmpeg...）를装载하려면官方网站上去下载해야 한다.如果是CMake构建的源码还好,如果是库文件,就需要编译类型是Debug还是Release、动态库还是静态库、MD还是MT、32位还是64位...에注意해야 한다.

很多小伙伴应该都库安装时各种配置에折磨받은 적이 있다.现在,终于大家를拯救하는工具啦 —— [Vcpkg](https://github.com/microsoft/vcpkg)

> Vcpkg은 Windows、 Linux 和 MacOS 上에서 C 和 C++ 库를管理하는 것을帮助한다.

它的使用에 대해大家可以参阅:

- https://github.com/microsoft/vcpkg/blob/master/README_zh_CN.md

## 버전 관리

那一天,笔者는 버전 관리가 없는 때의恐惧을回忆起了.

笔者早期学习时 버전 관리工具이 무엇인지了解하지 않았다.因为平时就是 문제 풀이를 하고代码量撑死也就一两百行,小工程을写也不过千行이다.直到后面工程的体量上去之后,每次 Feature의代码变动都比较大.所以动工之前,笔者는源代码를复制一份留做备份한다.以免新增的代码에一些 "莫名其妙" 、无法修复的错误가加入되기 때문이다.

早期这种做法也大问题를遇到하지 않았다.直到笔者가某一次代码를写上头了,提前备份하지 않았다.大概一个星期的代码变动,非常多.查了一天原因을找到하지 못하고头都要炸了.后面没办法,只能之前的备份을 사용하여重新写,一点一点的加,一点一点的测试.大概三天的时间을花了才问题를修复하고进度를恢复했다.

那三天的时间里,笔者는度日如年했다.一行行熟悉的代码를看着小心翼翼的再来一遍,一度放弃하려고 했지만又不断自己를 설득하여耐着性子坚持下去했다.

可即便如此,笔者也还是新东西를了解하는 시간을浪费하기不愿意하고那些时间을 **堆** 代码上에花였다.

直到后来,笔者는一位老大哥를遇到했다.耐着性子的笔者의工程中的瑕疵를点出하고流程中的不规范를指出하며苦口婆心的 Git을介绍했다.笔者也终于是 被 他 打动 了 ，决定去用下.这一用就现在까지用到了.如果现在的笔者가原来的自己를评价한다면那只有两个字 — 傻X

## 문서 노트

俗话说好记性不如烂笔头.人的大脑就像电脑的CPU,内存的速度很快,但容量有限하다.聪明的人懂得大量内容를 **"磁盘”（노트）** 上에存储하고内容的索引를大脑的 **“高速缓存”** 中에存放到懂得한다. 노트를记主要能带来几个好处:

- 记的时候印象를加深한다.
- 回顾的时候细节를快速联想한다.

那怎么 노트를记呢?

笔者目前见到过的 노트를记的方式主要有:

- 办公软件: Word、Excel
- 博客网站:知乎、博客园、CSDN、掘金、简书、哔哩哔哩、自己搭建的博客网站...
- 笔记类软件:如印象笔记

笔者早期 CSDN上解题思路的博客를记录했다.如果那个好大哥苦心孤诣地 Github、Markdown、CMake를介绍하지 않았다면可能现在依旧自己的世界中沉溺在继续自己와斗智斗勇할 것이다.

### Markdown

> Markdown 是一种[轻量级标记语言](https://baike.baidu.com/item/轻量级标记语言/52671915?fromModule=lemma_inlink)，创始人为约翰·格鲁伯（John Gruber）。 它允许人们使用易读易写的[纯文本格式](https://baike.baidu.com/item/纯文本格式/9862288?fromModule=lemma_inlink)编写文档，然后转换成有效的 [XHTML](https://baike.baidu.com/item/XHTML/316621?fromModule=lemma_inlink)（或者HTML）文档。这种语言吸收了很多在电子邮件中已有的纯文本标记的特性。
>
> ——《百度百科》：https://baike.baidu.com/item/markdown/3245829

为什么 Markdown을要用呢?

笔者的博客都是 Markdown을使用하여编写했다.一直使用下来的感受是:

- **编写速度快** : Markdown语法를熟悉之后,文档的编写速度很快다.
- **操作简单,认知负担小** :一些"不合理"的功能을限制하여文档的逻辑가线性的임을保证한다.它로文档를写感觉就是一种享受이다.
- **通用** :很多网站都 Markdown的支持를提供한다.因为它本质上只是纯文本이기 때문에其他网站可以它的语法를解析하여预览를进行한다.还文本的缘故이기 때문에文档的 버전 관리也很方便하다.
- **美观** : markdown은只文档的结构를记录한다.很多漂亮的第三方皮肤主题가 있다.

那什么로 Markdown을写呢?

Markdown编辑器很多다.一些博客网站就直接支持한다.对于本地,笔者见过较多的是 VS Code를使用하는 것,还有就是狂拽酷炫,天下无敌,宇宙第一的Markdown神器:
