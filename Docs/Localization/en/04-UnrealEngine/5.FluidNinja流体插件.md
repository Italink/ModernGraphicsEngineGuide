## Key Blueprints

### NinjaLiveComponent

NinjaLiveComponent is the core of Fluid Ninja. To use it, you must attach a static mesh (usually a plane, called the **Trace Mesh**). The final result of the fluid simulation will be output as the material of the trace mesh:

![image-20231114162146791](../../../04-UnrealEngine/Resources/image-20231114162146791.png)

> The red plane in the image above is the trace mesh

### NinjaLive

NinjaLive is a default Actor provided by Fluid Ninja. It wraps the parameters of NinjaLiveComponent, includes a trace plane that meets most usage requirements, simplifies the setup of NinjaLiveComponent, and adds some additional features, such as:

- Culling and休眠 of NinjaFluid through ActivationVolume; NinjaLiveComponent will only activate when entering the ActivationVolume

## Simulation Process

In the asset directory of FluidNinja, there is a blueprint named `Help`:

![image-20231114160604396](../../../04-UnrealEngine/Resources/image-20231114160604396.png)

It contains a detailed flowchart describing the Fluid Ninja simulation:

![image-20231114161417804](../../../04-UnrealEngine/Resources/image-20231114161417804.png)

The core of NinjaFluid lies in:

- Constructing **Density** maps and **Velocity** maps
- Overlaying **Noise** to increase the randomness of the fluid
- Adjusting **Brushes** to control the shape of the fluid
- Combining with **Output Materials**
- Outputting the final result to the material surface of the **Trace Mesh**
- Obtaining the desired result:

![12332312](../../../04-UnrealEngine/Resources/12332312.gif)

- Density is a single-channel texture with a value range of [0,1], used to represent the density of the fluid at the current position.
- Velocity is a two-channel texture with a value range of [0,1], used to represent the vector velocity of the fluid at the current position. Since it is normalized to [0,1], a velocity of 0 actually corresponds to an RG value of (0.5, 0.5). In the image above:
  - The R channel of the Velocity texture corresponds to horizontal velocity; when the value is `<0.5`, the fluid moves to the left; when it is `>0.5`, the fluid moves to the right
  - The G channel of the Velocity texture corresponds to vertical velocity; when the value is `<0.5`, the fluid moves upward; when it is `>0.5`, the fluid moves downward
- FluidNinja allows input of three-channel materials, where the RG channels represent Velocity and the B channel represents Density

## Usage Workflow

During production, we essentially operate on the **NinjaLiveComponent**, whose **Configuration Categories** include:

![image-20231114195314683](../../../04-UnrealEngine/Resources/image-20231114195314683.png)

- `Live Activation`: Only has a Disable Component option, which can be dynamically set via blueprints for culling.
- `Live Interaction`: All interaction-related configurations, such as filtering interaction targets, orientation and locking of the trace mesh, world coordinate offset, etc.
- `Live Brush Setting`: Parameter configuration of the brush.
- `Live Generic`: General configuration, mainly adjusting effect presets, inputs, and outputs.
- `Live Performance`: Performance configuration, which can configure the number of effect iterations, FPS range limits, LOD, etc.
- `Live Compatibility`: Compatibility configuration, which can configure collision channels, override inputs, etc.
- `Live Debug`: Debug configuration, providing some checkboxes for printing prompt information.
- `Live Raymarching`: Configure Raymarching.
- `Live Memory Management`: Configure memory management.

### Building Inputs

The inputs here mainly refer to **Density** and **Velocity**. The relevant input configuration parameters are mainly located under the `Live Generic` category of the **NiagaraComponent**. The input sources of Fluid Ninja can be the following:

- Static textures
- Dynamic materials
- Scene camera capture
- Render Targets
- Streaming videos
- Mouse input
- Scene interactions: static meshes, dynamic meshes, skeletal meshes, destructibles...

> The above inputs are not independent; they can coexist. FluidNinja will mix multiple inputs together. For details, see the flowchart in `Help.uasset`.

In the map `Content/FluidNinjaLive/Tutorial/Levels/NinjaLive_Level03_SimulationInputs_LIVE17.umap`, there are complete NinjaFluid input examples. The key steps for these inputs are recorded below:

The input configuration for materials is located under the `Live Generic` category of the **NinjaComponent**:

![image-20231114202905246](../../../04-UnrealEngine/Resources/image-20231114202905246.png)

- You can add available input materials in the **Input Materials** parameter. You can add multiple materials so that you can switch and preview them in **NinjaLive_PresetManager**.
- Adjust the **Input Material Selected** index to choose the currently used input material.
- Checking **RGB-Input Material** will make the RG channels of the material serve as the Velocity texture and the B channel as the Density texture; otherwise, **by default, only the R channel of the material will be used as the Density texture**
- Checking **Input Material Clamp** will crop the image where UV coordinates are outside [0,1].

#### Collision Interaction

Fluid Ninja can use physical collisions as input to achieve some interactive fluid effects. A simple example is as follows:

- Add a NinjaLiveActor

  - Set `Trace Mesh Size` and `Interaction Volume Size` to `(5,5,1)`
  - Set NinjaLiveComponent\Live Bursh Settings; otherwise, the result may not be visible due to the collision brush being too small
    - Check `Brush Scaled By Interacting Obj Size`
    - Set `Primitive Obj Brush Scale` to 20

- Add a Mannequin, and you can see the following effect:

  ![image-20231117163147270](../../../04-UnrealEngine/Resources/image-20231117163147270.png)

This effect is achieved through UE's physical collision mechanism, and its complete parameters are all located in `NinjaLiveComponent\Live Interaction`:

![image-20231117162047588](../../../04-UnrealEngine/Resources/image-20231117162047588.png)

- **Continuous Interaction with Owner Actor**: Continuously interact with the Actor holding this component
- **Continuous Interaction incluisve Obj Type**: Filter the collision object types for interaction
- **Continuous Interaction Component Name**: Filter the component names for interaction
- **Continuous Interaction Bone Names Exact**: Filter the bone names for interaction
- **Single Target Mode**: Single target mode; when enabled, FluidNinja considers that the images generated by collisions are all produced by one target, which can make the collision path smooth without断层 (interpolation)
- **Single Target Type**
- **Single Target Mode Skeletal Mesh Index**
- **Single Target Move Set Sim Speed**
- **Speed Influence Factor**: Speed influence factor
- **Clamp Max Velocity**: Clamp maximum velocity
- **Camera Facing Tace Mesh**: TraceMesh always faces the camera
- **Camera Facing Lock Y-Axis**: Lock the Y-axis of the camera
- **Use Legacy Camera Facing**
- **Trance Mesh Translucent Sort Prio**
- **Use Custom Trace Source**: Use a custom trace source; when enabled, it is equivalent to using the following position as the camera position for collision detection
- **Custom Trace Source Position**: Position of the custom trace source
- **Trace Mesh Moving in World Space**: TraceMesh is located in world space
- **Movement Not Quantized to Steps OnAxis**
- **Movements is Locked on This axis**: Lock movement on a certain axis
- **Force Trace Mesh to Custom Vertical Pos**
- **Force Trace Mesh Vertical Position**: Lock the position of the TraceMesh
- **Enable Paint Buffer Offset in World Spacing**: Enable the world space mechanism of the paint buffer offset
- **Simple Painter Mode**: Simple painter mode without collision input

For **NinjaLiveActor**, the above parameters are further encapsulated, and the following parameters can be adjusted:

![image-20231117162207129](../../../04-UnrealEngine/Resources/image-20231117162207129.png)

- **Overlap Based Interaction**: Enable collision interaction

- **Interaction Volume Size**: Size of the interaction volume

- The following parameters are used to **filter** which objects can "interact" with the interaction volume.
  - **Track Actor Primitive Components With Tag**: Track components with this tag
  - **Track Actor Skeletal Mesh Components With Tag**: Track skeletal mesh components with this tag
  - **Overlap Filter Inclusive Obj Tab**: Inclusive object collision types for filtering
  - **Overlap Filter Inclusive Bone Name Exact**: Inclusive bone names for filtering; if empty, all bones will be processed
  - **Overlap Filter Inclusive Bone Name Partial**: Partial bone names for filtering; for example, entering "Foot" will include all bones with names containing "Foot"
  - **Exclude Specific Actors from Overlap**: Actor types to exclude from overlap
  - **Auto Exclude Large Overlapping Objects**: Automatically exclude large overlapping objects

### Adjusting Brushes

Brushes are used to control the scaling factor of the action area of FluidNinja input maps. Their parameter configurations are as follows:

![image-20231117161748514](../../../04-UnrealEngine/Resources/image-20231117161748514.png)

Some key parameters:

- **Brush Scaled Inversely by Trace Mesh Size**: The brush scales inversely with the size of the trace mesh
- **Brush Scaled by Interacting Obj Size**: The brush scales with the size of the interacting object
- **Use Obj Bounds Instead of Size**: Use the bounds of the interacting object as the brush size
- **Global Brush Scale**: Global brush scaling factor

> If the effect of collision interaction is almost invisible, it is likely that the brush is too small

## Summary

FluidNinja has an ingenious思路 and is a bit cumbersome to use, but the key steps are clear:

- Construct the Density and Velocity maps required for the simulation process, use appropriate brushes and presets, and combine them with corresponding materials to present the final desired effect.

### Advantages and Disadvantages

- FluidNinja uses 2D planes to disguise 3D visual effects. Its performance overhead is much lower than conventional particle fluid simulations. However, to disguise sufficiently realistic 3D effects, you need sufficiently realistic 2D inputs; otherwise, the trace mesh plane of FluidNinja can be easily识破 from certain perspectives.
- FluidNinja provides many ways to construct fluid inputs: textures, materials, RT, Niagara, cameras... which can meet most development needs. However, there are many details, and it is not easy to use. In-depth learning is required to freely create the desired effects.
- FluidNinja cannot completely replace particles; it is more suitable for **interactive** fluid simulations, such as smoke, fire, water...
