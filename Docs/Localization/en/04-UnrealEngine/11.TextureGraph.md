## Overview

If you are a graphics developer, you should know that we use many **Graphics Rendering Pipelines** to draw geometric shapes **(Primitives)** onto a **Render Target** (which can be understood as a texture or image). This process is generally called the **Base Pass** (or **Mesh Pass**, **Primitives Pass**):

![image-20231006120654050](../../../04-UnrealEngine/Resources/image-20231006120654050.png)

For the final画面 presented to the audience, we often need to add additional effects (such as global illumination, post-processing...) based on the image output from the Base Pass:

![image-20231006114116772](../../../04-UnrealEngine/Resources/image-20231006114116772.png)

Such effects are usually generated using a series of Render Passes. A Render Pass typically requires some texture inputs and ultimately generates some RTs. These generated RTs can then serve as texture inputs for another Render Pass. Treating these Render Passes as nodes and connecting their inputs and outputs with lines, we eventually get a graph-like structure:

![image-20240921164132083](../../../04-UnrealEngine/Resources/image-20240921164132083.png)

We usually call this a **Render Graph / Frame Graph**.

The Texture Graph we use follows a similar process. The difference is that Render Graph is used to complete the rendering of a frame of game画面, while Texture Graph **usually** is used to generate texture assets **during the editor phase**.

## Use Cases

Although Texture Graph is essentially for procedural textures, its feature set is far less comprehensive than mature procedural texture tools (such as [Substance Designer](https://www.adobe.com/hk_en/products/substance3d/apps/designer.html)). It is more suitable for people like the author who have neither in-depth knowledge of procedural textures nor proficiency in using PS, but know how to write code and have a basic foundation in image processing knowledge.

The author uses it for these things:

1. Drag nodes to quickly write logic for simple image processing. For developers, when the input and output are clear, writing code is often more intuitive and efficient than operating the editor.
2. Build reusable texture generation pipelines, i.e., templating. This is very useful when there are a large number of source (input) textures or when source textures are frequently iterated over time cycles.

### Image Processing Widget

Some time ago, I watched *Ashes of Time* again, and there was a super cool shot in it 0.0

![WeChat Image_20240817215316](../../../04-UnrealEngine/Resources/%E5%BE%AE%E4%BF%A1%E5%9B%BE%E7%89%87_20240817215316.png)

I wanted to take it down as a background, but the style was a bit greasy. Maybe turning it black and white would look better, so I did a grayscale conversion:

![82770255820153](../../../04-UnrealEngine/Resources/82770255820153.png)

It looked pretty good, but the gloss on the nose felt weird. So I opened PS:
- Tried the eraser pen, but it got blurry.
- Used the lasso tool to frame the bright area and adjust the brightness range. Oh no, the edges couldn't be smoothed after adjustment.

It was clearly a simple logic—I just wanted the nose area not to be so bright—but I struggled for a long time without success. Finally, I opened Qt, wrote a rendering pipeline, and solved it with a few lines of code. The fragment shader code was roughly like this (values are not accurate):

```c++
void main(){
    vec4 TextureColor = texture(Texture, UV);
    float Gray = (TextureColor.r + TextureColor.g + TextureColor.b) / 3;		// Grayscale conversion
    if( UV.x > 0.53 && UV.x < 0.56 && UV.y > 0.45 && UV.y < 0.51)					// Area selection
    {
        if(Gray > 0.2)															// Select parts with grayscale value greater than 0.2
        {
            Gray = 0.2 + (Gray - 0.2) * 0.1; 									// Scale the grayscale of parts exceeding 0.2 to 0.1 times the original.
        }
    }
    OutFragColor = vec4(Gray, Gray, Gray, 1);
}
```

The final effect was pretty good:

![26b522e2fa38b897c6e61bb8b4d5042](../../../04-UnrealEngine/Resources/26b522e2fa38b897c6e61bb8b4d5042.jpg)

Of course, this can also be quickly implemented with Python and CV, but many friends who know UE can't write code or use those complex software (learning UE clearly is already hard enough). However, they usually know how to write materials, so the significance of Texture Graph is that it allows friends who know UE to do some simple image processing without having to spend a lot of effort learning a certain software for a relatively simple requirement.
