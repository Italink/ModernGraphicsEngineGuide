## IDE

An **IDE (Integrated Development Environment)** is the most frequently used tool for modern programmers. It not only provides compilation tools but also typically includes:

- **Text Editor**: Writes code with syntax highlighting for easier reading.
- **IntelliSense**: Suggests complete code as you type, speeding up development.
- **Debugger**: Executes programs step-by-step to quickly identify logical errors.
- **User-Friendly Interface**: Neatly arranged controls like buttons, panels, menus, and windows for convenient operation.
- **Performance Profiler**: Analyzes program performance metrics such as CPU usage and memory consumption.
- **Project Management Tools**: Manages all project resources, including source files, images, videos, and third-party libraries.
- ...

## Build Tools

In the previous section, we briefly walked through the C++ compilation process using Visual Studio's CL compiler. In actual project development, a project almost always has more than one source file, which means we need to write a lot of compilation commands. Fortunately, we can write these commands in a **makefile** and use the **make** tool to build. However, there is a critical issue:

> Commands that work on Windows won't run on Linux.

Yes, since makefiles directly call OS-specific commands, and commands differ between systems, many cross-platform build tools have emerged, such as:

- [cmake](https://link.zhihu.com/?target=https%3A//cmake.org/): The current mainstream cross-platform build tool.
- [qmake](https://link.zhihu.com/?target=https%3A//doc.qt.io/qt-6/qmake-manual.html): A build tool provided by Qt. Qt has now fully transitioned to CMake, and qmake is no longer maintained.
- [nmake](https://link.zhihu.com/?target=https%3A//docs.microsoft.com/en-us/cpp/build/reference/nmake-reference): A built-in tool in Visual Studio that executes compilation and linking steps described in Makefiles.
- [xmake](https://link.zhihu.com/?target=https%3A//xmake.io/): A lightweight Lua-based cross-platform build tool developed by a Chinese developer.
- UBT: A C#-based build tool in Unreal Engine.

For most C++ beginners, project building is often done using the IDE's graphical interface, clicking buttons to add source files (e.g., Visual Studio):

![image-20230113082804541](../../../00-C++/Resources/image-20230113082804541.png)

Graphical interfaces are convenient, but they have drawbacks:

- If the IDE doesn't support cross-platform, its project files definitely won't either, making compilation on other platforms impossible.
- Different systems require different build configurations. Graphical interfaces only allow static configurations, not automated build logic.
- Project files configured via the GUI may lose links if file paths or systems change.
- Library management is prone to chaos and is overly cumbersome...

> That said, the author used to build projects purely through the GUI without any build tools and had no issues (ignorance is bliss).
>
> The main reasons forcing me to abandon the GUI were:
>
> - Needing to "preprocess" some project files before compilation (copying Qt's Moc: [XObject](https://github.com/Italink/XObject)).
> - Executing scripts or commands before compilation, such as compiling shader code into binary files in advance.

So **which build tool should you choose among so many options?**


### CMake

Why CMake? Is it very powerful? No—that's not the main reason. The fundamental reason is: **most open-source communities use CMake as their build tool**, making it easy to integrate third-party libraries.

Many people may complain that CMake is difficult and its syntax is "like shit." But the difficulty isn't CMake itself—build logic naturally becomes complex as project size grows. All build tools share similar core logic, with only a few essential commands. The rest are just build options, cross-platform configurations, and automation scripts. Once you master one build tool, others are easy to pick up.

Using CMake to manage projects offers several benefits:

- CMake can generate project files for IDEs on various platforms.
- CMake allows writing logical code to implement automated builds and adapt to platform-specific build details.
- It simplifies managing subprojects (libraries).
- Project files include dependency analysis, enabling fast compilation.

For beginners, you only need to familiarize yourself with CMake GUI and basic CMakeLists syntax.

#### CMake GUI

CMake GUI is a **friendly** graphical interface that replaces command-line operations.

After installing CMake, remember to create a desktop shortcut for CMake GUI.

![image-20230108215228112](../../../00-C++/Resources/image-20230108215228112.png)

To build a CMake project using CMake GUI:

- Drag the CMakeLists.txt into the window. Set `Where to build the Binaries`—the author usually appends `/build` to the source directory.
- Click `Configure` to open a popup. Select the IDE project files you want to generate and any command-line parameters.

  ![image-20230108220004147](../../../00-C++/Resources/image-20230108220004147.png)

- After clicking `Finish`, configurable options will appear. Adjust them based on descriptions.
- Click `Generate` to create the corresponding IDE project files.
- Finally, click `Open Project` to launch the IDE and open the project.

If the code file structure changes later, you need to re-run `Generate` in CMake GUI. However, most IDEs automatically trigger `Generate` when they detect changes to **CMakeLists.txt**.

> Some IDEs (like Qt Creator and Visual Studio) support opening CMakeLists.txt directly. For Visual Studio, the author recommends using CMake GUI to generate `.sln` project files.


#### Basic CMakeLists Syntax

CMake isn't difficult—it just involves setting project information:

```cmake
project(${ProjectName} VERSION 0.1 LANGUAGES CXX)
```

Specify the minimum CMake version:

```cmake
cmake_minimum_required(VERSION 3.5)
```

The manual operation of "clicking to add a source file" becomes:

```cmake
add_executable(${TargetName} *.h *.cpp ...)				// Create executable
// add_library(${TargetName} STATIC *.h *.cpp ...)		// Create static library
// add_library(${TargetName} SHARED *.h *.cpp ...)		// Create dynamic library
```

To link other libraries:

```cmake
target_link_libraries(${TargetName} PRIVATE ${LibraryName})  
// PRIVATE: Only ${TargetName} can access code in ${LibraryName}
// PUBLIC: Other libraries linking ${TargetName} can also access ${LibraryName}
```

To add include directories:

```cmake
target_include_directories(QEngineEditor PRIVATE ${IncludeDir}) 
```

To manipulate a local variable:

```cmake
set(VarName "This is String")
message(Warning ${VarName})  // Use ${} to read variables; this prints the value of VarName
```

To add a subdirectory (containing a CMakeLists.txt):

```cmake
add_subdirectory(${Subdir})
```

These are the basic operations. If you think a configuration or feature is reasonable, it probably exists—just search online or check the official documentation. Build files don't change often; you only need to understand the core logic.

All build tools are similar—use whatever you prefer. They aren't hard to use; the real challenge is configuring details for various platforms and frameworks, which is unavoidable.

There are many excellent CMake tutorials online, but the author recommends the official documentation: https://cmake.org/cmake/help/latest/guide/tutorial/index.html

## Package Management

Python users are likely familiar with the package manager `pip`—using `pip install ...` quickly installs third-party libraries for Python.

C++ package management has always been chaotic. To add a third-party library (e.g., OpenCV, FFmpeg) to your project, you might need to download it from the official website. If it's CMake-built source code, that's manageable; but for precompiled libraries, you must check if it's Debug/Release, dynamic/static, MD/MT, or 32/64-bit...

Many people have struggled with library installation configurations. Now, there's a tool to save you—[Vcpkg](https://github.com/microsoft/vcpkg).

> Vcpkg helps you manage C and C++ libraries on Windows, Linux, and macOS.

For usage instructions, refer to:

- https://github.com/microsoft/vcpkg/blob/master/README_zh_CN.md


## Version Control

That day, I recalled the fear of working without version control...

When I first started learning, I didn't know about version control tools. I only solved small problems (max 100-200 lines of code) or wrote small projects (around 1,000 lines). As project size grew, each feature change involved significant code modifications. So before starting, I would copy the source code as a backup to avoid "mysterious" unfixable bugs from new code.

This worked initially—until I got carried away coding once and forgot to back up. A week's worth of changes (a lot of code) led to a bug I couldn't fix after a full day of debugging. I had to use an old backup and rewrite the code incrementally, testing each part. It took three days to fix the issue and restore progress.

Those three days were agony. I stared at familiar code, rewriting it carefully, almost giving up but forcing myself to persist...

Even then, I was reluctant to spend time learning new tools, preferring to "pile up" code instead.

Later, an experienced colleague patiently pointed out flaws in my project and process, and earnestly introduced Git. I was finally convinced to try it—and I've used it ever since. If I could judge my past self now, I'd only say two words: "idiot."

### Markdown

> Markdown is a lightweight markup language created by John Gruber. It allows people to write documents in a readable plain-text format, which is then converted to valid XHTML (or HTML). This language incorporates many features of plain-text markup already used in emails.
>
> —— Baidu Encyclopedia: https://baike.baidu.com/item/markdown/3245829

Why use Markdown?

The author writes all blogs in Markdown. Key benefits:

- **Fast Writing**: Familiarity with syntax speeds up document creation.
- **Simple Operation, Low Cognitive Load**: Restricts "unreasonable" features to ensure linear document logic—writing feels like a pleasure.
- **Universal**: Many websites support Markdown (it's plain text at heart). Other sites can parse its syntax for preview. Being text-based also makes version control easy.
- **Aesthetic**: Markdown only records structure; many beautiful third-party themes are available.

What tools are used to write Markdown?
