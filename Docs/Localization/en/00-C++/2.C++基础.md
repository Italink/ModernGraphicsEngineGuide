cl.exe is a command-line program. Next, we will use this command-line program to generate our own command-line program.

First, create a new file named **main.cpp** in any path with the following code:

```c++
#include <iostream>

/**
* argc is the number of parameters
* argv is the array of parameter strings
*/

int main(int argc, char** argv) {
	std::cout << "argc: " << argc << std::endl;
	for (int i = 0; i < argc; i++) {
		std::cout << i << ": " << argv[i] << std::endl;
	}
	return 0;
}
```

Enter `cmd` + `Enter` in the address bar of the Windows file browser to open the console. First, enter the command `cl.exe` + `Enter` for testing:

Successful compilation will generate two files:

- **main.obj**: Object file, intermediate file during compilation
- **main.exe**: Executable file under Windows

![image-20220816122621807](../../../00-C++/Resources/image-20220816122621807.png)

> Actually, cl.exe performs multiple steps here:
>
> - Precompilation: Output source files (`*.c`, `*.cpp`) as `*.i` files: Compile preprocessing directives in the source code, such as #define, #include, #if...
> - Compilation: Compile `*.i` into `*.s` files: Convert high-level language to assembly language.
> - Assembly: Compile `*.s` into `*.o` files: Convert assembly language to machine instructions.
> - Linking: Link `*.o` files and finally merge them into an executable file (`*.exe` under Windows).

- Enter `where command name` in cmd, and you can find the storage location of the corresponding command-line program. For example: `where winget` will get the path of winget.

## Libraries

In real life, you will find that all kinds of common devices are assembled from parts. For example, a common mobile phone consists of a battery, screen, sensors, etc.

If a mobile phone were not composed of parts but a whole, the following scenarios might occur:

- For users, even if only the screen is broken, they have to replace the entire phone...
- For mobile phone manufacturers, they need to control more directions, the R&D pressure doubles, and they have to increase investment. If the company's architecture is improper and decision-making power is excessively concentrated in the center, it will hinder the development of the R&D department.

Computers can be regarded as a reflection of the real world. In C++, such problems must also exist. For this reason, engineers often **modularize** programs and encapsulate collections of specific functions into a **Library**. The benefits of this are:

- Distribute the pressure of project development and maintenance to various libraries, making everyone in the development team much easier.
- In super-large projects, the compilation time can be greatly reduced by analyzing the dependency relationships of libraries.
- Libraries can also be used to extend plugins for programs.

## Coding Standards

In team collaboration, to reduce the cognitive burden between each other, team members are often required to follow a certain coding standard, such as:

- Google Coding Standard: https://google.github.io/styleguide/cppguide.html
- GNU Coding Standard: https://www.gnu.org/prep/standards/standards.html
- LLVM Coding Standard: https://llvm.org/docs/CodingStandards.html
- Linux Kernel Coding Standard: https://www.kernel.org/doc/Documentation/process/coding-style.rst
- Qt API Style: https://doc.qt.io/archives/qq/qq13-apis.html

Each team may have different requirements for coding style, so readers often need to "when in Rome, do as the Romans do". There are only two types of ugly code:

- Code that does not follow standards
- Code with inconsistent standards
