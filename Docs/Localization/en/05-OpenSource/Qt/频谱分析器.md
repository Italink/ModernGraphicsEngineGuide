# Audio Visualization Analyzer

- GitHub Repository: https://github.com/Italink/SpectrumEngine

Recently, I encapsulated the Specinker engine into a static link library. If you can program and like [spectrum](https://so.csdn.net/so/search?q=频谱&spm=1001.2101.3001.7020), you're in luck!

## Some Rambling

I originally thought that encapsulating it into a dynamic link library would allow unified use by languages that can call DLLs (C/C++, Java, Python...). It was a good idea, but not to mention Java and Python—even porting from Qt to VS was extremely difficult. The reason is that Qt's default compiler is MinGW, which generates static link library files with the .a extension. However, VS cannot parse .a files and can only parse .lib libraries. So I compiled it again with MSVC, linked various system libraries, and got it to run, but it threw errors as soon as I called it. The issue was that creating threads and using some Qt functions in my code required QApplication, which in turn needed a Qt runtime environment set up in VS. After days of work, I found that the library I encapsulated could still only be used in Qt (even in VS, it required a Qt environment set up) and could only be called via C++. I thought of an alternative approach: using system shared memory to transfer data, which would enable cross-language processing of spectrum data. However, this method would be quite cumbersome to implement, and I haven't had time to work on it recently. If you know any solutions to this problem, please let me know!
