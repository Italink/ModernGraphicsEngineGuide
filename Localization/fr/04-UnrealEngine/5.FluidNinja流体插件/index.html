    Fluid Ninja¶

    Fluid Ninja est un plugin de simulation de fluide interactif incroyable, qui permet de créer des effets époustouflants avec une consommation de performances extrêmement faible :

    • Chaîne YouTube de l'auteur : https://www.youtube.com/c/AndrasKetzer
    • Boutique Unreal : https://www.unrealengine.com/marketplace/en-US/product/fluidninja-live
    • Communauté de discussion (Discord) : https://discord.com/invite/rgEtwua2tu

    L'auteur propose de nombreuses tutoriels vidéo sur YouTube :

    • FluidNinja LIVE - ALL IN ONE TUTORIAL and making FX from scratch - YouTube

    • Tutoriels en chinois de FluidNinja - 陶仁贤

    Blueprints clés¶

    NinjaLiveComponent¶

    NinjaLiveComponent est le cœur de Fluid Ninja. Son utilisation nécessite l'association à un maillage statique (généralement un plan, appelé maillage de suivi (Trace Mesh)), et le résultat final de la simulation de fluide sera affiché sous forme de matériau sur ce maillage de suivi :

    Le plan rouge sur l'image ci-dessus est le maillage de suivi

    NinjaLive¶

    NinjaLive est un Actor par défaut fourni par Fluid Ninja. Il encapsule les paramètres de NinjaLiveComponent, inclut un plan de suivi adapté à la plupart des cas d'utilisation, simplifie la configuration de NinjaLiveComponent et ajoute des fonctionnalités supplémentaires, telles que :

    • Culling et mise en veille de NinjaFluid via ActivationVolume : NinjaLiveComponent s'active uniquement lorsqu'il entre dans ActivationVolume
    • Configuration plus fine de la zone d'interaction via InteractionVolume.

    NinjaLive_Utilities¶

    NinjaLive_Utilities (Actor Blueprint) offre des fonctionnalités de débogage pratiques, telles que :

    • Contrôle automatique du joueur le plus proche de ce Blueprint
    • Affichage de la souris
    • Ajustement de la qualité de l'anti-aliasing, de la profondeur de champ et du flou de mouvement
    • Suppression de la limite de 120 FPS de l'éditeur
    • ...

    Vous pouvez glisser-déposer ce Blueprint dans la scène et le configurer :

    Processus de simulation¶

    Dans le répertoire d'actifs de FluidNinja, il existe un Blueprint nommé Help :

    Il contient une description détaillée du flux de simulation de Fluid Ninja :

    Le cœur de NinjaFluid réside dans :

    • Construction des textures Density (densité) et Velocity (vitesse)
    • Superposition de Noise (bruit) pour ajouter de l'aléatoire au fluide
    • Ajustement des Brush (pinceaux) pour contrôler la forme du fluide
    • Association avec le matériau de sortie (Output Material)
    • Affichage du résultat final sur la surface du matériau du maillage de suivi (Trace Mesh)
    • Obtention du résultat souhaité :

    • Density est une texture monochannel, dont la plage de valeurs est [0,1], utilisée pour représenter la densité du fluide à la position actuelle.
    • Velocity est une texture双通道, dont la plage de valeurs est [0,1], utilisée pour représenter la vitesse vectorielle du fluide à la position actuelle. Étant donné qu'elle est normalisée à [0,1], une vitesse 0 correspond en réalité aux valeurs RG (0.5, 0.5). Sur l'image ci-dessus :
    • Le canal R de la texture Velocity correspond à la vitesse horizontale : lorsque la valeur est <0.5, le fluide se déplace vers la gauche ; lorsque elle est >0.5, il se déplace vers la droite
    • Le canal G de la texture Velocity correspond à la vitesse verticale : lorsque la valeur est <0.5, le fluide se déplace vers le haut ; lorsque elle est >0.5, il se déplace vers le bas
    • FluidNinja permet l'entrée de matériaux tricolores, où les canaux RG représentent Velocity et le canal B représente Density

    Processus d'utilisation¶

    Durant la création, nous opérons essentiellement sur NinjaLiveComponent, dont les catégories de configuration (Categories) sont les suivantes :

    • Live Activation : Contient uniquement l'option Disable Component, qui peut être définie dynamiquement via Blueprint pour effectuer du culling.
    • Live Interaction : Toutes les configurations relatives à l'interaction, telles que le filtrage des cibles d'interaction, l'orientation et le verrouillage du maillage de suivi, le décalage des coordonnées mondiales, etc.
    • Live Brush Setting : Configuration des paramètres du pinceau.
    • Live Generic : Configuration générique, principalement pour ajuster les pré-réglages, les entrées et les sorties de l'effet.
    • Live Performance : Configuration des performances, permettant de définir le nombre d'itérations de l'effet, la plage de FPS, le LOD, etc.
    • Live Compatibility : Configuration de compatibilité, permettant de définir le canal de collision, de remplacer les entrées, etc.
    • Live Debug : Configuration de débogage, fournissant des options à cocher pour afficher des informations de提示.
    • Live Raymarching : Configuration du raymarching.
    • Live Memory Management : Configuration de la gestion de mémoire.

    Construction des entrées¶

    Les entrées ici font principalement référence à Density (densité) et Velocity (vitesse). Les paramètres de configuration des entrées associés se trouvent principalement dans la catégorie Live Generic de NiagaraComponent. Les sources d'entrée de Fluid Ninja peuvent être les suivantes :

    • Textures statiques
    • Matériaux dynamiques
    • Capture par caméra de scène
    • Cibles de rendu (RenderTarget)
    • Vidéos en streaming
    • Entrées de souris
    • Interactions de scène : maillages statiques, maillages dynamiques, maillages squelettiques, objets destructibles...

    Ces entrées ne sont pas indépendantes ; elles peuvent coexister. FluidNinja mélange plusieurs entrées ensemble, voir le flux de travail dans Help.uasset pour plus de détails.

    Dans la carte Content/FluidNinjaLive/Tutorial/Levels/NinjaLive_Level03_SimulationInputs_LIVE17.umap, il existe des exemples complets d'entrées NinjaFluid. Les étapes clés de ces entrées sont enregistrées ci-dessous :

    Matériau dynamique (Material)¶

    La configuration de l'entrée de matériau se trouve dans la catégorie Live Generic de NinjaComponent :

    • Vous pouvez ajouter des matériaux d'entrée disponibles dans le paramètre Input Materials. Ajoutez-en plusieurs pour pouvoir basculer entre eux dans NinjaLive_PresetManager.
    • Réglez l'index Input Material Selected pour choisir le matériau d'entrée actuellement utilisé.
    • Cocher RGB-Input Material fera en sorte que les canaux RG du matériau servent de texture Velocity et le canal B de texture Density ; sinon, par défaut, seul le canal R du matériau sera utilisé comme texture Density
    • Cocher Input Material Clamp découpera l'image dont les coordonnées UV se trouvent hors de [0,1].

    Pour les matériaux d'entrée de Ninja Fluid, il faut sélectionner Domaine du matériau comme Post-process et désactiver Projeter les ombres de détection de lumière :

    Cible de rendu (RenderTarget)¶

    La configuration de l'entrée de matériau se trouve dans la catégorie Live Generic de NinjaComponent :

    • Cocher Use Render Target as Input fera en sorte que la Input Render Target ci-dessous soit utilisée comme entrée de simulation de fluide
    • Input Render Target est utilisé pour spécifier la Render Target à lire

    Dans Fluid Ninja, cette méthode peut être utilisée pour créer des fluides 3D à forme contrôlable

    Le Level3 contient l'exemple suivant :

    • À gauche, un système de particules Niagara ; au milieu, un RT projeté ; à droite, l'effet final obtenu grâce au RT + matériau de sortie

    • Empty : Émetteur de particules utilisé pour la simulation

    • Ajoutez une vitesse d'émission (60) et une vitesse initiale aléatoire dispersée ; vous verrez l'effet suivant :

    Interaction de collision¶

    Fluid Ninja peut utiliser des collisions physiques comme entrée pour créer des effets de fluide interactifs. Un exemple simple est le suivant :

    • Ajoutez un NinjaLiveActor

    • Définissez Trace Mesh Size et Interaction Volume Size sur (5,5,1)

    • Configurez NinjaLiveComponent\Live Bursh Settings ; sinon, le résultat sera invisible en raison d'un pinceau de collision trop petit

      • Cochez Brush Scaled By Interacting Obj Size
      • Définissez Primitive Obj Brush Scale sur 20

    • Ajoutez un personnage (Mannequin) ; vous verrez l'effet suivant :

    Cet effet est réalisé via le mécanisme de collision physique d'UE, et ses paramètres complets se trouvent dans NinjaLiveComponent\Live Interaction :

    • Continuous Interaction with Owner Actor : Interaction continue avec l'Actor possédant ce composant
    • Continuous Interaction incluisve Obj Type : Filtrer le type d'objet de collision pour l'interaction
    • Continuous Interaction Component Name : Filtrer le nom du composant pour l'interaction
    • Continuous Interaction Bone Names Exact : Filtrer le nom de l'os pour l'interaction
    • Single Target Mode : Mode cible unique. Lorsqu'il est activé, FluidNinja considère que toutes les images générées par les collisions proviennent d'une seule cible, ce qui rend le chemin de collision lisse sans断层 (interpolation)
    • Single Target Type
    • Single Target Mode Skeletal Mesh Index
    • Single Target Move Set Sim Speed
    • Speed Influence Factor : Facteur d'influence de la vitesse
    • Clamp Max Velocity : Tronquer la vitesse maximale
    • Camera Facing Tace Mesh : Le TraceMesh est toujours orienté vers la caméra
    • Camera Facing Lock Y-Axis : Verrouiller l'axe Y de la caméra
    • Use Legacy Camera Facing
    • Trance Mesh Translucent Sort Prio
    • Use Custom Trace Source : Utiliser une source de suivi personnalisée. Lorsqu'elle est activée, la position ci-dessous est utilisée comme position de la caméra pour la détection de collision
    • Custom Trace Source Position : Position de la source de suivi personnalisée
    • Trace Mesh Moving in World Space : Le TraceMesh se trouve dans l'espace mondial
    • Movement Not Quantized to Steps OnAxis
    • Movements is Locked on This axis : Verrouiller le mouvement sur cet axe
    • Force Trace Mesh to Custom Vertical Pos
    • Force Trace Mesh Vertical Position : Verrouiller la position du TraceMesh
    • Enable Paint Buffer Offset in World Spacing : Activer le mécanisme de décalage du tampon de peinture dans l'espace mondial
    • Simple Painter Mode : Mode peinture simple, sans entrée de collision

    Pour NinjaLiveActor, ces paramètres sont encapsulés davantage, et les paramètres suivants peuvent être ajustés :

    • Overlap Based Interaction : Activer l'interaction de collision

    • Interaction Volume Size : Taille du volume d'interaction

    • Les paramètres suivants sont utilisés pour filtrer quels objets peuvent interagir avec le volume d'interaction.

    • Track Actor Primitive Components With Tag : Suivre les composants primitifs d'Actor avec cette étiquette

    • Track Actor Skeletal Mesh Components With Tag : Suivre les composants de maillage squelettique d'Actor avec cette étiquette

    • Overlap Filter Inclusive Obj Tab : Type d'objet de collision à inclure pour le filtrage

    • Overlap Filter Inclusive Bone Name Exact : Nom de l'os à inclure pour le filtrage. Si vide, tous les os seront traités

    • Overlap Filter Inclusive Bone Name Partial : Champ du nom de l'os à inclure pour le filtrage. Par exemple, si vous entrez "Foot", tous les os dont le nom contient "Foot" seront inclus

    • Exclude Specific Actors from Overlap : Type d'Actor à exclure du chevauchement

    • Auto Exclude Large Overlapping Objects : Exclure automatiquement les objets de chevauchement de grande taille

    Ajustement du pinceau¶

    Le pinceau est utilisé pour contrôler le facteur d'échelle de la zone d'action de la texture d'entrée de FluidNinja. Ses paramètres de configuration sont les suivants :

    Quelques paramètres clés :

    • Brush Scaled Inversely by Trace Mesh Size : Le pinceau est mis à l'échelle inversement par la taille du maillage de suivi
    • Brush Scaled by Interacting Obj Size : Le pinceau est mis à l'échelle par la taille de l'objet interactif
    • Use Obj Bounds Instead of Size : Utiliser les limites de l'objet interactif comme taille du pinceau
    • Global Brush Scale : Facteur d'échelle global du pinceau

    Si l'effet de l'interaction de collision est presque invisible, c'est très probablement dû à un pinceau trop petit

    Résumé¶

    La démarche de FluidNinja est ingénieuse, son utilisation est un peu fastidieuse, mais les étapes clés sont claires :

    • Construire les textures Density (densité) et Velocity (vitesse) nécessaires au processus de simulation, utiliser des pinceaux et des pré-réglages appropriés et associer le matériau correspondant pour afficher le résultat final souhaité.

    Avantages et inconvénients¶

    • FluidNinja utilise un plan 2D pour simuler un effet visuel 3D. Sa consommation de performances est bien inférieure à celle de la simulation de fluide par particules classique. Cependant, pour simuler un effet 3D suffisamment réaliste, il faut des entrées 2D suffisamment réalistes ; sinon, le plan de suivi de FluidNinja peut être facilement détecté sous certains angles.
    • FluidNinja propose de nombreuses façons de construire les entrées du fluide : textures, matériaux, RT, Niagara, caméras... qui peuvent répondre à la plupart des besoins de développement. Cependant, il y a beaucoup de détails et l'utilisation n'est pas facile. Pour créer librement les effets souhaités, une étude approfondie est nécessaire.
    • FluidNinja ne peut pas remplacer complètement les particules ; il est plus adapté aux simulations de fluide interactives, telles que la fumée, le feu, l'eau...
