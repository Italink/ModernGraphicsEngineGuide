    IDE¶

    L'IDE (Integrated Development Environment - Environnement de développement intégré) est l'outil avec lequel les programmeurs modernes interagissent le plus fréquemment. Il propose non seulement des outils de compilation, mais inclut généralement :

    • Éditeur de texte : Écrire du code, avec coloration syntaxique pour faciliter la lecture.
    • Suggestions intelligentes : Suggérer le code complet après avoir saisi une partie, accélérant la vitesse de rédaction du développeur.
    • Débogueur : Exécuter le programme étape par étape, facilitant la découverte rapide de logiques erronées.
    • Interface esthétique : Disposition ordonnée de boutons, panneaux, menus, fenêtres et autres contrôles, pour une manipulation plus facile.
    • Analyse des performances : Outils pour analyser les performances du programme, comme l'utilisation du CPU, la consommation de mémoire.
    • Outil de gestion de projet : Gérer toutes les ressources du programme, y compris fichiers sources, images, vidéos, bibliothèques tierces, etc.
    • ...

    Les IDE C++主流 actuels sont :

    • Visual Studio : Fourni par Microsoft, surnommé "l'IDE numéro un de l'univers" par beaucoup. Il est volumineux et est le premier choix pour le développement sous Windows.

    • Qt Creator : IDE officiel de Qt, multiplateforme, avec des fonctionnalités moyennes, mais convivial pour le développement de programmes Qt.

    • Clion : IDE fourni par JET BRAINS, avec des fonctionnalités d'assistance au code très confortables. Son autre IDE — Rider : dédié au développement de moteurs de jeu.

    • XCode : IDE sous système Mac.

    • Visual Studio Code : Éditeur de code multiplateforme fourni par Microsoft. Grâce à des extensions, il peut également compiler des programmes.

    Pour l'auteur, au début, lors de la résolution d'exercices, il a été obligé par l'école d'utiliser DevC++, VC6.0, et il s'en servait avec plaisir. En regardant en arrière aujourd'hui, il se rend compte qu'ils sont vraiment dépassés~

    L'auteur a passé par les étapes suivantes pour ses IDE :

    VC6.0 > Dev c++ > Visual Studio > IDEA(Java) > Qt Creator

    Actuellement, l'auteur utilise Visual Studio pour écrire du code C++ sous Windows, et Visual Studio Code pour traiter des fichiers texte courants, comme Lua, Python, GLSL...

    Visual Studio Code est sans aucun doute un excellent éditeur de texte (avec une multitude de plugins).

    Les IDE C++ sont en réalité assez similaires, avec toutes les fonctionnalités essentielles. L'auteur utilise Visual Studio pour le développement C++ principalement parce que son interface utilisateur est belle et qu'elle est complètement traduite en chinois...

    • Maîtriser le débogage pas à pas, les outils de vérification de mémoire et de performances, et comprendre les fichiers PDB.

    • Prêter attention au format d'encodage des fichiers de code.

    Outils de construction¶

    Dans la section précédente, nous avons brièvement passé en revue le processus de compilation C++ avec le compilateur CL de Visual Studio. Dans le développement de projets réels, un projet n'a绝大多数情况下 pas qu'un seul fichier source, ce qui signifie que nous devons écrire une multitude d'instructions de compilation. Heureusement, nous pouvons écrire ces instructions dans un fichier makefile et utiliser l'outil make pour construire. Mais il y a un problème très grave :

    Une instruction sous Windows ne sera pas reconnue sous Linux~

    Oui, car le makefile appelle directement les instructions du système d'exploitation, mais les instructions varient d'un système à l'autre. Cela a conduit à l'émergence de nombreux outils de construction de projets multiplateformes, comme :

    • cmake : Outil de construction multiplateforme主流 actuel.
    • qmake : Outil de construction fourni par Qt. Actuellement, Qt a complètement basculé vers Cmake, et qmake n'est plus maintenu.
    • nmake : Outil intégré de Visual Studio, chargé d'exécuter les étapes de compilation et de liaison décrites dans le Makefile.
    • xmake : Outil de construction multiplateforme léger basé sur Lua, écrit par un Chinois.
    • UBT : Outil de construction basé sur C# dans Unreal Engine.

    Pour la plupart des débutants en C++, la construction de projets se fait probablement la plupart du temps directement via l'interface graphique de l'IDE, en cliquant sur des boutons pour ajouter des fichiers sources, comme dans Visual Studio :

    L'interface graphique est effectivement pratique à utiliser, mais elle présente également certaines limites :

    • Si l'IDE lui-même ne supporte pas la multiplateforme, son fichier de projet ne pourra pas non plus être multiplateforme, de sorte que d'autres plateformes ne pourront pas compiler.
    • Sur différents systèmes, il y aura différentes configurations de construction. L'interface graphique ne permet que des configurations statiques, pas la mise en œuvre de logiques de construction automatisées.
    • Les fichiers de projet configurés via l'interface graphique peuvent perdre des liens précédents si le chemin du fichier ou le système change.
    • La gestion des bibliothèques est facile à embrouiller et trop fastidieuse...

    Quoi qu'il en soit, l'auteur n'a pas eu de problème en utilisant uniquement l'interface graphique pour écrire des projets sans outil de construction au début (l'ignorance est la faute).

    Les raisons principales qui l'ont poussé à abandonner l'interface graphique sont :

    • Besoin de "prétraiter" certains fichiers du projet avant la compilation du programme, puis de les soumettre au compilateur C++. (Copier Moc de Qt : XObject)
    • Exécuter des scripts ou des instructions avant la compilation du programme, comme compiler à l'avance le code shader en fichier binaire.

    Alors, quel outil de construction choisir parmi tant d'options ?

    CMake¶

    Pourquoi CMake ? Est-ce qu'il est très puissant ? Non, ce n'est pas la raison principale. La raison la plus fondamentale est : la plupart de la communauté open source utilise CMake comme outil de construction, et il est facile d'intégrer d'autres bibliothèques tierces avec lui.

    Beaucoup de camarades peuvent se plaindre que Cmake est difficile et que sa syntaxe est comme de la merde. En réalité, ce n'est pas Cmake qui est difficile, mais la logique de construction devient nécessairement complexe lorsque la taille du projet augmente. La logique principale de n'importe quel outil de construction est similaire, avec seulement quelques instructions de construction clés. Le reste concerne des options de construction, des configurations multiplateformes, des scripts automatisés, etc. Une fois qu'on maîtrise un outil de construction, les autres sont faciles à comprendre en passant rapidement dessus.

    La gestion de projets avec CMake apporte principalement les avantages suivants :

    • CMake peut générer des fichiers de projet pour les IDE de chaque plateforme.
    • Avec CMake, on peut écrire du code logique pour réaliser une construction automatisée et adapter les détails de construction de chaque plateforme.
    • Facilite la gestion des sous-projets (bibliothèques).
    • Les fichiers de projet ont une analyse des dépendances, et la vitesse de compilation est extrêmement rapide.

    Pour les débutants, il suffit généralement de maîtriser l'utilisation de CMakeGUI et la syntaxe de base de CmakeLists.

    CMake GUI¶

    CMake GUI est une interface graphique conviviale qui peut remplacer les opérations en ligne de commande.

    Après avoir installé Cmake, veuillez créer un raccourci sur le bureau pour CMake GUI.

    Pour construire un projet CMake, ouvrez directement CMake GUI :

    • Faites glisser CMakeLists.txt dans la fenêtre, définissez Where to build the Binaries (où construire les binaires), c'est-à-dire le répertoire de construction. L'auteur ajoute généralement /build à la fin du répertoire source.
    • Cliquez sur Configure, une fenêtre pop-up apparaît. Choisissez l'IDE pour lequel vous voulez générer les fichiers de projet, ainsi que quelques paramètres de ligne de commande.

    • Après Finish, des options de configuration ajustables apparaîtront, que vous pouvez modifier selon la description.
    • Cliquez ensuite sur Generate, qui générera les fichiers de projet pour l'IDE correspondant.
    • Enfin, cliquez sur Open Project, qui ouvrira directement le projet avec l'IDE correspondant.

    Si la structure des fichiers de code change par la suite, il faudra重新 Generate dans Cmake GUI. Cependant, généralement, l'IDE déclenchera automatiquement Generate lorsqu'il détecte un changement dans le contenu de CMakeLists.

    Certains IDE peuvent supporter l'ouverture directe de CMakeList.txt, comme Qt Creator et Visual Studio. Pour Visual Studio, l'auteur recommande plutôt d'utiliser CMake GUI pour générer les fichiers de projet VS (*.sln).

    Syntaxe de base de CMakeList¶

    CMake n'est pas difficile, il suffit de définir les informations du projet :

    project(${ProjectName} VERSION 0.1 LANGUAGES CXX)

    Limiter la version minimale de Cmake :

    cmake_minimum_required(VERSION 3.5)

    L'opération d'ajouter un fichier source en cliquant manuellement sur un bouton est remplacée par :

    add_executable(${TargetName} *.h *.cpp ...)             //Créer un fichier exécutable
// add_library(${TargetName} STATIC *.h *.cpp ...)      //Créer une bibliothèque statique
// add_library(${TargetName} SHARED *.h *.cpp ...)      //Créer une bibliothèque dynamique

    Si vous voulez intégrer une autre bibliothèque, utilisez :

    target_link_libraries(${TargetName} PRIVATE ${LibraryName})  
//PRIVATE signifie que seul ${TargetName} peut accéder au code de ${LibraryName}
//PUBLIC signifie que d'autres bibliothèques intégrant ${TargetName} peuvent également accéder au code de ${LibraryName}

    Si vous voulez ajouter un chemin Include, utilisez :

    target_include_directories(QEngineEditor PRIVATE ${IncludeDir})

    Si vous voulez manipuler une variable locale, utilisez directement :

    set(VarName "This is String")
message(Warning ${VarName})  // Utilisez ${} pour lire la variable. Ici, l'opération est d'afficher la valeur de VarName.

    Si vous voulez ajouter un sous-répertoire (un répertoire contenant un CMakeLists.txt), utilisez :

    add_subdirectory(${Subdir})

    Les opérations de base ne sont rien de plus que cela. Si vous pensez qu'une configuration ou une fonctionnalité est raisonnable, elle existe probablement. Une recherche sur Internet ou une consultation du site officiel suffisent. Les modifications des fichiers de construction ne sont pas fréquentes, il suffit de connaître la logique principale.

    Les outils de construction sont en réalité assez similaires, peu importe lequel on utilise. Leur utilisation n'est pas difficile, la difficulté réside dans les configurations détaillées de diverses plateformes et frameworks, ce qui est inévitable.

    Concernant l'utilisation de CMake, il y a beaucoup de tutoriels de qualité sur Internet, mais l'auteur recommande plutôt de lire sa documentation officielle : https://cmake.org/cmake/help/latest/guide/tutorial/index.html

    Gestion de paquets¶

    Certains camarades qui ont utilisé Python ont probablement utilisé l'outil de gestion de paquets — pip.

    L'utilisation de pip install ... permet d'installer rapidement des bibliothèques tierces pour Python.

    La gestion de paquets en C++ a toujours été assez confuse. Si vous voulez installer une bibliothèque tierce dans votre projet (par exemple OpenCV, ffmpeg...), vous devrez probablement la télécharger sur le site officiel. Si c'est un code source construit avec CMake, c'est bien, mais si c'est un fichier de bibliothèque, vous devrez faire attention au type de compilation (Debug ou Release), à la bibliothèque dynamique ou statique, à MD ou MT, à 32 bits ou 64 bits...

    Beaucoup de camarades ont dû souffrir de diverses configurations lors de l'installation de bibliothèques. Maintenant,终于有 un outil qui sauve tout le monde — Vcpkg

    Vcpkg vous aide à gérer les bibliothèques C et C++ sur Windows, Linux et MacOS.

    Concernant son utilisation, vous pouvez consulter :

    • https://github.com/microsoft/vcpkg/blob/master/README_zh_CN.md

    Gestion de versions¶

    Ce jour-là, l'auteur a rappelé la peur qu'il y avait sans gestion de versions...

    Au début de son apprentissage, l'auteur ne connaissait pas les outils de gestion de versions, car il ne résolvait que des exercices, avec un volume de code ne dépassant jamais一两百 lignes, et même un petit projet n'atteignait pas mille lignes. Jusqu'à ce que la taille du projet augmente, et que chaque modification de code pour une fonctionnalité soit assez importante. Donc, avant de commencer, l'auteur copiait le code source pour le sauvegarder, afin d'éviter que le code ajouté ne contienne des erreurs "inexplicables" et irréparables.

    Au début, cette méthode n'a pas posé de problème, jusqu'à ce que l'auteur soit absorbé par l'écriture de code et n'ait pas fait de sauvegarde à l'avance. Il y avait environ une semaine de modifications de code, très nombreuses, et après une journée de recherche sans trouver la cause, il était sur le point de craquer. Plus tard, il n'a eu d'autre choix que d'utiliser la sauvegarde précédente pour réécrire, ajouter petit à petit, tester petit à petit. Il a fallu environ trois jours pour corriger le problème et reprendre le rythme.

    Durant ces trois jours, l'auteur a vécu chaque jour comme une éternité, regardant des lignes de code familières, réessayant avec prudence, voulant abandonner à plusieurs reprises, mais se persuadant constamment de continuer avec patience...

    Mais même ainsi, l'auteur n'était pas prêt à perdre du temps à découvrir de nouvelles choses, mais préférait consacrer ce temps à accumuler du code.

    Jusqu'à ce qu'il rencontre un vieux frère, qui a pris le temps de pointer les défauts dans son projet, les irrégularités dans son processus, et qui lui a présenté Git avec patience. L'auteur a终于 été touché par lui et a décidé de l'utiliser. Il l'utilise depuis lors. Si l'auteur actuel devait évaluer son ancien soi, il n'y aurait que deux mots — idiot.

    • Site officiel : https://git-scm.com/

    Si vous l'avez installé avec succès, vous verrez dans le menu contextuel (clic droit) :

    • Adresse de téléchargement : https://tortoisegit.org/download/

    Bien que certains IDE supportent Git, leurs fonctionnalités ne sont pas aussi puissantes que celles de Tortoise Git.

    Veuillez noter d'installer le pack de langue chinois lors de l'installation.

    L'utilisation de Git & Tortoise Git apporte les avantages suivants :

    • Vous pouvez soumettre du code petit à petit, et les journaux permettent de comparer直观ement les modifications entre versions.

    • Vous pouvez retracer les informations de soumission complètes d'un seul fichier.

    • Lors de la collaboration entre plusieurs personnes, vous pouvez fusionner du code.
    • Vous pouvez effectuer des essais de fonctionnalités sur des branches.
    • ...

    SVN¶

    SVN est l'abréviation de subversion, un système de contrôle de version open source. Grâce à une gestion efficace via un système de branches, il est simplement utilisé pour que plusieurs personnes développent un même projet, partagent des ressources et réalisent une gestion centralisée finale.

    Comparé à Git, SVN semble très ancien, mais de nombreuses entreprises continuent de l'utiliser en raison de sa facilité de gestion.

    Tortoise propose également un support pour SVN :

    • https://tortoisesvn.net/

    Documentation et notes¶

    Comme le dit le proverbe, une bonne mémoire ne vaut pas un mauvais crayon. Le cerveau humain est comme le CPU d'un ordinateur : la mémoire est rapide, mais sa capacité est limitée. Les gens intelligents savent stocker de grandes quantités de contenu sur le "disque (notes)" et conserver l'index du contenu dans le "cache rapide" du cerveau. Prendre des notes apporte principalement plusieurs avantages :

    • Renforcer l'impression lors de la note-taking.
    • Associer rapidement les détails lors de la révision.

    Alors, comment prendre des notes ?

    Les méthodes de note-taking que l'auteur a vu jusqu'à présent sont principalement :

    • Logiciels de bureautique : Word, Excel.
    • Sites de blog : Zhihu, CSDN, Juejin, JianShu, Bilibili, sites de blog auto-hébergés...
    • Logiciels de notes : comme Evernote.

    Au début, l'auteur enregistrait des idées de résolution d'exercices sur CSDN. Sans le vieux frère qui lui a présenté avec patience Github, Markdown et CMake, il serait probablement encore en train de s'enfermer dans son propre monde et de lutter contre lui-même...

    Markdown¶

    Markdown est un langage de balisage léger, créé par John Gruber. Il permet aux gens d'écrire des documents dans un format de texte brut facile à lire et à écrire, puis de les convertir en documents XHTML (ou HTML) valides. Ce langage absorbe de nombreuses caractéristiques de balisage de texte brut déjà présentes dans les e-mails.

    ——《Baidu Encyclopedia》：https://baike.baidu.com/item/markdown/3245829

    Pourquoi utiliser Markdown ?

    Les blogs de l'auteur sont tous écrits en Markdown. Ses impressions après utilisation constante sont :

    • Vitesse d'écriture rapide : Après avoir maîtrisé la syntaxe Markdown, la vitesse d'écriture de documents est très rapide.
    • Manipulation simple, faible charge cognitive : Limite certaines fonctionnalités "irrationales", garantit que la logique du document est linéaire. Écrire un document avec lui est une véritable jouissance.
    • Universel : Beaucoup de sites supportent Markdown, car il s'agit essentiellement de texte brut. D'autres sites peuvent analyser sa syntaxe pour prévisualiser, et étant donné qu'il s'agit de texte, la gestion de versions des documents est également facile.
    • Esthétique : Markdown ne enregistre que la structure du document, et il y a beaucoup de beaux thèmes de peau tiers.

    Alors, quel outil utiliser pour écrire en Markdown ?

    Il y a beaucoup d'éditeurs Markdown, et certains sites de blog le supportent directement. Pour l'utilisation locale, l'auteur a vu que beaucoup utilisent VS Code, et puis il y a l'outil Markdown incroyable, le meilleur du monde, l'神器 :

    Cartes mentales¶

    Comparé à la narration linéaire de Markdown, les cartes mentales (Mind map) correspondent mieux aux habitudes de pensée humaines, avec des avantages comme stimuler la pensée, mémoire temporaire, pensée divergente et pensée concentrée.

    Elles sont适用于 :

    • Liste de tâches à faire
    • Préparation de discours
    • Prise de notes
    • Résolution de problèmes
    • Planification de projets
    • Décision-making
    • Gestion des connaissances
    • Gestion de projets
    • Réflexion personnelle
    • Écriture
    • ...
