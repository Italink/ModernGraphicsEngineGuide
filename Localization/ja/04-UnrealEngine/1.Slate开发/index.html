    1.Slate开发

    SlateはUEに提供されるUIフレームワークで、その核心理念は以下の通りです。

    • Slate アーキテクチャ|Unreal Engine 5.2 ドキュメント

    UIに関するいくつかの基礎概念については、以下を参照してください。

    • 現代グラフィックエンジン入門ガイド（七）— GUI

    基礎¶

    UEでSlateを使用するには、3つの核心構造を理解する必要があります。

    • FSlateApplication ：グローバルシングルトンで、すべてのUIのスケジューリングセンターです。
    • SWindow ：トップレベルウィンドウで、クロスプラットフォームウィンドウのインスタンス（FGenericWindow）を保持し、ウィンドウに関する設定と操作を提供します。
    • SWidget ：ウィジェットで、ウィンドウ領域を分割し、自身の領域内のインタラクションと描画イベントを処理します。

    基本的な使用方法¶

    UEにおける簡単なSlateの使用例は以下の通りです。

    auto Window = SNew(SWindow)                         //ウィンドウを作成
    .ClientSize(FVector2D(600, 600))                //ウィンドウサイズを設定
    [                                               //ウィンドウ内容を埋める
        SNew(SHorizontalBox)                        //水平ボックスを作成
        + SHorizontalBox::Slot()                    //サブコントロールスロットを追加
        [                                           
            SNew(STextBlock)                        //テキストボックスを作成
            .Text(FText::FromString("Hello"))       //テキストボックスの内容を設定
        ]
        + SHorizontalBox::Slot()                    //サブコントロールスロットを追加
        [
            SNew(STextBlock)                        //テキストボックスを作成
            .Text_Lambda([](){                      //テキストボックスの内容を設定    
                return FText::FromString("Slate");
            })      
        ]
    ];
FSlateApplication::Get().AddWindow(Window, true);   //このウィンドウを登録し、即座に表示

    Slateのコードスタイルは以下の通りです。

    • Slate コントロールのクラス名は一般的に Sで始まります

    • 以下の関数でSlateコントロールを快速に構築できます。

      • SNew( WidgetType, ... )：汎用的な構築方式
      • SAssignNew( ExposeAs, WidgetType, ... )：構築完了後、コントロールをExposeAsに代入
      • SArgumentNew( InArgs, WidgetType, ... )：パラメータセットを使用して構築

    • 構築のコード式の中で、いくつかの関数でコントロールの構築パラメータを設定できます。これらの関数はいずれもコントロール自身の参照を返すため、チェーンコールが可能です。

      • operatpr . を通じて関数を呼び出し、コントロールのプロパティとイベントを設定できます
      • SPanel のサブクラスについては、operator +SPanelType::Slotを使用してサブコントロールのスロットを追加できます
      • SCompoundWidget と SPanel::Slot については、operator []を使用してサブコントロールを埋めることができます
      • Slateのプロパティとイベントについては、複数の方式でバインドできます。例えば上記の.Text(...)は静的な値を設定しますが、バインド関数を通じて動的にプロパティ値を取得することもできます。
        • Text_Lambda(...)
        • Text_Raw(...)
        • Text_Static(...)
        • Text_UObject(...)

    コントロール開発では、いくつかの経験（合理的であれば存在する）とIDEの補助に依存してコードを記述できます。

    SlateはGame UIとEditor UIの両方として使用できます。

    Editorでは、以下の方式でUIを追加できます。

    auto Window = SNew(SWindow)                         //トップレベルウィンドウが必須
    .Title(FText::FromString("CustomWindow"))       //ウィンドウタイトルを設定
    .ClientSize(FVector2D(600, 600))                //ウィンドウサイズを設定
    [                                               //ウィンドウ内容を埋める
        SNew(SSpacer)                               //自身のコントロール、ここは空白埋めです               
    ];

//方法1：このウィンドウを登録し、即座に表示
FSlateApplication::Get().AddWindow(Window, true);   

//方法2：このウィンドウを登録し、表示せず、手動でShowWindowを呼び出して表示
FSlateApplication::Get().AddWindow(Window, false);  //このウィンドウを登録し、即座に表示
Window->ShowWindow();

    DockTabの方式でウィンドウを追加することもできます。

    // Tabページの生成器を登録
FGlobalTabmanager::Get()->RegisterTabSpawner(FName("CustomTab"),FOnSpawnTab::CreateLambda([](const FSpawnTabArgs& Args){
    return SNew(SDockTab)
        [
            SNew(SSpacer)
        ];
}));
FGlobalTabmanager::Get()->TryInvokeTab(FTabId("CustomTab"));        //Tabページのアクティブを試行

    Gameでは、以下の方式でUIを追加できます。

    GEngine->GameViewport->AddViewportWidgetContent(
        SNew(SSpacer)
);

    GameViewportには他のインターフェースも利用可能です。

    class UGameViewportClient : public UScriptViewportClient, public FExec
{
    virtual void AddViewportWidgetContent( TSharedRef<class SWidget> ViewportContent, const int32 ZOrder = 0 );
    virtual void RemoveViewportWidgetContent( TSharedRef<class SWidget> ViewportContent );
    virtual void AddViewportWidgetForPlayer(ULocalPlayer* Player, TSharedRef<SWidget> ViewportContent, const int32 ZOrder);
    virtual void RemoveViewportWidgetForPlayer(ULocalPlayer* Player, TSharedRef<SWidget> ViewportContent);
    void RemoveAllViewportWidgets();
    void RebuildCursors();
};

    詳細は：https://docs.unrealengine.com/5.2/en-US/using-slate-in-game-in-unreal-engine/ を参照してください。

    基本概念¶

    UI開発には、以下の基礎概念を理解する必要があります。

    • ウィンドウの基本状態 ：アクティブ（Active）、フォーカス（Focus）、可視（Visible）、モーダル（Modal）、変換（Transform）
    • レイアウト戦略及び関連概念 ：
      • ボックスレイアウト（HBox、VBox）、フローレイアウト（Flow）、グリッドレイアウト（Grid）、アンカーレイアウト（Anchors）、オーバーラップレイアウト（Overlap）、キャンバス（Canvas）
      • パディング（Padding）、マージン（Margin）、スペーシング（Spacing）、アライメント方式（Alignment）
    • スタイル管理 ：アイコン（Icon）、スタイル（Style）、ブラシ（Brush）
    • フォント管理 ：フォントタイプ（Font Family）、テキスト幅測定(Font Measure)
    • サイズ計算 ：コントロールサイズ計算戦略
    • インタラクションイベント ：マウス、キーボード、ドラッグ、フォーカスイベント、イベント処理メカニズム、マウスキャプチャ
    • 描画イベント ：描画要素、領域クリッピング
    • 基本コントロール ：ラベル（Label）、ボタン（Button）、チェックボックス（Check）、コンボボックス（Combo）、スライダー（Slider）、スクロールバー（Scroll Bar）、テキストボックス（Text）、ダイアログ（Dialog）、カラーピッカー（Color）、メニューバー（Menu Bar）、メニュー（Menu）、ステータスバー（Status Bar）、スクロールパネル（Scroll ）、スタック（切り替え）パネル（Stack/Switcher）、リストパネル（List）、ツリーパネル（Tree）...
    • 国際化 ：テキストのローカライズ翻訳（Localization）

    また、UIフレームワークにどのようなグローバルデータと操作があるかを理解し、UEでは入力Get、Setを使用し、IDEの提示に従って簡単に確認できます。

    これも一定のコーディング規範に従うことでもたらされるメリットを体現しています。

    開発フロー¶

    Slate開発の大部分の作業内容は以下のようにまとめられます。

    • コントロールプロパティの設定
    • イベントロジックのバインド
    • 階層構造の組織

    SWidgetは抽象基底クラスであり、UEは異なる使用方式に応じて派生させ、4つのカテゴリに分類しています。

    • SCompoundWidget ：ChildSlotを設定できます

      Slateが開発者に提供する主な拡張方式で、一般的にこれを継承するのは既存のSWidgetを利用して一連のWidgetを組織するためです。

    • SPanel ：SWidgetのコンテナと看做せ、1つまたは複数のChildSlotを含み、SWidgetを追加するために使用されます。

      Slateはすでに十分な数のSPanelを派生させ、Slateのレイアウトなどの各種操作を組織するために使用しています。一般的には派生させることは少ないです。

    • SLeafWidget ：リーフコントロールで、ChildSlotを含みません

      これを派生させる主な目的は、独特な描画とサイズ処理メカニズムを持つコントロールをカスタマイズするためです。

    • SWeakWidget ：イベント上ではなく、論理的な帰属を定義します。

      SPanel内のSWidgetはイベント上で階層関係を持ちますが、ボタンをクリックしてメニューを開くなどの特殊な場合があります。メニューはこのボタンに属すると看做せますが、本質的には新しいウィンドウを開くため、イベント伝達上で階層関係は存在しません。そのためSWeakWidgetでこの問題を解決する必要があります。一般的には使用する機会は少ないです。

    ほとんどの場合、SCompoundWidget を継承するC++クラスを新規作成し、Construct関数でサブコントロールを埋めます。例えば以下のようになります。

    class SCustomWidget: public SCompoundWidget
{
public:
    SLATE_BEGIN_ARGS(SCustomWidget) {}              //Slateパラメータを定義
    SLATE_END_ARGS()
public:
    void Construct(const FArguments& InArgs){       //SNewを使用する本质はこの関数を呼び出すこと
        ChildSlot                                   //サブコントロールを埋める
        [
            SNew(STextBlock)
            .Text(FText::FromString("This is body"))
        ];
    }
};

    これで以下のコードでこのコントロールを作成できます。

    auto MyWidget = SNew(SCustomWidget);

    パラメータ（Argument） を追加したい場合、例えばテキスト内容を設定できるようにする場合は、定義を以下のように変更します。

    class SCustomWidget : public SCompoundWidget
{
public:
    SLATE_BEGIN_ARGS(SCustomWidget)                         
        : _Text(FText::FromString("Default")) {     //パラメータのデフォルト値を初期化、変数名はパラメータ定義時の変数名の前にアンダースコアを加えたもの
        }               
        SLATE_ARGUMENT(FText,Text)                  //マクロSLATE_ARGUMENTでパラメータを定義
    SLATE_END_ARGS()
public:
    void Construct(const FArguments& InArgs) {      
        Text = InArgs._Text;                        //渡されたパラメータを受け取る
        ChildSlot                                   
        [
            SNew(STextBlock)
            .Text(Text)                             //テキスト内容を渡す
        ];
    }
private:
    FText Text;
};

    これで以下のコードでコントロール内容を設定できます。

    auto MyWidget = SNew(SCustomWidget)
                    .Text(FText::FromString("Hello"));

    もちろん、FArgumentsの方式を使用せず、直接以下のようにすることもできます。

    class SCustomWidget : public SCompoundWidget
{
public:
    SLATE_BEGIN_ARGS(SCustomWidget){}               
    SLATE_END_ARGS()
public:
    void Construct(const FArguments& InArgs, FText InText) {    //直接Constructの関数パラメータから渡す
        Text = InText;                      
        ChildSlot                                   
        [
            SNew(STextBlock)
            .Text(Text)
        ];
    }
private:
    FText Text;
};

    auto MyWidget = SNew(SCustomWidget,FText::FromString("Hello"));   //SNewのパラメータリストからTextを渡す

    上記のパラメータをデリゲートにバインドできるようにしたい場合、Slateの 属性（Attribute） メカニズムを使用する必要があります。

    class SCustomWidget : public SCompoundWidget
{
public:
    SLATE_BEGIN_ARGS(SCustomWidget)                         
        : _Text(FText::FromString("Default")) {     
        }               
        SLATE_ATTRIBUTE(FText,Text)                         //マクロSLATE_ATTRIBUTEでパラメータを定義
    SLATE_END_ARGS()
public:
    void Construct(const FArguments& InArgs) {      
        Text = InArgs._Text;                                //渡されたパラメータを受け取る
        ChildSlot                                   
            [
                SNew(STextBlock)
                .Text(Text)                                 //テキスト属性を渡す
            ];
    }
private:
    TAttribute<FText> Text;                                 //TAttributeで属性をラップ
};

    そして以下のコードを使用できます。

    auto MyWidget = SNew(SCustomWidget)
        .Text_Lambda([](){
            return FText::FromString("Hello");
        });

    上記のテキストが変更されたときに処理を行うなど、コントロールのイベント処理コールバックを追加したい場合、Slateの イベント（Event） メカニズムを使用できます。

    class SCustomWidget : public SCompoundWidget
{
public:
    SLATE_BEGIN_ARGS(SCustomWidget)                         
        : _Text(FText::FromString("Default")) {     
        }               
        SLATE_ATTRIBUTE(FText,Text)                         
        SLATE_EVENT(FSimpleDelegate, OnTextChanged) //マクロSLATE_EVENTでイベントを宣言
    SLATE_END_ARGS()
public:
    void Construct(const FArguments& InArgs) {      
        Text = InArgs._Text;    
        OnTextChanged = InArgs._OnTextChanged;      //イベントデリゲートを渡す
        ChildSlot                                   
        [
            SNew(STextBlock)
            .Text(Text)
        ];
    }
    void SetText(FText InText) {
        Text = InText;
        OnTextChanged.ExecuteIfBound();             //デリゲートを実行
    }
    FText GetText(){
        return Text.Get();
    }
private:
    FSimpleDelegate OnTextChanged;                  //デリゲートを定義
    TAttribute<FText> Text;
};

    auto MyWidget = SNew(SCustomWidget)
    .Text_Lambda([](){
        return FText::FromString("Hello");
    })
    .OnTextChanged_Lambda([](){                     //テキストが変更されたときにログを出力
        UE_LOG(LogTemp,Warning,TEXT("Oh, Text is changed!"));
    });

    此外、SLATE_BEGIN_ARGS(...)とSLATE_END_ARGS()の間には他の使用可能なマクロも存在しますが、使用頻度は高くないため、ここでは展開しません。具体的には以下を参照してください。

    • Engine\Source\Runtime\SlateCore\Public\Widgets\DeclarativeSyntaxSupport.h

    以上、Slateの開発フローは基本的にこのようになります。

    コントロール一覧¶

    ここでは主に コントロール<--->タイプ のマッピングを確立し、どのコントロールが存在するかを知ることを目的としています。これらのコントロールを使用する際、UEソースコード内の大量の使用例を参考にできます。またUEは対応するデバッグツールも提供しています。

    基礎¶

    • SButton：ボタン

    • SCheckBox：チェックボックス

    コード参考¶

    UEは コントロールリフレクター を提供し、対応するUIの作成コードを快速に特定できます。その起動ポイントはエディターメインパネルのトップメニューバー - ツール - デバッグ - コントロールリフレクターにあります。

    また、公式のエンジンソースコードには SlateViewer プロジェクトが提供されており、大部分のSlateコントロールの基本的な使用方法が展示されています。

    IDEの コード検索ツール を利用して、エンジン内の対応するコントロールのパラメータ例を見つけることができます。Visual Studioではソリューションエクスプローラーでクラスの派生関係を表示し、すべてのコントロールを概観することもできます。

    高度なカスタマイズ¶

    上記のスキルでUI開発の大部分のニーズを満たすことができますが、複雑なインタラクションメカニズムや描画ロジックに関わる必要がある場合は、カスタムSLeafWidgetが必要になります。

    ここに優れた例があり、ドラッグして移動可能なコントロールを実装しています。

    コードは以下の通りです。

    #pragma once
#include "Styling/StyleColors.h"
#include "Brushes/SlateColorBrush.h"

class SCustomSlateWidget :public SLeafWidget {
    SLATE_DECLARE_WIDGET(SCustomSlateWidget, SLeafWidget)   //マクロSLATE_DECLARE_WIDGETでSlateコントロールを宣言
public:
    SLATE_BEGIN_ARGS(SCustomSlateWidget) {}
    SLATE_END_ARGS()
    void Construct(const SCustomSlateWidget::FArguments InArgs) {
        SetCursor(EMouseCursor::GrabHand);                  //マウスがコントロール領域に入ったときのスタイルを設定
    }
protected:
    FReply OnMouseButtonDown(const FGeometry& MyGeometry, const FPointerEvent& MouseEvent) override {
        if (MouseEvent.IsMouseButtonDown(EKeys::LeftMouseButton)) {
            LastMouseDownPosition = MyGeometry.AbsoluteToLocal(MouseEvent.GetScreenSpacePosition());//マウス位置をスクリーン空間からコントロールのローカル空間に変換
            return FReply::Handled().CaptureMouse(SharedThis(this));                                //グローバルなマウス移動の高頻度キャプチャを開始
        }
        return FReply::Handled();
    }
    FReply OnMouseMove(const FGeometry& MyGeometry, const FPointerEvent& MouseEvent) override{
        if (MouseEvent.IsMouseButtonDown(EKeys::LeftMouseButton)) {
            auto Window = FSlateApplication::Get().FindWidgetWindow(SharedThis(this));                  //このコントロールのウィンドウを取得
            auto CurrentMousePosition = MyGeometry.AbsoluteToLocal(MouseEvent.GetScreenSpacePosition());
            auto CurrWindowPosition = Window->GetPositionInScreen();
            auto TargetPosition = CurrentMousePosition + CurrWindowPosition - LastMouseDownPosition;    //位置移動を計算
            Window->MoveWindowTo(TargetPosition);
        }
        return FReply::Handled();
    }
    FReply OnMouseButtonUp(const FGeometry& MyGeometry, const FPointerEvent& MouseEvent) override {
        LastMouseDownPosition = FVector2D::ZeroVector;
        return FReply::Handled().ReleaseMouseCapture();                                         //マウスキャプチャを解放
    }
    int32 OnPaint(const FPaintArgs& Args, const FGeometry& AllottedGeometry, const FSlateRect& MyCullingRect, FSlateWindowElementList& OutDrawElements, int32 LayerId, const FWidgetStyle& InWidgetStyle, bool bParentEnabled) const override {
        static FSlateFontInfo FontInfo = FCoreStyle::GetDefaultFontStyle("Bold",30);
        static const FSlateBrush* Bursh = FAppStyle::GetBrush("WhiteBrush");
        FLinearColor BackgroundColor = IsHovered()? FLinearColor(0.6f, 0.5f, 0.9f) : FLinearColor(0.1f, 0.5f, 0.9f);
        FSlateDrawElement::MakeBox(OutDrawElements, LayerId, AllottedGeometry.ToPaintGeometry(), Bursh, ESlateDrawEffect::None, BackgroundColor);       //背景を描画
        FSlateDrawElement::MakeText(OutDrawElements, LayerId, AllottedGeometry.ToPaintGeometry(), FText::FromString("Hello Slate"), FontInfo);          //文字を描画
        return LayerId;
    }
    FVector2D ComputeDesiredSize(float LayoutScaleMultiplier) const override {
        return FVector2D::ZeroVector;                                                           // 零ベクトルを使用すると親コントロールの内容を埋める
    }
private:
    FVector2D LastMouseDownPosition = FVector2D::ZeroVector;
};

// 以下のコードはcppに配置する必要があります
SLATE_IMPLEMENT_WIDGET(SCustomSlateWidget)                          // マクロSLATE_IMPLEMENT_WIDGETでコード実装を生成
void SCustomSlateWidget::PrivateRegisterAttributes(FSlateAttributeInitializer& AttributeInitializer)    //この関数を実装する必要があります
{
}

    FSlateApplication::Get().AddWindow(
    SNew(SWindow)
    .ClientSize(FVector2D(200,200))                 //ウィンドウサイズを200*200に設定
    .SizingRule(ESizingRule::FixedSize)             //ウィンドウサイズを固定
    .SupportsMaximize(false)                        //最大化を無効
    .SupportsMinimize(false)                        //最小化を無効
    .CreateTitleBar(false)                          //タイトルバーを作成しない
    .AutoCenter(EAutoCenter::PreferredWorkArea)     //中央表示
    .IsTopmostWindow(true)                          //最前面表示
    [
        SNew(SCustomSlateWidget)
    ]
);

    カスタム SLeafWidget の作業フローは以下の通りです。

    • マクロ SLATE_DECLARE_WIDGET(WidgetType, ParentType) を使用してコントロールを宣言
    • マクロ SLATE_IMPLEMENT_WIDGET(WidgetType) を使用してcppでコード実装を定義し、以下の関数を実装します。
      • void WidgetType::PrivateRegisterAttributes(FSlateAttributeInitializer& AttributeInitializer)
    • コントロールサイズ計算の関数をオーバーライドします。
      • virtual FVector2D SWidget::ComputeDesiredSize(float LayoutScaleMultiplier) const = 0
    • 各種インタラクションイベントをオーバーライドします。
    • コントロールのプロパティステートマシンを調整します。
    • プロパティステートマシンに基づき、描画関数（OnPaint）で描画要素を追加します。

    インタラクションイベント¶

    SWidgetは非常に多くのインタラクションイベント（Onで始まる仮想関数）を提供し、開発者がオーバーライドできます。

    • OnFocusReceived：フォーカスを取得
    • OnFocusLost：フォーカスを失う
    • OnFocusChanging：フォーカスが変更される
    • OnKeyChar：キーボード入力時
    • OnKeyDown：キーボードキーが押された時
    • OnKeyUp：キーボードキーが離された時
    • OnMouseButtonDown：マウスボタンが押された時
    • OnMouseButtonUp：マウスボタンが離された時
    • OnMouseMove：マウスが移動した時
    • OnMouseEnter：マウスがWidget領域に入った瞬間
    • OnMouseLeave：マウスがWidget領域から離れた瞬間
    • OnMouseButtonDoubleClick：マウスダブルクリック
    • OnMouseWheel：マウスホイールがスクロールした時
    • OnDragEnter：何かをドラッグしてWidget領域に入った瞬間
    • OnDragLeave：何かをドラッグしてWidget領域から離れた瞬間
    • OnDragOver：何かをドラッグしてWidget領域を覆っている時
    • OnDrop：Widget上でドラッグしたものを解放した時
    • ...

    詳細な説明については、SWidgetの定義を参照してください。各イベントの説明とトリガータイミングが記載されています。用法についてはUEソースコード内の対応する使用例を検索できます。

    使用説明：

    • これらのイベントは FSlateApplication が呼び出しを担当し、その関数パラメータには一般的にこのイベントが携帯するすべての情報が含まれています。私たちはそれをオーバーライド（override）し、イベントデータに基づいて自身のロジックを実行するだけです。

    • イベントの戻り値の型は FReply で、イベントの後続処理を定義するために使用されます。そのコンストラクタはプライベートであるため、以下の静的関数を使用してインスタンスを作成する必要があります。

      • FReplay::Handled()：このイベントが処理されたことを示し、イベントは次のレベルに伝達されません。
      • FReplay::Unhandled()：このコントロールがこのイベントを処理しないことを示し、イベントは次のレベルに伝達されます。

      FReply はイベント終了時にいくつかの処理を行うための一連の操作を提供します。

    描画イベント¶

    SWidgetの実際の描画関数はPaintですが、描画プロセスにはいくつかの固定ステップが存在するため、Slateは描画イベントOnPaintを公開し、カスタム描画ロジックを可能にしています。その定義は以下の通りです。

    virtual int32 OnPaint(const FPaintArgs& Args, 
                      const FGeometry& AllottedGeometry,
                      const FSlateRect& MyCullingRect, 
                      FSlateWindowElementList& OutDrawElements, 
                      int32 LayerId,
                      const FWidgetStyle& InWidgetStyle,
                      bool bParentEnabled) const = 0;

    パラメータの説明：

    • const FPaintArgs& Args：描画イベントのパラメータ、描画の現在時間、間隔、親ウィンドウなどを取得できます。
    • const FGeometry& AllottedGeometry：このSWidgetに割り当てられた幾何学的なサイズ（親ウィンドウに対して）
    • const FSlateRect& MyCullingRect：このSWidgetのクリッピング矩形、描画中にこの矩形に基づいて描画要素を破棄できます。
    • FSlateWindowElementList& OutDrawElements：これは整个SWindowの描画要素リストで、描画はこのオブジェクトを変更することで行われます。
    • int32 LayerId：描画のLayerID、一般的にUIをレイヤー分けし、同じレイヤーの描画要素を統一的に処理するために使用されます。
    • const FWidgetStyle& InWidgetStyle：親ウィンドウから渡されたStyle
    • bool bParentEnabled：親ウィンドウが有効な状態かどうか。

    OnPaint関数では、主に FSlateDrawElement 内のMakeで始まる多くの静的関数を使用して描画要素を作成します。其中には以下のものがあります。

    static void MakeBox( //ボックスを描画、Brushを設定することで、カラーブロックまたは画像にできます
    FSlateWindowElementList& ElementList,
    uint32 InLayer,
    const FPaintGeometry& PaintGeometry,
    const FSlateBrush* InBrush,
    ESlateDrawEffect InDrawEffects = ESlateDrawEffect::None,
    const FLinearColor& InTint = FLinearColor::White );

static void MakeRotatedBox(...);        //回転したボックスを描画
static void MakeGradient(...);          //グラデーションのボックスを描画
static void MakeText(...);              //テキストを描画
static void MakeShapedText(...);        //形状テキストを描画
static void MakeLines(...);             //線を描画
static void MakeSpline(...)             //曲線を描画
static void MakeDrawSpaceSpline(...);    //描画空間で曲線を描画
static void MakeCubicBezierSpline(...);  //三次ベジェ曲線を描画
static void MakeViewport(...)           //FSlateViewportを描画
static void MakeCustom(...);            //カスタム要素を描画、要素のRender関数を自行実装可能
static void MakeCustomVerts(...);       //頂点に基づいて描画

    FSlateBrush¶

    FSlateBrush は領域の塗りつぶしを制御するために使用され、インターフェースでは使用頻度が高いため、Slateはいくつかの便利な拡張を提供しています。

    • FSlateBorderBrush ：ボーダーを塗りつぶす
    • FSlateBoxBrush ：ボックスブラシ
    • FSlateRoundedBoxBrush ：角丸矩形ブラシ
    • FSlateColorBrush ：カラーブラシ
    • FSlateImageBrush ：画像
      • FSlateVectorImageBrush ：ベクター画像
    • FSlateDynamicImageBrush ：動的に画像を切り替え可能なブラシ
    • FSlateNoResource ：リソースを持たないブラシ

    上記のいくつかのブラシは本质的に特定のパラメータで FSlateBrush を構築するものです。上記のブラシを組み合わせる必要がある場合、それらの構築パラメータに基づいて自行組み合わせることができます。

    UEにはいくつかの組み込みの FSlateBrush が提供されており、ソースコード内で::Get().GetBrushを検索して関連する使用例を見つけることができます。

    例¶

    整个SWidgetを赤色で塗りつぶしたい場合、以下のコードを使用できます。

    int32 SCustomSlateWidget::OnPaint(const FPaintArgs& Args,
                                  const FGeometry& AllottedGeometry,
                                  const FSlateRect& MyCullingRect,
                                  FSlateWindowElementList& OutDrawElements,
                                  int32 LayerId,
                                  const FWidgetStyle& InWidgetStyle,
                                  bool bParentEnabled) const {
    static FSlateColorBrush ColorBrush(FColor(255,0,0));
    FSlateDrawElement::MakeBox(OutDrawElements,
                               LayerId, 
                               AllottedGeometry.ToPaintGeometry(),
                               &ColorBrush,
                               ESlateDrawEffect::None, 
                               ColorBrush.TintColor.GetColor(InWidgetStyle));
    return LayerId;
}

    ESlateDrawEffect¶

    ESlateDrawEffect はSlateにいくつかの効果を提供し、以下の値を取ることができます。

    enum class ESlateDrawEffect : uint8
{
    None                    = 0,            //効果なし
    NoBlending          = 1 << 0,           //ブレンディングなし
    PreMultipliedAlpha  = 1 << 1,           //事前乗算Alpha
    NoGamma             = 1 << 2,           //Gamma補正なし
    InvertAlpha         = 1 << 3,           //透明度を反転
    // ^^ These Match ESlateBatchDrawFlag ^^

    NoPixelSnapping     = 1 << 4,           //ピクセルアライメントを無効
    DisabledEffect      = 1 << 5,           //無効状態の効果
    IgnoreTextureAlpha  = 1 << 6,           //テクスチャの透明度を無視

    ReverseGamma            = 1 << 7        //Gammaを逆転
};

    FSlateFontInfo¶

    FSlateFontInfo はフォント情報を指定するために使用され、UE内のフォントアセットに対応します。その部分的な定義は以下の通りです。

    struct SLATECORE_API FSlateFontInfo
{
    /**フォントオブジェクト（UMGまたはSlateウィジェットスタイルアセットから使用される場合に有効） */
    TObjectPtr<const UObject> FontObject;

    /**このフォントをレンダリングする際に使用するマテリアル */
    TObjectPtr<UObject> FontMaterial;

    /**フォントにアウトラインを適用するための設定 */
    FFontOutlineSettings OutlineSettings;

    /**使用する複合フォントデータ（C++のSlateスタイルセットで使用される場合に有効） */
    TSharedPtr<const FCompositeFont> CompositeFont;

    /**デフォルトのタイプフェイスから使用するフォントの名前（Noneの場合は最初のエントリを使用） */
    FName TypefaceFontName;

    /**
     * フォントサイズはポイント値で測定されます。ポイントからSlateユニットへの変換は96 dpiで行われます。
     * レイアウトやUIモックアップのプロトタイピングにPhotoshopなどのツールを使用する場合は、デフォルトのdpi測定値を72 dpiから96 dpiに変更してください。
     */
    int32 Size;

    /**テキスト内のすべての文字間の均一なスペーシング（トラッキング）。 */
    int32 LetterSpacing = 0;

    /**フォントフォールバックレベル。ランタイムのみ、共有されたFSlateFontInfoに設定しないでください。そうすると他の場所のフォントが変更される可能性があります（コピーを作成してください）。 */
    EFontFallback FontFallback;
};

    UEには専用のフォントエディターがあり、C++で直接構築するのは比較的面倒ですが、UEはいくつかの組み込みの FSlateFontInfo も提供しています。例えば：

    • FCoreStyle::Get().GetFontStyle("NormalFont")
    • FCoreStyle::Get().GetFontStyle("SmallFont")
    • FCoreStyle::GetDefaultFontStyle("Regular",FontSize);
    • FCoreStyle::GetDefaultFontStyle("Bold",FontSize)
    • FCoreStyle::GetDefaultFontStyle("Italic",FontSize);
    • FCoreStyle::GetDefaultFontStyle("Mono",FontSize);

    性能最適化¶

    SlateはUIのPaintとTick性能を最適化するため、SInvalidationPanel コントロールを提供しています。このコントロールは子コントロール内の消費の高い操作をキャッシュさせ、特定の操作によって キャッシュが無効（Invalidate） になった場合にのみ再実行されます。

    詳細は：Unreal Engine Slate アーキテクチャの理解 - ポーリングデータフローとデリゲート | Unreal Engine 5.2 ドキュメント を参照してください。

    手動で子コントロールのInvalidate()関数を呼び出してキャッシュを無効にすることができます。

    void SWidget::Invalidate(EInvalidateWidgetReason InvalidateReason);

    EInvalidateWidgetReason の値は以下の通りです。

    enum class EInvalidateWidgetReason : uint8
{
    None = 0,
    Layout = 1 << 0,        //Widgetの必要なサイズを変更する必要がある場合、レイアウトを無効にしてください。これは高コストな無効操作であるため、小さなウィジェットを再描画するだけの場合は使用しないでください。
    Paint = 1 << 1,             //描画を無効にする
    Volatility = 1 << 2,        //Volatilityが変動した時にトリガー
    ChildOrder = 1 << 3,        //自コントロールを追加または削除した時にトリガー、無効にするとChildの順序が再構築されます
    RenderTransform = 1 << 4,   //RenderTransformが変動した時にトリガー
    Visibility = 1 << 5,        //可視性が変動した時にトリガー
    AttributeRegistration = 1 << 6,     //属性をバインドした時にトリガー
    Prepass = 1 << 7,                   //Prepassを無効にする

    /**
     * 描画またはサイズに関連する通常のプロパティを変更する場合は、Paintの無効化を使用してください。
     * さらに、変更されたプロパティがVolatilityに影響を与える場合、Volatilityを無効にして再計算しキャッシュすることが重要です。
     */
    PaintAndVolatility = Paint | Volatility,
    /**
     * 描画またはサイズに関連する通常のプロパティを変更する場合は、Layoutの無効化を使用してください。
     * さらに、変更されたプロパティがVolatilityに影響を与える場合、Volatilityを無効にして再計算しキャッシュすることが重要です。
     */
    LayoutAndVolatility = Layout | Volatility,
};

    Slateは 属性（SlateAttribue） に基づく方式を提供し、属性の変動をキャッシュの再構築に関連付けています。

    具体的な方法は：

    • TSlateAttribute で属性をラップします（TAttribute の用途とは異なります）。TSlateAttribute でラップされた属性は、構築初期化時にパラメータ(*this)を渡す必要があります。

    • void WidgetType::PrivateRegisterAttributes(...)関数で、マクロ SLATE_ADD_MEMBER_ATTRIBUTE_DEFINITION(_Initializer, _Property, _Reason) を使用して属性を登録します。

    SlateからUMGへ¶

    UEのロジックプログラミングはUObject上に構築されていますが、Slateは極限のパフォーマンスを追求するため、UObjectのような重いメカニズムを使用してUIオブジェクトを管理していません。

    Slateでは**共有ポインタ（Shared Pointer）** の方式でUIオブジェクトのライフサイクルを管理しています。

    ゲーム開発者のUI開発効率を向上させるため、UEはUObjectを使用してSlateコントロールをラップし、リフレクションを通じてSlateコントロールの一部のプロパティと関数を公開すると同時に、視覚的なUIデザインをサポートしています。このレイヤーのインターフェースが、私たちがよく知る**UMG**です。

    **UMG**については、公式ドキュメントに詳細な説明があります：

    • https://docs.unrealengine.com/5.2/zh-CN/umg-ui-designer-for-unreal-engine/

    以下の簡潔なコードは、SlateとUMGの関係をよく示しています：

    #pragma once

#include "UObject/ObjectMacros.h"
#include "Widgets/Text/STextBlock.h"
#include "Components/Widget.h"
#include "CustomUWidget.generated.h"

UCLASS(meta = (DisplayName = "CustomWidget"))                   // DisplayNameはコントロール名
class UMGEXTENDUTILITIES_API UCustomWidget : public UWidget
{
    GENERATED_BODY()
protected:
    virtual TSharedRef<SWidget> RebuildWidget() override {                      // コントロールを再構築し、メンバー変数に代入する
        return SAssignNew(MyTextBlock,STextBlock);
    }
    virtual void SynchronizeProperties() override {                             // UObjectのプロパティをSlateコントロールに同期する
        MyTextBlock->SetText(Text);
        Super::SynchronizeProperties();
    }
    virtual void ReleaseSlateResources(bool bReleaseChildren) override {        // Slateリソースを解放する
        MyTextBlock.Reset();
    }

#if WITH_EDITOR
    virtual const FText GetPaletteCategory() override {                         // エディタ上のコントロールカテゴリ
        return FText::FromString("CustomCategory");
    }
#endif

public:
    UFUNCTION(BlueprintCallable)        // 関数をBlueprintに公開する
    FText GetText() const {
        return Text;
    }
    UFUNCTION(BlueprintCallable)
    void SetText(FText InText) {
        Text = InText;
        if (MyTextBlock) {              // プロパティを設定し、コントロールが既に作成されている場合は直接値をコントロールに設定する
            MyTextBlock->SetText(Text);
        }
    }
protected:
    UPROPERTY(EditAnywhere, BlueprintGetter = "GetText", BlueprintSetter = "SetText")
    FText Text;                         // プロパティをエディタに公開する

    TSharedPtr<STextBlock> MyTextBlock; // 実際のSlateコントロール
};

    ライフサイクル管理¶

    **UWidget**は**UObject**のガベージコレクション（GC）に従い、**SWidget**の共有ポインタを保持しています。コントロールが表示されている間（TSharedPtr<SWidget>が存在する間）、**UWidget**がGCされないようにするため、UMGは**FGCObject**を継承したコントロール**SObjectWidget**を使用して**UWidget**への参照を追加しています。

    上記のサンプルコードに戻ると、UWidget::TakeWidget()を呼び出して取得するのはUWidget::RebuildWidget()で作成されたコントロールではなく、それをさらに**SObjectWidget**でラップしたものであることがわかります。それらの作成過程における階層関係は以下の通りです：

    破棄時の解放順序は以下の通りです：

    • **SObjectWidget**は**FGCObject**を継承しており、UWidgetへの参照を追加することで、**SObjectWidget**が存在する間は**UWidget**がGCされないように保証します。
    • コントロールの破棄が開始されると、**SObjectWidget**の参照カウントが0になって破棄され、この時UWidgetへの参照が解除されます。
    • **UWidget**の参照が0になると、次回のGC時に解放され、この時初めて保持している**SWidget**の共有ポインタが解放されます。
