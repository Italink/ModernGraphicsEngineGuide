    1.Slate开发

    Slate is a UI framework provided in UE, with its core concepts as follows:

    • Slate Architecture | Unreal Engine 5.2 Documentation

    For some basic concepts of UI, you can refer to:

    • Introduction to Modern Graphics Engines (7) — GUI

    Basics¶

    To use Slate in UE, you need to understand three core structures:

    • FSlateApplication: A global singleton, serving as the scheduling center for all UIs.
    • SWindow: A top-level window that holds an instance of a cross-platform window (FGenericWindow) and provides window-related configurations and operations.
    • SWidget: A widget that divides the window area and handles interaction and drawing events within its own area.

    Basic Usage¶

    A simple Slate usage example in UE is as follows:

    auto Window = SNew(SWindow)                         // Create a window
    .ClientSize(FVector2D(600, 600))                // Set window size
    [                                               // Fill window content
        SNew(SHorizontalBox)                        // Create a horizontal box
        + SHorizontalBox::Slot()                    // Add a child widget slot
        [                                           
            SNew(STextBlock)                        // Create a text block
            .Text(FText::FromString("Hello"))       // Set text block content
        ]
        + SHorizontalBox::Slot()                    // Add a child widget slot
        [
            SNew(STextBlock)                        // Create a text block
            .Text_Lambda([](){                      // Set text block content   
                return FText::FromString("Slate");
            })      
        ]
    ];
FSlateApplication::Get().AddWindow(Window, true);   // Register the window and display it immediately

    The code style of Slate is as follows:

    • The class names of Slate widgets generally start with S
    • You can quickly construct Slate widgets through the following functions:
    • SNew(WidgetType, ...): A general construction method
    • SAssignNew(ExposeAs, WidgetType, ...): After construction, assign the widget to ExposeAs

    • SArgumentNew(InArgs, WidgetType, ...): Construct using a parameter set

    • In the construction code expression, you can set the widget's construction parameters through some functions. Since these functions all return a reference to the widget itself, you can perform chained calls:

    • You can call functions via operator . to set widget properties and events
    • For subclasses of SPanel, you can use operator +SPanelType::Slot to add child widget slots
    • For SCompoundWidget and SPanel::Slot, you can use operator [] to fill child widgets
    • For Slate properties and events, you can bind them in multiple ways. For example, .Text(...) sets a static value, and you can also dynamically obtain property values by binding functions:
      • Text_Lambda(...)
      • Text_Raw(...)
      • Text_Static(...)
      • Text_UObject(...)

    During widget development, we can rely on some experience (if it works, it's valid) and IDE assistance to complete code writing.

    Slate can be used as both Game UI and Editor UI.

    In the Editor, you can add UI in the following ways:

    auto Window = SNew(SWindow)                         // Must have a top-level window
    .Title(FText::FromString("CustomWindow"))       // Set window title
    .ClientSize(FVector2D(600, 600))                // Set window size
    [                                               // Fill window content
        SNew(SSpacer)                               // A self-contained widget, here it's a blank filler                
    ];

// Method 1: Register the window and display it immediately
FSlateApplication::Get().AddWindow(Window, true);   

// Method 2: Register the window without displaying it; manually call ShowWindow to display
FSlateApplication::Get().AddWindow(Window, false);  // Register the window and display it immediately
Window->ShowWindow();

    You can also add a window via the DockTab method:

    // Register the Tab page spawner
FGlobalTabmanager::Get()->RegisterTabSpawner(FName("CustomTab"), FOnSpawnTab::CreateLambda([](const FSpawnTabArgs& Args){
    return SNew(SDockTab)
        [
            SNew(SSpacer)
        ];
}));
FGlobalTabmanager::Get()->TryInvokeTab(FTabId("CustomTab"));        // Try to activate the Tab page

    In the Game, you can add UI in the following way:

    GEngine->GameViewport->AddViewportWidgetContent(
        SNew(SSpacer)
);

    Development Process¶

    Most of the work in Slate development can be summarized as:

    • Setting widget properties
    • Binding event logic
    • Organizing hierarchical structure

    SWidget is an abstract base class. UE further derives it into four main categories based on different usage methods:

    • SCompoundWidget: Can set ChildSlot

    The main extension method provided by Slate for developers. Generally, inheriting it is to use existing SWidgets to organize a series of widgets.

    • SPanel: Can be regarded as a container for SWidgets, which can contain one or more ChildSlots for adding SWidgets.

    Slate has derived enough SPanels for organizing Slate layouts and various operations. Generally, it is rarely derived.

    • SLeafWidget: Leaf widget, does not contain ChildSlot

    Deriving it is mainly to customize some widgets with unique rendering and size handling mechanisms.

    • SWeakWidget: Defines logical ownership rather than event ownership.

    The SWidgets in SPanel have a hierarchical relationship in terms of events, but sometimes special situations occur, such as clicking a button to open a menu. The menu can be regarded as belonging to this button, but essentially the menu opens a new window, and there is no hierarchical relationship in event passing. Therefore, SWeakWidget is needed to solve this problem. It is rarely used in general cases.

    Most of the time, we will add a new C++ class that inherits from SCompoundWidget, and fill the child widgets in the Construct function, like this:

    class SCustomWidget : public SCompoundWidget
{
public:
    SLATE_BEGIN_ARGS(SCustomWidget) {}              // Define Slate parameters
    SLATE_END_ARGS()
public:
    void Construct(const FArguments& InArgs) {      // Using SNew essentially calls this function
        ChildSlot                                   // Fill child widgets
        [
            SNew(STextBlock)
            .Text(FText::FromString("This is body"))
        ];
    }
};

    In this way, we can use the following code to create the widget:

    auto MyWidget = SNew(SCustomWidget);

    If you want to add arguments, for example, to make the text content configurable, you can change the definition to:

    class SCustomWidget : public SCompoundWidget
{
public:
    SLATE_BEGIN_ARGS(SCustomWidget)                         
        : _Text(FText::FromString("Default")) {     // Initialize the default value of the parameter; the variable name is the parameter name with an underscore prefix
        }               
        SLATE_ARGUMENT(FText, Text)                 // Define the parameter using the macro SLATE_ARGUMENT
    SLATE_END_ARGS()
public:
    void Construct(const FArguments& InArgs) {      
        Text = InArgs._Text;                        // Receive the passed parameter
        ChildSlot                                   
        [
            SNew(STextBlock)
            .Text(Text)                             // Pass the text content
        ];
    }
private:
    FText Text;
};

    In this way, you can use the following code to set the widget content:

    auto MyWidget = SNew(SCustomWidget)
                    .Text(FText::FromString("Hello"));

    Of course, we can also bypass the FArguments method and do it directly like this:

    class SCustomWidget : public SCompoundWidget
{
public:
    SLATE_BEGIN_ARGS(SCustomWidget) {}              
    SLATE_END_ARGS()
public:
    void Construct(const FArguments& InArgs, FText InText) {    // Pass directly from the function parameters of Construct
        Text = InText;                      
        ChildSlot                                   
        [
            SNew(STextBlock)
            .Text(Text)
        ];
    }
private:
    FText Text;
};

    auto MyWidget = SNew(SCustomWidget, FText::FromString("Hello"));      // Pass Text from the parameter list of SNew

    If you want to make the parameter able to bind a delegate, you need to use Slate's Attribute mechanism:

    class SCustomWidget : public SCompoundWidget
{
public:
    SLATE_BEGIN_ARGS(SCustomWidget)                         
        : _Text(FText::FromString("Default")) {     
        }               
        SLATE_ATTRIBUTE(FText, Text)                            // Define the parameter using the macro SLATE_ATTRIBUTE
    SLATE_END_ARGS()
public:
    void Construct(const FArguments& InArgs) {      
        Text = InArgs._Text;                                // Receive the passed parameter
        ChildSlot                                   
            [
                SNew(STextBlock)
                .Text(Text)                                 // Pass the text attribute
            ];
    }
private:
    TAttribute<FText> Text;                                 // Wrap the attribute with TAttribute
};

    Then you can use code like this:

    auto MyWidget = SNew(SCustomWidget)
        .Text_Lambda([](){
            return FText::FromString("Hello");
        });

    If you want to add some event handling callbacks for the widget, such as handling when the above text changes, you can use Slate's Event mechanism:

    class SCustomWidget : public SCompoundWidget
{
public:
    SLATE_BEGIN_ARGS(SCustomWidget)                         
        : _Text(FText::FromString("Default")) {     
        }               
        SLATE_ATTRIBUTE(FText, Text)                            
        SLATE_EVENT(FSimpleDelegate, OnTextChanged) // Declare the event using the macro SLATE_EVENT
    SLATE_END_ARGS()
public:
    void Construct(const FArguments& InArgs) {      
        Text = InArgs._Text;    
        OnTextChanged = InArgs._OnTextChanged;      // Pass the event delegate
        ChildSlot                                   
        [
            SNew(STextBlock)
            .Text(Text)
        ];
    }
    void SetText(FText InText) {
        Text = InText;
        OnTextChanged.ExecuteIfBound();             // Execute the delegate
    }
    FText GetText() {
        return Text.Get();
    }
private:
    FSimpleDelegate OnTextChanged;                  // Define the delegate
    TAttribute<FText> Text;
};

    auto MyWidget = SNew(SCustomWidget)
    .Text_Lambda([](){
        return FText::FromString("Hello");
    })
    .OnTextChanged_Lambda([](){                     // Print a log when the text changes
        UE_LOG(LogTemp, Warning, TEXT("Oh, Text is changed!"));
    });

    In addition, there are other macros available between SLATE_BEGIN_ARGS(...) and SLATE_END_ARGS(), which are not used frequently, so they are not expanded here. For details, you can check:

    • Engine\Source\Runtime\SlateCore\Public\Widgets\DeclarativeSyntaxSupport.h

    Advanced Customization¶

    The above skills can meet most needs of UI development, but when it comes to some complex interaction mechanisms and rendering logic, you need to customize SLeafWidget.

    Here is a good example that implements a draggable and movable widget:

    The code is as follows:

    #pragma once
#include "Styling/StyleColors.h"
#include "Brushes/SlateColorBrush.h"

class SCustomSlateWidget : public SLeafWidget {
    SLATE_DECLARE_WIDGET(SCustomSlateWidget, SLeafWidget)   // Declare the Slate widget using the macro SLATE_DECLARE_WIDGET
public:
    SLATE_BEGIN_ARGS(SCustomSlateWidget) {}
    SLATE_END_ARGS()
    void Construct(const SCustomSlateWidget::FArguments InArgs) {
        SetCursor(EMouseCursor::GrabHand);                  // Set the mouse style when entering the widget area
    }
protected:
    FReply OnMouseButtonDown(const FGeometry& MyGeometry, const FPointerEvent& MouseEvent) override {
        if (MouseEvent.IsMouseButtonDown(EKeys::LeftMouseButton)) {
            LastMouseDownPosition = MyGeometry.AbsoluteToLocal(MouseEvent.GetScreenSpacePosition());// Convert the mouse position from screen space to the widget's local space
            return FReply::Handled().CaptureMouse(SharedThis(this));                                // Start high-frequency capture of global mouse movement
        }
        return FReply::Handled();
    }
    FReply OnMouseMove(const FGeometry& MyGeometry, const FPointerEvent& MouseEvent) override {
        if (MouseEvent.IsMouseButtonDown(EKeys::LeftMouseButton)) {
            auto Window = FSlateApplication::Get().FindWidgetWindow(SharedThis(this));                  // Get the window of this widget
            auto CurrentMousePosition = MyGeometry.AbsoluteToLocal(MouseEvent.GetScreenSpacePosition());
            auto CurrWindowPosition = Window->GetPositionInScreen();
            auto TargetPosition = CurrentMousePosition + CurrWindowPosition - LastMouseDownPosition;    // Calculate position movement
            Window->MoveWindowTo(TargetPosition);
        }
        return FReply::Handled();
    }
    FReply OnMouseButtonUp(const FGeometry& MyGeometry, const FPointerEvent& MouseEvent) override {
        LastMouseDownPosition = FVector2D::ZeroVector;
        return FReply::Handled().ReleaseMouseCapture();                                         // Release mouse capture
    }
    int32 OnPaint(const FPaintArgs& Args, const FGeometry& AllottedGeometry, const FSlateRect& MyCullingRect, FSlateWindowElementList& OutDrawElements, int32 LayerId, const FWidgetStyle& InWidgetStyle, bool bParentEnabled) const override {
        static FSlateFontInfo FontInfo = FCoreStyle::GetDefaultFontStyle("Bold", 30);
        static const FSlateBrush* Brush = FAppStyle::GetBrush("WhiteBrush");
        FLinearColor BackgroundColor = IsHovered() ? FLinearColor(0.6f, 0.5f, 0.9f) : FLinearColor(0.1f, 0.5f, 0.9f);
        FSlateDrawElement::MakeBox(OutDrawElements, LayerId, AllottedGeometry.ToPaintGeometry(), Brush, ESlateDrawEffect::None, BackgroundColor);       // Draw background
        FSlateDrawElement::MakeText(OutDrawElements, LayerId, AllottedGeometry.ToPaintGeometry(), FText::FromString("Hello Slate"), FontInfo);          // Draw text
        return LayerId;
    }
    FVector2D ComputeDesiredSize(float LayoutScaleMultiplier) const override {
        return FVector2D::ZeroVector;                                                           // Using zero vector will fill the parent widget's content
    }
private:
    FVector2D LastMouseDownPosition = FVector2D::ZeroVector;
};

SLATE_IMPLEMENT_WIDGET(SCustomSlateWidget)                          // Generate code implementation using the macro SLATE_IMPLEMENT_WIDGET

{
}

    SNew(SWindow)
    .ClientSize(FVector2D(200, 200))                    // Set window size to 200*200
    .SizingRule(ESizingRule::FixedSize)             // Fixed window size
    .SupportsMaximize(false)                        // Disable maximize
    .SupportsMinimize(false)                        // Disable minimize
    .CreateTitleBar(false)                          // Do not create a title bar
    .AutoCenter(EAutoCenter::PreferredWorkArea)     // Display centered
    .IsTopmostWindow(true)                          // Keep on top
    [
        SNew(SCustomSlateWidget)

    The workflow for customizing SLeafWidget is:

    • Declare the widget using the macro SLATE_DECLARE_WIDGET(WidgetType, ParentType)
    • Define the code implementation in cpp using the macro SLATE_IMPLEMENT_WIDGET(WidgetType), and implement the function:
    • void WidgetType::PrivateRegisterAttributes(FSlateAttributeInitializer& AttributeInitializer)
    • Override the function for widget size calculation:
    • virtual FVector2D SWidget::ComputeDesiredSize(float LayoutScaleMultiplier) const = 0
    • Override various interaction events.
    • Adjust the widget's attribute state machine
    • Add drawing elements in the drawing function (OnPaint) according to the attribute state machine

    Interaction Events¶

    SWidget provides a large number of interaction events (virtual functions starting with On) for developers to override:

    • OnFocusReceived: Gain focus
    • OnFocusLost: Lose focus
    • OnFocusChanging: Focus changes
    • OnKeyChar: When keyboard input occurs
    • OnKeyDown: Keyboard key pressed
    • OnKeyUp: Keyboard key released
    • OnMouseButtonDown: Mouse button pressed
    • OnMouseButtonUp: Mouse button released
    • OnMouseMove: Mouse moves
    • OnMouseEnter: The moment the mouse enters the Widget area
    • OnMouseLeave: The moment the mouse leaves the Widget area
    • OnMouseButtonDoubleClick: Mouse double-click
    • OnMouseWheel: Mouse wheel scrolls
    • OnDragEnter: The moment something is dragged into the Widget area
    • OnDragLeave: The moment something is dragged out of the Widget area
    • OnDragOver: When something is dragged over the Widget area
    • OnDrop: Release the dragged item on the Widget
    • ...

    For detailed descriptions, see the definition of SWidget, which has explanations and trigger timings for each event. For usage, you can search for corresponding use cases in the UE source code.

    Usage instructions:

    • These events are called by FSlateApplication. Their function parameters generally contain all the information carried by the event. We only need to override them and implement our own logic based on the event data.

    • The return type of the event is FReply, which is used to define the subsequent processing of the event. Its constructor is private, so you must use the following static functions to create an instance:

      • FReply::Handled(): Indicates that the event has been processed, and the event will not continue to be passed down.
      • FReply::Unhandled(): Indicates that the widget does not handle the event, and the event will continue to be passed down.

    Drawing Events¶

    The actual drawing function of SWidget is Paint, but since there are some fixed steps in the drawing process, Slate exposes the drawing event OnPaint for us to customize the drawing logic. Its definition is as follows:

    virtual int32 OnPaint(const FPaintArgs& Args, 
                      const FGeometry& AllottedGeometry,
                      const FSlateRect& MyCullingRect, 
                      FSlateWindowElementList& OutDrawElements, 
                      int32 LayerId,
                      const FWidgetStyle& InWidgetStyle,
                      bool bParentEnabled) const = 0;

    Parameter description:

    • const FPaintArgs& Args: Parameters of the drawing event, which can get the current time, interval, parent window...
    • const FGeometry& AllottedGeometry: The geometric size allocated to the SWidget (relative to the parent window)
    • const FSlateRect& MyCullingRect: The culling rectangle of the SWidget, which can be used to discard drawing elements during drawing
    • FSlateWindowElementList& OutDrawElements: This is the drawing element list of the entire SWindow. Our drawing is to modify this object.
    • int32 LayerId: The LayerID for drawing, generally used to layer the UI for unified processing of drawing elements at the same level.
    • const FWidgetStyle& InWidgetStyle: The Style passed from the parent window
    • bool bParentEnabled: Whether the parent window is in the enabled state.

    In the OnPaint function, we mainly create drawing elements through many static functions named starting with Make in FSlateDrawElement, including:

    Example¶

    If you want to fill the entire SWidget with red, you can use code like this:

    int32 SCustomSlateWidget::OnPaint(const FPaintArgs& Args,
                                  const FGeometry& AllottedGeometry,
                                  const FSlateRect& MyCullingRect,
                                  FSlateWindowElementList& OutDrawElements,
                                  int32 LayerId,
                                  const FWidgetStyle& InWidgetStyle,

    Performance Optimization¶

    To optimize the Paint and Tick performance of the UI, Slate provides an SInvalidationPanel widget, which allows caching of high-consumption operations in child widgets. Only when some specific operations cause cache invalidation (Invalidate), will they be re-executed.

    For details: Understanding the Slate UI Architecture in Unreal Engine - Polling Data Flows and Delegates | Unreal Engine 5.2 Documentation

    We can manually call the Invalidate() function of the child widget to invalidate the cache:

    void SWidget::Invalidate(EInvalidateWidgetReason InvalidateReason);

    The values of EInvalidateWidgetReason can be:

    enum class EInvalidateWidgetReason : uint8
{
    None = 0,
    Layout = 1 << 0,        // If you need to change the size required by the Widget, invalidate the layout. This is an expensive invalidation operation, so don't use it if you only need to repaint a widget
    Paint = 1 << 1,             // Invalidate painting
    Volatility = 1 << 2,        // Triggered when Volatility changes
    ChildOrder = 1 << 3,        // Triggered when adding or removing child widgets; invalidating it will rebuild the order of Children
    RenderTransform = 1 << 4,   // Triggered when RenderTransform changes
    Visibility = 1 << 5,        // Triggered when visibility changes
    AttributeRegistration = 1 << 6,     // Triggered when binding attributes
    Prepass = 1 << 7,                   // Invalidate Prepass

    /**
     * Use Paint invalidation if you're changing a normal property involving painting or sizing.
     * Additionally if the property that was changed affects Volatility in anyway, it's important
     * that you invalidate volatility so that it can be recalculated and cached.
     */
    PaintAndVolatility = Paint | Volatility,
    /**
     * Use Layout invalidation if you're changing a normal property involving painting or sizing.
     * Additionally if the property that was changed affects Volatility in anyway, it's important
     * that you invalidate volatility so that it can be recalculated and cached.
     */
    LayoutAndVolatility = Layout | Volatility,
};

    Slate provides a method based on attributes (SlateAttribute): linking changes in attributes to cache reconstruction.

    The specific approach is:

    • Wrap the attribute with TSlateAttribute (different from the purpose of TAttribute). The attribute wrapped by TSlateAttribute needs to pass the parameter (*this) during construction initialization.

    • In the function void WidgetType::PrivateRegisterAttributes(...), use the macro SLATE_ADD_MEMBER_ATTRIBUTE_DEFINITION(_Initializer, _Property, _Reason) to register the attribute.

    From Slate to UMG¶

    UE's logic programming is built on UObject, but Slate doesn't use the heavy UObject mechanism to manage UI objects in pursuit of extreme performance.

    In Slate, Shared Pointers are used to manage the lifecycle of UI objects.

    To improve UI development efficiency for game developers, UE wraps Slate widgets with UObject, exposes some properties and functions of Slate widgets through reflection, and supports visual UI design. This layer of interface is what we know as UMG.

    For details about UMG, refer to the official documentation:

    • https://docs.unrealengine.com/5.2/zh-CN/umg-ui-designer-for-unreal-engine/

    The following short code snippet well illustrates the relationship between Slate and UMG:

    #pragma once

#include "UObject/ObjectMacros.h"
#include "Widgets/Text/STextBlock.h"
#include "Components/Widget.h"
#include "CustomUWidget.generated.h"

UCLASS(meta = (DisplayName = "CustomWidget"))                   // DisplayName is the widget name
class UMGEXTENDUTILITIES_API UCustomWidget : public UWidget
{
    GENERATED_BODY()
protected:
    virtual TSharedRef<SWidget> RebuildWidget() override {                      // Rebuild the widget and assign it to the member variable
        return SAssignNew(MyTextBlock, STextBlock);
    }
    virtual void SynchronizeProperties() override {                             // Synchronize UObject properties to the Slate widget
        MyTextBlock->SetText(Text);
        Super::SynchronizeProperties();
    }
    virtual void ReleaseSlateResources(bool bReleaseChildren) override {        // Release Slate resources
        MyTextBlock.Reset();
    }

#if WITH_EDITOR
    virtual const FText GetPaletteCategory() override {                         // Widget category in the editor
        return FText::FromString("CustomCategory");
    }
#endif

public:
    UFUNCTION(BlueprintCallable)        // Expose the function to Blueprints
    FText GetText() const {
        return Text;
    }
    UFUNCTION(BlueprintCallable)
    void SetText(FText InText) {
        Text = InText;
        if (MyTextBlock) {              // Set the property; if the widget is already created, directly pass the value to the widget
            MyTextBlock->SetText(Text);
        }
    }
protected:
    UPROPERTY(EditAnywhere, BlueprintGetter = "GetText", BlueprintSetter = "SetText")
    FText Text;                         // Expose the property to the editor

    TSharedPtr<STextBlock> MyTextBlock; // Actual Slate widget
};

    In C++, the way to use UMG is:

    UWidget* UMGWidget = LoadObject<UWidget>(nullptr, TEXT("{AssetPath}"));                // Load from asset, or use NewObject
TSharedPtr<SWidget> SlateWidget = UMGWidget->TakeWidget();                             // This creates a new SWidget
TSharedPtr<SWidget> CachedSlateWidget = UMGWidget->GetCachedWidget();                  // Get the previously created SWidget
// Then use the Slate usage method

    Lifecycle Management¶

    UWidget uses UObject's garbage collection. It holds a shared pointer to the SWidget. To ensure that the UWidget isn't garbage-collected while the widget is displayed (when the TSharedPtr<SWidget> still exists), UMG uses a widget SObjectWidget that inherits from FGCObject to add a reference to the UWidget.

    Going back to the example code above, we can see that the widget obtained by calling UWidget::TakeWidget() isn't the one created in UWidget::RebuildWidget(), but is wrapped an extra layer with SObjectWidget. Their hierarchical relationship during creation is as follows:

    During destruction, their release order is as follows:

    • SObjectWidget inherits from FGCObject and adds a reference to the UWidget, ensuring the UWidget isn't GC'd while the SObjectWidget exists.
    • When the widget starts to be destroyed, the SObjectWidget's reference count becomes 0 and it's destroyed, which then releases the reference to the UWidget.
    • When the UWidget's reference count becomes 0, it's released in the next garbage collection, and only then is the shared pointer to the SWidget it holds released.
