    Graphics API Overview¶

    Before starting to learn, you need to clearly recognize that C/C++ is just a tool for materializing practical theories in computers, and you must be proficient in using it. Otherwise, you should continue to study in depth. The author believes that without building a complete basic knowledge system and good code literacy, you are not capable or even qualified to further your learning.

    Defining this is quite difficult. You can think of it like playing Spider Solitaire. It's best to ask for a new deal only when you feel there's no way out, because entering a new field will provide some entry points but also face greater challenges, or even lead you into a dead end.

    In addition, you need to consider whether it is necessary to learn it. If your future career direction is:

    • Game engines, graphics
    • VR, AR, XR
    • 3D industrial software
    • Audio and video
    • Graphics drivers

    Then learning low-level graphics APIs is a necessary path. But if you focus more on the artistic effects and fun presented by graphics, directly starting with game engines and 3D processing software will be a better beginning.

    Rasterization¶

    What is a graphic?

    Triangles, rectangles, circles, cup-like shapes... If we have to consider so many things, computers will have countless rules to define. Therefore, simplification is needed: use the smallest basic units to include all graphics in nature, and computers only need to handle the rendering of these basic units. These basic units (primitives) are:

    • Point
    • Line
    • Triangle

    They can be described using the following data structures:

    struct Point {
    int x, y;
};

struct Line {
    std::array<Point, 2> points;
};

struct Triangle {
    std::array<Point, 3> vertices;
};

    If you want to draw a point on the FrameBuffer, it's very simple:

    void drawPoint(std::vector<std::vector<char>>& frameBuffer, const Point& point) {
    frameBuffer[point.x][point.y] = '1';
}

    What if you want to draw a line on the FrameBuffer?

    A line consists of a series of points, but note that there are countless points on a line, while the points on the FrameBuffer are limited. Therefore, some precision will be lost during drawing, and we only need to calculate the coordinates of the corresponding points according to the precision. This process is exactly rasterization (Rasterisation).

    A line can be represented by the slope-intercept equation: y = kx + b.

    The values of k and b can be solved according to the coordinates of two points. If the precision is set to 1, it is easy to calculate other points between the endpoints. However, note that the slope-intercept form cannot represent lines perpendicular to the x-axis, so we have to avoid calculating the slope. This method is DDA (Digital differential analyzer). A simple implementation is as follows:

    void drawLine(std::vector<std::vector<char>>& frameBuffer, Line line) {
    int dx = line.points[1].x - line.points[0].x;
    int dy = line.points[1].y - line.points[0].y;

    if (dx == 0 && dy == 0) {            // Endpoints overlap, draw point directly
        drawPoint(frameBuffer, line.points[0]);
    }

    float steps = abs(dx) > abs(dy) ? abs(dx) : abs(dy);

    float xInc = dx / (float)steps;     // X increment
    float yInc = dy / (float)steps;     // Y increment

    float x = line.points[0].x;         // X starting value
    float y = line.points[0].y;         // Y starting value

    for (int i = 0; i <= steps; i++) {
        drawPoint(frameBuffer, Point(round(x), round(y)));
        x += xInc;
        y += yInc;
    }
}

    In addition, there are other line rasterization algorithms, which will not be introduced one by one here:

    • Bresenham's line algorithm
    • Xiaolin Wu's line algorithm

    Test it in renderFrame:

    void renderFrame(std::vector<std::vector<char>>& frameBuffer) {
    std::vector<Line> lines = {
        {0,0,39,0},
        {0,0,39,19}
    };

    for (const auto& line : lines) {
        drawLine(frameBuffer, line);
    }
}

    The rasterization of triangles is relatively more complex. Here are several algorithms:

    • Division method
    • Bresenham's algorithm
    • Barycentric algorithm

    Among them, the division method is more common. Its core idea is simple: divide a triangle into two triangles whose bases are parallel to the X-axis, then fill lines step by step in the vertical direction:

    For detailed ideas, please read:

    • http://www.sunshine2k.de/coding/java/TriangleRasterization/TriangleRasterization.html

    Here is a simple implementation:

    void drawTriangle(std::vector<std::vector<char>>& frameBuffer, Triangle triangle) {
    std::sort(triangle.vertices.begin(), triangle.vertices.end(), [](const Point& a, const Point& b) {
        return a.y < b.y;
    });
    if (triangle.vertices[0] == triangle.vertices[1]    // Do not draw if vertices overlap
        || triangle.vertices[1] == triangle.vertices[2]
        || triangle.vertices[0] == triangle.vertices[2]
        )
        return;

    auto fillBottomFlatTriangle = [&](const Point& v1, const Point& v2, const Point& v3) {
        float invslope1 = (v2.x - v1.x) / (v2.y - v1.y);
        float invslope2 = (v3.x - v1.x) / (v3.y - v1.y);

        float curx1 = v1.x;
        float curx2 = v1.x;

        for (int scanlineY = v1.y; scanlineY <= v2.y; scanlineY++) {
            Line scanLine = {
             (int)curx1, scanlineY ,
             (int)curx2, scanlineY 
            };
            drawLine(frameBuffer, scanLine);
            curx1 += invslope1;
            curx2 += invslope2;
        }
    };

    auto fillTopFlatTriangle = [&](const Point& v1, const Point& v2, const Point& v3) {
        float invslope1 = (v3.x - v1.x) / (float)(v3.y - v1.y);
        float invslope2 = (v3.x - v2.x) / (float)(v3.y - v2.y);

        float curx1 = v3.x;
        float curx2 = v3.x;

        for (int scanlineY = v3.y; scanlineY > v1.y; scanlineY--) {
            Line scanLine = {
             (int)curx1, scanlineY ,
             (int)curx2, scanlineY
            };
            drawLine(frameBuffer, scanLine);
            curx1 -= invslope1;
            curx2 -= invslope2;
        }
    };
    if (triangle.vertices[1].y == triangle.vertices[2].y) {
        fillBottomFlatTriangle(triangle.vertices[0], triangle.vertices[1], triangle.vertices[2]);
    }
    else if (triangle.vertices[0].y == triangle.vertices[1].y) {
        fillTopFlatTriangle(triangle.vertices[0], triangle.vertices[1], triangle.vertices[2]);
    }
    else {
        Point mid = Point({
            (int)(triangle.vertices[0].x + ((float)(triangle.vertices[1].y - triangle.vertices[0].y) / (float)(triangle.vertices[2].y - triangle.vertices[0].y)) * (triangle.vertices[2].x - triangle.vertices[0].x))
            , triangle.vertices[1].y
        });
        fillBottomFlatTriangle(triangle.vertices[0], triangle.vertices[1], mid);
        fillTopFlatTriangle(triangle.vertices[1], mid, triangle.vertices[2]);
    }
}

    Processing Pipeline¶

    In computers, besides representing simple, static geometric graphics, sometimes it is necessary to draw some dynamic, processed graphic effects. This requires:

    • Being able to process each vertex, such as moving, rotating relative to the coordinate origin, scaling, etc.
    • Being able to perform additional processing on the pixels on the FrameBuffer, such as coloring, adding various filters, etc.

    Combined with the SwapChain from the previous section, you can implement such a small program:

    In the above image, the size of the triangle is dynamically scaled and a * border is added to it. The complete code is as follows:

    #include <iostream>
#include <vector>
#include <algorithm>
#include <functional>
#include <array>
#include <Windows.h>

double GTime = 0;

struct Point {
    int x, y;
    bool operator == (const Point& other) { return x == other.x && y == other.y; }
};

struct Line {
    std::array<Point, 2> points;
};

struct Triangle {
    std::array<Point, 3> vertices;
};

void drawPoint(std::vector<std::vector<char>>& frameBuffer, const Point& point) {
    frameBuffer[point.x][point.y] = '1';
}

void drawLine(std::vector<std::vector<char>>& frameBuffer, Line line) {
    int dx = line.points[1].x - line.points[0].x;
    int dy = line.points[1].y - line.points[0].y;

    if (dx == 0 && dy == 0) {            // Endpoints overlap, draw point directly
        drawPoint(frameBuffer, line.points[0]);
    }

    float steps = abs(dx) > abs(dy) ? abs(dx) : abs(dy);

    float xInc = dx / (float)steps;     // X increment
    float yInc = dy / (float)steps;     // Y increment

    float x = line.points[0].x;         // X starting value
    float y = line.points[0].y;         // Y starting value

    for (int i = 0; i <= steps; i++) {
        drawPoint(frameBuffer, Point(round(x), round(y)));
        x += xInc;
        y += yInc;
    }
}

void drawTriangle(std::vector<std::vector<char>>& frameBuffer, Triangle triangle) {
    std::sort(triangle.vertices.begin(), triangle.vertices.end(), [](const Point& a, const Point& b) {
        return a.y < b.y;
    });
    if (triangle.vertices[0] == triangle.vertices[1]    // Do not draw if vertices overlap, temporarily ignore collinear cases
        || triangle.vertices[1] == triangle.vertices[2]
        || triangle.vertices[0] == triangle.vertices[2]
        )
        return;

    auto fillBottomFlatTriangle = [&](const Point& v1, const Point& v2, const Point& v3) {
        float invslope1 = (v2.x - v1.x) / (v2.y - v1.y);
        float invslope2 = (v3.x - v1.x) / (v3.y - v1.y);

        float curx1 = v1.x;
        float curx2 = v1.x;

        for (int scanlineY = v1.y; scanlineY <= v2.y; scanlineY++) {
            Line scanLine = {
             (int)curx1, scanlineY ,
             (int)curx2, scanlineY 
            };
            drawLine(frameBuffer, scanLine);
            curx1 += invslope1;
            curx2 += invslope2;
        }
    };

    auto fillTopFlatTriangle = [&](const Point& v1, const Point& v2, const Point& v3) {
        float invslope1 = (v3.x - v1.x) / (float)(v3.y - v1.y);
        float invslope2 = (v3.x - v2.x) / (float)(v3.y - v2.y);

        float curx1 = v3.x;
        float curx2 = v3.x;

        for (int scanlineY = v3.y; scanlineY > v1.y; scanlineY--) {
            Line scanLine = {
             (int)curx1, scanlineY ,
             (int)curx2, scanlineY
            };
            drawLine(frameBuffer, scanLine);
            curx1 -= invslope1;
            curx2 -= invslope2;
        }
    };
    if (triangle.vertices[1].y == triangle.vertices[2].y) {
        fillBottomFlatTriangle(triangle.vertices[0], triangle.vertices[1], triangle.vertices[2]);
    }
    else if (triangle.vertices[0].y == triangle.vertices[1].y) {
        fillTopFlatTriangle(triangle.vertices[0], triangle.vertices[1], triangle.vertices[2]);
    }
    else {
        Point mid = Point({
            (int)(triangle.vertices[0].x + ((float)(triangle.vertices[1].y - triangle.vertices[0].y) / (float)(triangle.vertices[2].y - triangle.vertices[0].y)) * (triangle.vertices[2].x - triangle.vertices[0].x))
            , triangle.vertices[1].y
        });
        fillBottomFlatTriangle(triangle.vertices[0], triangle.vertices[1], mid);
        fillTopFlatTriangle(triangle.vertices[1], mid, triangle.vertices[2]);
    }
}

/* Per-vertex processing
* Dynamically scale vertex positions based on time
*/
Point processVertex(const Point& point) {
    Point newPoint = point;
    double scaleFactor = 0.5 + 0.4 * std::sin(GTime);        // Ensure scale factor is within [0.1, 0.9]
    newPoint.x *= scaleFactor;
    newPoint.y *= scaleFactor;
    return newPoint;
}

/* Per-pixel processing
* Simple edge outlining
*/
char processPixel(const std::vector<std::vector<char>>& frameBuffer, int x, int y) {
    static int direction[4][2] = { {0,1},{0,-1},{1,0},{-1,0} };    // Four directions
    for (int i = 0; i < 4; i++) {
        int xOff = x + direction[i][0];
        int yOff = y + direction[i][1];
        if (xOff >= 0                                            // Check if within frame boundaries, current pixel is '0' and surrounding pixel has '1'
            && xOff < frameBuffer.size()
            && yOff >= 0 
            && yOff < frameBuffer[0].size()
            && frameBuffer[x][y] == '0'
            && frameBuffer[xOff][yOff] == '1') {
            return '*';
        }
    }
    return frameBuffer[x][y];
}

void renderFrame(std::vector<std::vector<char>>& frameBuffer) {
    std::vector<Triangle> triangles = { 
        {0,0,40,0,20,19},
    };

    /* Vertex processing */
    for (auto& triangle : triangles) {
        for (auto& vertex : triangle.vertices) {
            vertex = processVertex(vertex);
        }
    }

    for (const auto& triangle : triangles) {
        drawTriangle(frameBuffer, triangle);
    }

    /* Pixel processing */
    std::vector<std::vector<char>> newFrameBuffer(frameBuffer);
    for (int x = 0; x < frameBuffer.size(); x++) {
        for (int y = 0; y < frameBuffer[x].size(); y++) {
            newFrameBuffer[x][y] = processPixel(frameBuffer, x, y);
        }
    }
    frameBuffer = newFrameBuffer;
}

int main() {
    HANDLE frontendBuffer = GetStdHandle(STD_OUTPUT_HANDLE);        // Get default buffer
    HANDLE backendBuffer = CreateConsoleScreenBuffer(               // Create a new buffer as the backend buffer
        GENERIC_READ | GENERIC_WRITE,
        FILE_SHARE_READ | FILE_SHARE_WRITE,
        NULL,
        CONSOLE_TEXTMODE_BUFFER,
        NULL
    );
    // Hide cursors of both buffers
    CONSOLE_CURSOR_INFO cci;
    cci.bVisible = 0;
    cci.dwSize = 1;
    SetConsoleCursorInfo(frontendBuffer, &cci);
    SetConsoleCursorInfo(backendBuffer, &cci);

    const int width = 40;
    const int height = 20;
    const char clearCh = '0';
    const int MaxBufferSize = width * height * 10;

    char bufferData[MaxBufferSize];     // Temporary buffer for cached data
    DWORD bufferLength = 0;
    COORD zeroCoord = { 0,0 };
    while (true) {
        GTime += 0.01;
        bufferLength = 0;
        CONSOLE_SCREEN_BUFFER_INFO backendBufferInfo;      
        GetConsoleScreenBufferInfo(backendBuffer, &backendBufferInfo);
        int lineWidth = backendBufferInfo.srWindow.Right - backendBufferInfo.srWindow.Left + 1;

        std::vector<std::vector<char>> frameBuffer(width, std::vector<char>(height, clearCh));
        renderFrame(frameBuffer);

        for (int y = 0; y < height; y++) {
            for (int x = 0; x < width; x++) {
                bufferData[bufferLength++] = frameBuffer[x][y];
            }
            while (bufferLength % lineWidth != 0) {             // Fill characters to achieve line break effect
                bufferData[bufferLength++] = ' ';
            }
        }

        WriteConsoleOutputCharacterA(backendBuffer, bufferData, bufferLength, zeroCoord, &bufferLength);
        SetConsoleActiveScreenBuffer(backendBuffer);           
        std::swap(backendBuffer, frontendBuffer);              
    }
    return 0;
}

    Now we have the theory of drawing, but in computers, we also need to consider performance, because this determines the upper limit of the number of triangles that can be drawn within a certain time range.

    • The processing of vertices, the processing of pixels, and the drawing of primitives do not affect each other, which means these operations can be parallelized

    Modern GPUs are very efficient at manipulating computer graphics and image processing. For algorithms that process large blocks of data in parallel, their parallel structure makes them more efficient than general-purpose Central Processing Units (CPUs).

    Graphics APIs¶

    Graphics APIs provide an abstract way to access GPU hardware, simplifying various stages of computer graphics generation so that developers do not need to understand hardware details deeply and can focus on building graphics.

    It can be done purely in software and run on the CPU, which is common in embedded systems, or hardware-accelerated by the GPU, which is more common in PCs and mainly used in video games and simulations.

    The current mainstream 3D graphics APIs are:

    • DX11, DX12: 3D graphics programming interfaces developed by Microsoft for Windows systems
    • OpenGL: OpenGL is a cross-language, cross-platform API. Its implementations exist in Windows, some UNIX systems, and Mac OS. These implementations are generally provided by graphics card manufacturers and are highly dependent on the hardware provided by the manufacturer.
    • Vulkan: The next generation of OpenGL. In comparison, Vulkan is closer to the hardware and can well allocate CPU cores to perform parallel tasks.
    • Metal: The Metal API is provided by Apple. It aims to provide low-level access to GPU hardware for applications on iOS, iPadOS, macOS, and tvOS to improve performance. It belongs to low-level APIs like Vulkan and DX12.

    I believe many friends' first reaction when seeing them is:

    • Among these APIs, which one is the strongest? Which one should I learn?

    Everyone has their own opinions on this issue, such as:

    • Zhihu: What are the advantages and disadvantages of Vulkan compared to OpenGL, DX12, Metal, and Mantle?

    As someone who has been through this, the author's view is:

    • Don't expect to learn any one of these APIs and then be able to sit back and relax. In actual work development, you will at least come into contact with two or more of the above APIs, and it is more likely that you will develop on the upper-layer interfaces of these APIs.

    Most game engines encapsulate these graphics APIs into a unified interface, which can be switched on different platforms to pursue better graphics performance. We generally call this set of interfaces RHI (Rendering Hardware Interface).

    Although OpenGL and Vulkan support most platforms, they are not perfect. In addition, Apple requires the use of Metal on its operating systems.

    If you continue to develop in related industries and go deep into the bottom layer, you will definitely encounter various difficulties with DX12, Vulkan, and Metal.     One of the main goals of Qt6 is to free Qt from direct use of OpenGL and, through appropriate abstraction, allow operation on a wider range of graphics APIs, such as Vulkan, Metal, and Direct3D.     • qrhi_p.h: Defines the structures and operations of various graphics resources
    • qrhi.cpp: QRhi's scheduling implementation with a lot of comment explanations
    • qrhi_p_p.h: Defines the complete structural skeleton of QRhi

    Other files starting with qrhi are specific implementations of specific graphics APIs.

    Examples¶

    There are many QRhi test projects in the following directory:

    Just modify the CMakeLists.txt in the current directory and add the following at the beginning of the content:

    cmake_minimum_required(VERSION 3.12)
project(QRhiTests VERSION 0.0.1)
find_package(Qt6 COMPONENTS Core Widgets BuildInternals REQUIRED)
include(QtSetup)
include(QtCMakeHelpers)
include(QtTestHelpers)

    Then you can use Cmake to generate project files for this directory.

    In these project examples, you can adjust the Rhi configuration in Project Properties - Debugging - Command Arguments. The configurable items can refer to QCommandLineParser in examplefw.h:

    For example, adding -v can use Vulkan as the rendering backend. Some examples cannot run in DX11.

    If you have a certain foundation in graphics APIs, you can quickly get started with QRhi through these project examples.

    helloinimalcrossgfxtriangle: A simple triangle drawing program

    multiwindow: Multiple Rhi windows

    multiwindow_threaded: Multiple windows, multiple threads

    rhiwidget: Use Rhi on QWidget

    offscreen: Off-screen (windowless) rendering

    triquadcube: Draw some simple geometric shapes

    polygonmode: Wireframe mode

    msaatexture: Texture using MSAA

    msaarenderbuffer: RenderBuffer using MSAA

    tst_manual_instancing: Instanced rendering

    noninstanced: Non-instanced rendering, using Buffer to achieve the same purpose as instancing

    mrt: Multiple Render Targets: A pipeline has multiple outputs

    texuploads: Upload textures

    floattexture: Floating-point texture: Originally, the value storage range of the texture is [0,1]

    texturearray: Texture array

    tex3d: 3D texture

    cubemap: Cube texture

    cubemap_scissor: Scissoring

    cubemap_render: Render output to cube texture

    compressedtexture_bc1: Compressed texture

    compressedtexture_bc1_subupload: Upload part of the compressed texture

    computebuffer: Use Compute Shader to make simple GPU particles

    computeimage: Use Compute Shader to dynamically generate images

    float16texture_with_compute: Compute and generate 16-bit floating-point texture

    geometryshader: Use geometry shader

    tessellation: Use tessellation shader

    shadowmap: Draw shadows

    The main purpose of this tutorial is to help some friends get started and cultivate good coding habits.

    For in-depth technologies, don't expect too many articles and tutorials to explain their principles. The code in mainstream engines is definitely the best reference, but to read them, you need not only sufficient theoretical knowledge but also excellent engineering capabilities.
