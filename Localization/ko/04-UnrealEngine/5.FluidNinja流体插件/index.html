    Fluid Ninja¶

    **Fluid Ninja**는 매우 낮은 성능 손실로 경이로운 효과를 제작할 수 있는 놀라운 인터랙티브 유체 시뮬레이션 플러그인입니다:

    NinjaLive¶

    NinjaLive는 Fluid Ninja가 제공하는 기본 Actor로, NinjaLiveComponent의 매개변수를 한 층 감싸고 대부분의 사용 요구를 충족할 수 있는 트레이스 평면을 포함하여 NinjaLiveComponent의 설정을 단순화하며 추가 기능을 제공합니다. 예를 들어:

    • ActivationVolume을 통해 NinjaFluid를 제거하고 휴면 상태로 만들며, ActivationVolume에 진입해야 NinjaLiveComponent가 활성화됩니다
    • InteractionVolume을 통해 더 세밀한 인터랙션 영역을 설정합니다.

    • 마우스를 표시합니다

    • 편집기의 120FPS 제한을 해제합니다

    시뮬레이션 과정¶

    FluidNinja의 에셋 디렉토리에는 Help 블루프린트가 있습니다:

    여기에는 Fluid Ninja 시뮬레이션의 흐름도가 상세히 설명되어 있습니다:

    NinjaFluid의 핵심은 다음과 같습니다:

    • Density(밀도) 텍스처와 Velocity(속도) 텍스처를 구축합니다
    • 노이즈(Noise) 를 중첩하여 유체의 무작위성을 증가시킵니다
    • 브러시(Brush) 를 조정하여 유체의 형태를 제어합니다
    • 출력 재질(Output Material) 과 결합합니다
    • 최종 결과를 트레이스 메시(Trace Mesh) 의 재질 표면에 출력합니다
    • 원하는 결과를 얻습니다:

    • Density는 단일 채널 텍스처로, 값 범위는 [0,1]이며 현재 위치의 유체 밀도를 나타냅니다.
    • Velocity는 이중 채널 텍스처로, 값 범위는 [0,1]이며 현재 위치의 유체 벡터 속도를 나타냅니다. [0,1]로 정규화되므로 속도 0은 실제로 RG 값 (0.5,0.5)에 해당합니다. 위 그림에서:
    • Velocity 텍스처의 R 채널은 수평 속도에 해당하며, 값이 <0.5일 때 유체는 왼쪽으로, >0.5일 때 오른쪽으로 이동합니다
    • Velocity 텍스처의 G 채널은 수직 속도에 해당하며, 값이 <0.5일 때 유체는 위로, >0.5일 때 아래로 이동합니다
    • FluidNinja는 3채널 재질 입력을 허용하며, 여기서 RG 채널은 Velocity를, B 채널은 Density를 나타냅니다

    사용 흐름¶

    제작 과정에서 본질적으로 NinjaLiveComponent 를 조작하며, 그 구성 항목 분류(Categories) 는 다음과 같습니다:

    • Live Activation: Disable Component 옵션만 있으며, 블루프린트를 통해 동적으로 설정하여 제거할 수 있습니다.
    • Live Interaction: 인터랙션 관련 모든 구성, 예를 들어 인터랙션 대상 필터링, 트레이스 메시의 방향 및 잠금, 월드 좌표 오프셋 등이 포함됩니다.
    • Live Brush Setting: 브러시의 매개변수 구성입니다.
    • Live Generic: 일반 구성으로, 주로 효과의 프리셋, 입력 및 출력을 조정합니다.
    • Live Performance: 성능 구성으로, 효과의 반복 횟수, FPS 범위 제한, LOD 등을 구성할 수 있습니다.
    • Live Compatibility: 호환성 구성으로, 충돌 채널, 입력 덮어쓰기 등을 구성할 수 있습니다.
    • Live Debug: 디버깅 구성으로, 힌트 메시지를 출력하기 위한 일부 체크박스를 제공합니다.
    • Live Raymarching: Raymarching을 구성합니다.
    • Live Memory Management: 메모리 관리 구성입니다.

    입력 구성¶

    여기서의 입력은 주로 밀도(Density) 와 속도(Velocity) 를 의미하며, 관련 입력 구성 매개변수는 주로 NiagaraComponent 의Live Generic 분류에 위치합니다. Fluid Ninja의 입력 소스는 다음과 같습니다:

    • 정적 텍스처
    • 동적 재질
    • 장면 카메라 캡처
    • 렌더 타겟(RenderTarget)
    • 스트리밍 비디오
    • 마우스 입력
    • 장면 인터랙션: 정적 메시, 동적 메시, 스켈레탈 메시, 파괴 가능한 객체...

    위 입력은 독립적이지 않으며 공존할 수 있습니다. FluidNinja는 여러 입력을 혼합하며, 자세한 내용은Help.uasset의 흐름도를 참조하십시오.

    지도Content/FluidNinjaLive/Tutorial/Levels/NinjaLive_Level03_SimulationInputs_LIVE17.umap에는 NinjaFluid 입력 예시가 완전히 포함되어 있으며, 다음은 이러한 입력의 핵심 단계를 기록한 것입니다:

    정적 텍스처(Texture)¶

    정적 텍스처의 입력 설정은 NinjaPreset 데이터 테이블에 위치합니다:

    동적 재질(Material)¶

    재질의 입력 구성은 NinjaComponent 의 Live Generic 분류에 위치합니다:

    • Input Materials 매개변수에서 사용 가능한 입력 재질을 추가할 수 있습니다. 여러 개를 추가하여 NinjaLive_PresetManager 에서 전환하여 미리 볼 수 있습니다.
    • Input Material Selected 인덱스를 조절하여 현재 사용할 입력 재질을 선택합니다.
    • RGB-Input Material 을 체크하면 재질의 RG 채널이 Velocity 텍스처로, B 채널이 Density 텍스처로 사용되며, 그렇지 않으면 기본적으로 재질의 R 채널만 Density 텍스처로 사용됩니다
    • Input Material Clamp 를 체크하면 UV 좌표가 [0,1] 외부에 있는 이미지가 자르기 처리됩니다.

    Ninja Fluid의 입력 재질은재질 도메인을후처리로 선택하고투사 광선 그림자 감지를 비활성화해야 합니다:

    장면 카메라 캡처(Scene Capture 2D)¶

    FluidNinja는 카메라를 사용하여 장면을 캡처하고 카메라 화면 내의 이미지를 유체 시뮬레이션의 입력으로 사용할 수 있으며,具體的한 구성은 NinjaComponent 의 Live Generic 분류에 위치합니다:

    • Input Scene Capture Camera 에서 현재 장면에 존재하는 Actor를 선택할 수 있습니다

    예시:

    • Ninja Live, Cube 및 장면 캡처 2D(Scene Capture 2D) 를 생성하고 카메라를 캡처할 Cube를 향하도록 합니다

    • Ninja Live 의 Ninja Component 에서 장면 캡처 2D를 구성하고 직관적인 재질 출력을 선택합니다:

    렌더 타겟(RenderTarget)¶

    재질의 입력 구성은 NinjaComponent 의 Live Generic 분류에 위치합니다:

    • Use Render Target as Input 을 체크하면 아래의 Input Render Target 이 유체 시뮬레이션의 입력으로 사용됩니다
    • Input Render Target 은 읽을 Render Target을 지정하는 데 사용됩니다

    Fluid Ninja에서 이方案은 형태 제어가 가능한 3D 유체 제작에 사용할 수 있습니다.

    Level3에는 다음 예시가 있습니다:

    • 왼쪽은 Niagara 입자 시스템, 중간은 투영된 RT, 오른쪽은 RT+출력 재질을 이용한 최종 효과입니다

    • 콘텐츠 브라우저에서【Niagara 입자 시스템】을 새로 생성하고【기존 시스템에서 복사】를 선택합니다

    • NE_ParticleCaptureBasic: Empty 발사기의 입자를 메시 좌표를 통해 RenderTarget에 매핑하며, AttributeReader에서 어떤 발사기를 캡처할지 선택할 수 있습니다.

    • Empty: 시뮬레이션용 입자 발사기

    • NiagaraSystem의 기본 매개변수에 지정하고 사용자 매개변수를 조정하여 RT의 매핑 규칙을 이해합니다:

    충돌 인터랙션¶

    Fluid Ninja는 물리 충돌을 입력으로 사용하여 인터랙티브한 유체 효과를 완성할 수 있습니다. 간단한 예시는 다음과 같습니다:

    • NinjaLiveActor를 추가합니다

    • Trace Mesh Size와Interaction Volume Size를(5,5,1)로 설정합니다

    • NinjaLiveComponent\Live Bursh Settings를 설정합니다. 그렇지 않으면 충돌 브러시가 너무 작아 결과를 볼 수 없습니다

      • Brush Scaled By Interacting Obj Size를 체크합니다
      • Primitive Obj Brush Scale을 20으로 설정합니다

    • 소형 인간 모델을 추가하면 다음 효과를 볼 수 있습니다:

    이 효과는 UE의 물리 충돌 메커니즘을 통해 구현되며,完整한 매개변수는 모두 NinjaLiveComponent\Live Interaction 에 위치합니다:

    • Continuous Interaction with Owner Actor: 이 컴포넌트를 소유하는 Actor와 지속적으로 인터랙션합니다
    • Continuous Interaction incluisve Obj Type: 인터랙션할 충돌 객체 타입을 필터링합니다
    • Continuous Interaction Component Name: 인터랙션할 컴포넌트 이름을 필터링합니다
    • Continuous Interaction Bone Names Exact: 인터랙션할 골격 이름을 필터링합니다
    • Single Target Mode: 단일 대상 모드로, 활성화하면 FluidNinja는 충돌로 생성된 이미지가 모두 하나의 대상에서 생성된 것으로 간주하여 충돌 경로를 매끄럽게 만들고 단절(보간) 없이 만듭니다
    • Single Target Type
    • Single Target Mode Skeletal Mesh Index
    • Single Target Move Set Sim Speed
    • Speed Influence Factor: 속도 영향 인자
    • Clamp Max Velocity: 최대 속도를截断합니다
    • Camera Facing Trace Mesh: TraceMesh가 항상 카메라를面向합니다
    • Camera Facing Lock Y-Axis: 카메라의 Y축을 잠급니다
    • Use Legacy Camera Facing
    • Trance Mesh Translucent Sort Prio
    • Use Custom Trace Source: 사용자 정의 추적 리소스를 사용하며, 활성화하면 충돌 감지를 위해 아래 위치를 카메라 위치로 사용합니다
    • Custom Trace Source Position: 자동 추적 리소스의 위치
    • Trace Mesh Moving in World Space: TraceMesh가 월드 공간에 위치합니다
    • Movement Not Quantized to Steps OnAxis
    • Movements is Locked on This axis: 특정 축의 이동을 잠급니다
    • Force Trace Mesh to Custom Vertical Pos
    • Force Trace Mesh Vertical Position: TraceMesh의 위치를 잠급니다
    • Enable Paint Buffer Offset in World Spacing: 월드 공간 메커니즘에서 페인트 버퍼 오프셋을 활성화합니다
    • Simple Painter Mode: 단순한 페인트 모드로, 충돌 입력이 없습니다

    NinjaLiveActor 의 경우 위 매개변수를 추가로封装하여 다음 매개변수를 조정할 수 있습니다:

    • Overlap Based Interaction: 충돌 인터랙션을 활성화합니다

    • Interaction Volume Size: 인터랙션 볼륨 크기

    • 다음 매개변수는 어떤 객체가 인터랙션 볼륨과 "작용"할 수 있는지 **필터링**하는 데 사용됩니다.

    • Track Actor Primitive Components With Tag: 해당 태그가 있는 컴포넌트를 추적합니다

    • Track Actor Skeletal Mesh Components With Tag: 해당 태그가 있는 스켈레탈 메시 컴포넌트를 추적합니다

    • Overlap Filter Inclusive Obj Tab: 포함할 객체 충돌 타입

    • Overlap Filter Inclusive Bone Name Exact: 포함할 골격 이름. 비어 있으면 모든 골격을 처리합니다

    • Overlap Filter Inclusive Bone Name Partial: 포함할 골격 이름 필드. 예를 들어 Foot를 입력하면 이름에 Foot가 포함된 모든 골격이 포함됩니다

    • Exclude Specific Actors from Overlap: 인터랙션에서 제외할 Actor 타입

    • Auto Exclude Large Overlapping Objects: 대형 중첩 객체를 자동으로 제외합니다

    브러시 조절¶

    브러시는 FluidNinja 입력 텍스처의 작용 영역缩放 인자를 제어하는 데 사용되며,其 매개변수 구성은 다음과 같습니다:

    일부 핵심 매개변수:

    • Brush Scaled Inversely by Trace Mesh Size: 브러시가 트레이스 메시의 크기에 따라缩放됩니다
    • Brush Scaled by Interacting Obj Size: 브러시가 인터랙션 객체의 크기에 따라缩放됩니다
    • Use Obj Bounds Instead of Size: 인터랙션 객체의 경계를 브러시 크기로 사용합니다
    • Global Brush Scale: 전역 브러시缩放 계수

    충돌 인터랙션 효과가 거의 보이지 않으면 브러시가 너무 작기 때문일 가능성이 높습니다

    요약¶

    FluidNinja의 아이디어는 매우巧妙하며 사용하기는 다소 번거롭지만 핵심 단계는 명확합니다:

    • 시뮬레이션 과정에 필요한 Density(밀도) 텍스처와 Velocity(속도) 텍스처를 구성하고 적절한 브러시와 프리셋을 사용하며 해당 재질과 결합하여 최종 원하는 효과를呈现합니다.

    장단점¶

    • FluidNinja는 2D 평면을 사용하여 3D 시각 효과를 위장하며, 일반적인 입자 유체 시뮬레이션보다 성능 손실이 훨씬 적습니다. 하지만 충분히 실제적인 3D 효과를 위장하려면 충분히 실제적인 2D 입력이 필요하며, 그렇지 않으면 일부 시점에서 FluidNinja의 트레이스 메시 평면을 쉽게 식별할 수 있습니다.
    • FluidNinja는 텍스처, 재질, RT, Niagara, 카메라 등 유체 입력을 구성하는 많은 방법을 제공하여 대부분의 개발 요구를满足할 수 있지만 세부 사항이 많아 사용하기 쉽지 않으며 원하는 효과를 자유자재로 제작하려면 심층적인 학습이 필요합니다.
    • FluidNinja는 입자를 완전히 대체할 수 없으며 인터랙티브한 유체 시뮬레이션, 예를 들어 연기, 불꽃, 물 등에 더 적합합니다.
