    GUI¶

    그래픽 사용자 인터페이스(Graphical User Interface, 약칭 GUI, 그래픽 사용자 인터페이스라고도 함)는 그래픽 방식으로 표시되는 컴퓨터 조작 사용자 인터페이스를 의미한다.

    그래픽 사용자 인터페이스는 컴퓨터 통신과 사람이 소통하는 인터페이스 표시형식으로, 사용자가 마우스 등 입력 장치를 사용해 화면 상의 아이콘이나 메뉴 옵션을 조작하여 명령 선택, 파일 호출, 프로그램 실행 또는 기타 일부일상 작업을 수행할 수 있게 한다. 키보드를 통해 텍스트나 문자 명령을 입력하여 일상 작업을 완료하는 문자 인터페이스와 비교했을 때, 그래픽 사용자 인터페이스에는 많은 장점이 있다. 그래픽 사용자 인터페이스는 창, 드롭다운 메뉴, 대화 상자 및 해당 제어 메커니즘으로 구성되며, 다양한 신규 애플리케이션에서 표준화되어 동일한 작업이 항상 동일한 방식으로 완료된다. 그래픽 사용자 인터페이스에서 사용자가 보고 조작하는 것은 모두 그래픽 객체이며, 컴퓨터 그래픽스 기술을 적용한다.

    ——《백두百科》

    콘솔과 힘겨운 싸움을 하는 날들이 지겨웠다면, 이 글이 도움이 될 수 있다.

    개요¶

    GUI는 주로 두 가지 큰 범주로 나눌 수 있다:

    • Native UI : 전통적인 네이티브 앱 개발 모드로, 시스템 플랫폼의 인터페이스를 사용하여 개발
    • Web UI : 브라우저에서 특정적으로 실행되는 웹사이트 애플리케이션

    여기에 더 자세한 소개가 있다:

    • 지후(知乎): Native、Web App、Hybrid이란 무엇인가?

    Hybrid는 Native UI와 Web UI를 혼합하여 개발하는 것을 의미한다.

    이들에 대한 논쟁은 다음을 참고할 수 있다:

    • 지후(知乎): Web App과 Native App 중 어떤 것이 추세인가?

    Web UI는 비용이 저렴하고 개발이 빠르기 때문에 인터넷 시장에서 주도적인 위치를 차지하고 있으며, Native UI를 사용하는 이유는 무外乎 고성능, 맞춤화, 하드웨어 상호작용이다.

    현재 Web GPU가 안정화되어 Web 프로그래머에게 더 큰 성장 공간을 제공하고 있지만, 그래픽 및 엔진 분야의 학생들에게는 저자가 Native 방향으로 가는 것을 권장한다. 이렇게 하면 더 많은 제어 가능한 공간이 있다.

    Native UI方案은 언어에 따라 주로 다음과 같이 나눌 수 있다:

    C/C++: Qt、WxWidget、GTK、FLTK、DearImGUI、Nuklear、duilib、C++ Builder、MFC、EasyX

    Python: PyQt、WxPython、PyGTK、PyFLTK、DearPyGUI、Tkinter、PyGame

    C#: WPF、WinForm

    Java: Swing、JavaFx

    위 프레임워크에서 C/C++를 사용하는 것은 천연적인 장점이 있지만, 만약 Python이나 C# 개발자이고 강제적인 업무 요구가 없다면 GUI를 위해 C++를 배우기 위해 불필요하게 수고를 들일 필요는 없다.

    • 지후(知乎): 어떤 언어가 GUI를 만드는 데 가장 적합한가?

    이러한 C++ GUI 프레임워크 중 어떤 것을 선택해야 할까?

    저자는 순서대로 EasyX - Tkinter - PyGame - JavaFx - FLTK - Qt - ImGUI - UE Slate를 배웠다.

    전체적으로 사용해보니 GUI는 아무리 봐도 다음과 같다:

    • 시스템의 (키보드/마우스) 상호작용 이벤트를 처리
    • 화면에 픽셀을 채워 몇 개의 그래픽을 그림

    이것은 운영체제 또는 각 GUI 프레임워크가 최소한 제공해야 하는 기능이다. 이 두 가지 기능이 있다면, 키보드/마우스 조작에 콜백 함수를 바인딩하고 루프를 사용해 화면 픽셀에 RGB를 채우는 것만으로도 어떤 멋진 그래픽 인터페이스도 만들 수 있다. 예를 들어 다음과 같은 프로그램:

    #include <conio.h>      //콘솔 IO
#include <iostream>

int main() {
    char currentChar = '\0';
    const int width = 20;
    const int height = 20;
    while (true) {
        if (kbhit()) {              //kbhit은 현재 키 입력이 있는지 판단할 수 있다
            currentChar = getch();  //getch는 비표시 입력 함수로, getchar와 달리 입력된 키가 콘솔에 표시되지 않는다
        }
        system("cls");              //콘솔 화면 지우기
        std::cout << "Please enter key:" << std::endl;
        for (int y = 0; y < height; y++) {
            for (int x = 0; x < width; x++) {
                std::cout << currentChar;
            }
            std::cout << std::endl;
        }
    }
    return 0;
}

    콘솔 프로그램은 실행 중疯狂闪烁하는데, 이는 다음 섹션에서 해결할 것이다.

    GUI는 위 콘솔 프로그램과 비교했을 때, 키보드/마우스 입력을 한 층 인터페이스로封装하고 width와 height를 창 크기로 하여 해당 좌표의 픽셀에 색상을 채우는 것에 불과하다.

    실제로 어떤 프레임워크를 선택할지 결정하는 가장 중요한 것은 생태계이며, 구체적으로 다음과 같다:

    • 사용하는 사람이 많고 동료가 많아 채용이 더 쉬움
    • 프레임워크의 적용 범위가 넓고 도구 라이브러리가 많으며 문서가 완비됨
    • 공식적으로 장기간 유지보수하며迭代频率가 높고 문제가 적음

    위 프레임워크 중 가장 잘做得最好的 것은 의심할 여지 없이 — Qt이다.

    Qt의 대부분 모듈은 LGPL 라이선스를 따르며, 이는 동적 링크 형식으로 모듈을 사용하고 상용 소프트웨어를 배포할 수 있게 허용한다. 각 모듈의 오픈 소스 라이선스는 다음을 참고하라:

    • https://doc.qt.io/qt-6/licenses-used-in-qt.html

    Qt 소스 코드를 수정하거나 일부 상용 모듈을 사용하려면 Qt의 상용 라이선스를 구매해야 한다. 구체적인 내용은 다음을 참고하라:

    • https://www.qt.io/licensing/open-source-lgpl-obligations

    Qt의 오픈 소스 라이선스가 비교적 엄격하고 C++ 표준과 독립적이며 체적이 방대하기 때문에 많은 팀은 여전히 WxWidget, C++ Builder, duilib, GTK 등의 프레임워크를 선택할 수 있다. MFC, FLTK, EasyX는 좋은 GUI 프레임워크일 수 있지만 개발 생태계가 낙후되어 있으므로 선택할 수 있다면 저자가 접근하지 않는 것을 권장한다.

    Dear ImGUI와 Nuklear는 가벼우고 이식 가능하며 **Immediate Mode**를 따르는 GUI 툴킷으로, 본질적으로 개발자에게 일부 컨트롤 인터페이스를 제공하여 한 프레임의 그래픽을 그리도록 한다. ImGUI를 예로 들어 다음과 같은 코드를 사용할 수 있다:

    ImGui::Text("Hello Dear ImGUI");
static bool CheckState;
ImGui::Checkbox("CheckBox ", &CheckState);

    다음과 같은 인터페이스를 생성할 수 있다:

    Immediate Mode（즉시 모드）**는 변수 CheckState의 포인터를 "컨트롤"에 전달하는 데 주로体现되는데, Qt에서의 전통적인 **Retained Mode（보존 모드） 코드는 다음과 같을 수 있다:

    static bool CheckState;
QCheckBox* CheckBox = new QCheckBox;
CheckBox->setCheckState( CheckState? Qt::Checked : Qt::Unchecked);      //초기화
QObject::connect(CheckBox,&QCheckBox::stateChanged,[&](int state){      //signal-slot 바인딩
    CheckState = state == Qt::Checked;
});

    **QCheckBox**가 CheckState의 포인터를 사용하지 않고 CheckState를 통해 컨트롤의 초기 상태를 설정하고, 컨트롤 stateChanged 시 CheckState의 값을 설정하는 것을 볼 수 있다. 즉 컨트롤 자체가 자신의 State를持有하는 반면, **Immediate Mode는 무상태를 강조**하며 상태를 컨트롤에嵌入한다.

    개발 과정에서 너무 많은 로컬 상태를 저장하면 동기화를 유지하기 위해 많은 코드를 작성해야 하며 실수로 버그를 만들기 쉽다. 예를 들어 일부 이벤트가 여러 번 실행되거나 심지어 무한 루프에 빠질 수 있다.

    예를 들어 Color를 조절한다고 가정해보자:

    색상 선택기, 드래그 또는 채널 값 입력, 16진수 입력, 화면 색상 추출 등 다양한 방식으로 동일한 색상 값을 조절할 수 있다. 보존 모드를 사용하면某种方式로 색상을修改한 후 다른 컨트롤을手动으로调整하여 색상 동기화를保证해야 한다. 일부 디자인 패턴을 따르면 이 문제를 해결할 수 있지만, 즉시 모드는 이러한 응용 시나리오에서 천연적인 장점이 있다. 이들의 차이에 대한 논쟁은 다음을 참고하라:

    • 지후(知乎): Retained와 IMGUI의联系와区别는 무엇인가?

    那么这是否意味着 Dear ImGUI가 Qt보다 좋은가? 그렇지 않다. 저자의 관점은 다음과 같다:

    • Immediate Mode는 게임 엔진에 더 적합하지만 Dear ImGUI는 아직 부족하다. 이는 단순히 작은 GUI 툴킷일 뿐이며 쉽게上手할 수 있고不错的界面效果를 만들 수 있지만 대형 소프트웨어 시스템의 개발은工程艺术이며 낮은 진입 장벽은更多的问题를带来할 수 있다.足够的人手와精力로不断迭代하지 않는 한原生 Dear ImGUI로 개발하는 것은一场灾难이다...

    여기에 Dear ImGUI에 대한 이야기는 아니지만 이러한 프레임워크의 문제를很好地暴露하는 답변が 있다: https://www.zhihu.com/question/66934513/answer/248036488

    • Retained Mode는 컨트롤 아키텍처의一种方式일 뿐, Qt != Retained Mode이다. 기본적으로 Native UI 프레임워크의 공식 컨트롤은 Retained Mode를 사용하지만 원한다면这些框架上에서 Immediate Mode를 사용할 수도 있다.

    Why Qt and not IMGUI?

    那么这是否意味着 Qt가更好的가? 그렇지 않다. Qt를 사용하면 Core와 Widget 모듈 및 moc을整个引入해야 하며 오픈 소스 라이선스로 인해 소스 코드를修改할 수 없기 때문에 게임 엔진에서는 대부분编辑器로 사용된다. 예를 들어:

    • O3DE：https://github.com/o3de/o3de

    현재 게임 내 UI方案으로는 적합하지 않다:

    • 云风의 BLOG — 게임 UI 모듈의 선택：https://blog.codingnow.com/2020/07/game_ui.html

    UE의 Slate는非常优秀的底层UI框架이다:

    • https://docs.unrealengine.com/5.1/en-US/understanding-the-slate-ui-architecture-in-unreal-engine/

    但本系列文章接下来的图形相关教程에서는 Qt를主编辑器로 사용하고 ImGUI를内嵌하여场景编辑에 사용할 것이다. 주요原因如下:

    • Qt는跨平台的Window封装을拥有하며 Handle을拿到 Native API를 사용하여一些特殊处理를 할 수 있다.
    • Qt는优雅的反射系统을拥有하며编辑器를搭建하기 쉽고 Signal-Slot을使用하여逻辑를很好地解耦하고 가독성을 높일 수 있다.
    • Qt는独立的容器库를拥有하며 STL의摧残을 받지 않을 수 있다.
    • Qt는接口风格이统一的很多扩展库를拥有하며 기본 수학 라이브러리, 이미지编解码 라이브러리, 멀티미디어 라이브러리 등学习成果를更容易变现할 수 있다.
    • Qt 6.0以后 OpenGL, DX11, Vulkan, Metal을支持하는 RHI(Render Hardware Interface)를推出했으며 OpenGL보다使用하기 쉽고架构上 Vulkan风格의 glsl과现代图形API를使用하며 bgfx처럼魔改하지 않았으며最重要的是 Qt의 RHI를使用하여 Native API와很好地兼容할 수 있어图形API나硬件提供的高级特性를使用하기 쉽다.
    • Qt의很多体系结构를 Unreal Engine에映射할 수 있으며 목표가 Unreal Engine이라면 Qt는最好的跳板이다. Qt의 공식 코드는 가독성이 높고大量的文档, Demo,教程를拥有하기 때문이다.

    플랫폼 기초¶

    GUI程序은 화면에显示되며 화면上의 픽셀을系统的管理하기 위해 운영체제는 Window라는 구조를提供한다. Windows10上에서标准的Window는 다음과 같으며 아이콘,标题文本,最小化按钮,最大化按钮,关闭按钮이 있는标题栏을带有한다:

    다음과 같은方式로 Window를创建할 수 있다:

    • CMakeLists.txt와 main.cpp 파일을新建한다.

    • CMakeLists.txt에 다음을填入한다:

    cmake_minimum_required(VERSION 3.12)
project(Window)
add_executable(Window WIN32 main.cpp)

    Win32는 해당 executable이 Win32窗口임을表明하며具体적으로 Visual Studio의 프로젝트 설정 - 링커 - 시스템 - 서브시스템 - 窗口에对应한다.

    • main.cpp에 다음을填入한다:
    #ifndef UNICODE
#define UNICODE
#endif 

#include <windows.h>

LRESULT CALLBACK WindowProc(HWND hwnd, UINT uMsg, WPARAM wParam, LPARAM lParam);

int WINAPI wWinMain(HINSTANCE hInstance, HINSTANCE hPrevInstance, PWSTR pCmdLine, int nCmdShow)
{
    // Register the window class.
    const wchar_t CLASS_NAME[]  = L"Sample Window Class";

    WNDCLASS wc = { };

    wc.lpfnWndProc   = WindowProc;
    wc.hInstance     = hInstance;
    wc.lpszClassName = CLASS_NAME;

    RegisterClass(&wc);

    // Create the window.

    HWND hwnd = CreateWindowEx(
        0,                              // Optional window styles.
        CLASS_NAME,                     // Window class
        L"Learn to Program Windows",    // Window text
        WS_OVERLAPPEDWINDOW,            // Window style

        // Size and position
        CW_USEDEFAULT, CW_USEDEFAULT, CW_USEDEFAULT, CW_USEDEFAULT,

        NULL,       // Parent window    
        NULL,       // Menu
        hInstance,  // Instance handle
        NULL        // Additional application data
        );

    if (hwnd == NULL)
    {
        return 0;
    }

    ShowWindow(hwnd, nCmdShow);

    // Run the message loop.

    MSG msg = { };
    while (GetMessage(&msg, NULL, 0, 0) > 0)
    {
        TranslateMessage(&msg);
        DispatchMessage(&msg);
    }

    return 0;
}

LRESULT CALLBACK WindowProc(HWND hwnd, UINT uMsg, WPARAM wParam, LPARAM lParam)
{
    switch (uMsg)
    {
    case WM_DESTROY:
        PostQuitMessage(0);
        return 0;

    case WM_PAINT:
        {
            PAINTSTRUCT ps;
            HDC hdc = BeginPaint(hwnd, &ps);

            // All painting occurs here, between BeginPaint and EndPaint.

            FillRect(hdc, &ps.rcPaint, (HBRUSH) (COLOR_WINDOW+1));

            EndPaint(hwnd, &ps);
        }
        return 0;

    }
    return DefWindowProc(hwnd, uMsg, wParam, lParam);
}

    Multiple buffering¶

    之前的控制台程序中页面이疯狂闪烁하는데这是因为一个缓冲区에一点一点添加东西하며控制台窗口이这个过程을预览하기 때문이다.刷新速度가很快기 때문에闪烁이导致된다.这类问题를解决하기 위해计算机科学中 **Multiple buffering（多缓冲）**的概念을提出했다:

    • 控制台预览에供给하는缓冲区을 **前台缓冲区**라고 부르며多缓冲的核心在于前台缓冲区을直接操作하지 않고 **后台缓冲区**에处理完毕后 **统一提交**给前台缓冲区하는 것이다.这样可以有效避免闪烁和撕裂.

    统一提交을提到하면上一节的 **for copy**와 **memcpy**를想到하지 않는가?

    筐里的所有橘子를另一个筐里放到 경우一个一个放快还是直接抬起筐倒快?显而易见.

    硬件和接口的提供者显然也懂得这个道理.绝大多情况下他们都会 Map, Blit之类的操作을支持한다.

    控制台中双缓冲区을使用하는示例如下:

    #include <conio.h>      //控制台IO
#include <iostream>
#include <Windows.h>

const int width = 20;
const int height = 20;
const int MaxBufferSize = width * height * 10;

void UseSingleBuffer() {
    char currentChar = '*';
    while (true) {
        if (kbhit()) {              //kbhit은当前是否有按键输入을判断할 수 있다
            currentChar = getch();  //getch는 비표시输入函数로 getchar와不同的是输入的按键가控制台에显示되지 않는다
        }
        system("cls");              //控制台清屏
        for (int y = 0; y < height; y++) {
            for (int x = 0; x < width; x++) {
                std::cout << currentChar;
            }
            std::cout << std::endl;
        }
    }
}

void UseDoubleBuffer() {
    HANDLE frontendBuffer = GetStdHandle(STD_OUTPUT_HANDLE);        //默认的缓冲区을获取

    HANDLE backendBuffer = CreateConsoleScreenBuffer(               //新的缓冲区을创建하여后台缓冲区로作为
        GENERIC_READ | GENERIC_WRITE,
        FILE_SHARE_READ | FILE_SHARE_WRITE,
        NULL,
        CONSOLE_TEXTMODE_BUFFER,
        NULL
    );

    //两个缓冲区的光标을隐藏
    CONSOLE_CURSOR_INFO cci;
    cci.bVisible = 0;
    cci.dwSize = 1;
    SetConsoleCursorInfo(frontendBuffer, &cci);
    SetConsoleCursorInfo(backendBuffer, &cci);


    char bufferData[MaxBufferSize];     //缓存数据暂存区
    DWORD bufferLength = 0;
    COORD zeroCoord = { 0,0 };
    char currentChar = '*';

    while (true) {
        if (kbhit()) {              
            currentChar = getch();  
        }
        bufferLength = 0;

        CONSOLE_SCREEN_BUFFER_INFO backendBufferInfo;       //backendBuffer每行的字符数量을获取
        GetConsoleScreenBufferInfo(backendBuffer, &backendBufferInfo);
        int lineWidth = backendBufferInfo.srWindow.Right - backendBufferInfo.srWindow.Left + 1;     

        for (int y = 0; y < height; y++) {
            for (int x = 0; x < width; x++) {
                bufferData[bufferLength++] = currentChar;
            }
            while (bufferLength % lineWidth != 0) {             //换行的效果를到达하기 위해字符을填充
                bufferData[bufferLength++] = ' ';
            }
        }

        //backendBuffer의 zeroCoord부터 bufferLength长度的bufferData를写入
        WriteConsoleOutputCharacterA(backendBuffer, bufferData, bufferLength, zeroCoord, &bufferLength);    
        SetConsoleActiveScreenBuffer(backendBuffer);            //backendBuffer를显示出来
        std::swap(backendBuffer, frontendBuffer);               //前后缓冲操作句柄을交换. frontendBuffer는下一次循环的backendBuffer로作为
    }
}

int main() {
    //UseSingleBuffer();
    UseDoubleBuffer();
    return 0;
}

    *.cpp中写在 Q_OBJECT에 대해서는末尾에手动으로 *.moc을 include해야 moc的执行을触发할 수 있다. 예를 들어:

    /* main.cpp
*/

#include <QApplication>
#include <QMetaType>
#include <QMetaProperty>

class QExmapleClass : public QObject {
    Q_OBJECT
    Q_PROPERTY(int Var READ getVar WRITE setVar)                //Getter、Setter를通过하여 MetaProperty를声明
public:
    int getVar() {
        return mVar;
    }
    void setVar(int inVar) {
        mVar = inVar;
    }

    Q_INVOKABLE void sayHello(const QString& inName) {          //MetaMethod를声明
        qDebug() << "Hello " << inName.toLatin1().data();
    }

    enum Number {
        Zero, One, Two, Three
    };
    Q_ENUM(Number)                                              //MetaEnum을声明
protected:
    int mVar= 5;
};

int main(int argc, char* argv[]) {
    QApplication a(argc, argv);

    QExmapleClass obj;      

    //MetaObject를获取
    const QMetaObject* metaObjectFromStatic = &QExmapleClass::staticMetaObject; 
    const QMetaObject* metaObjectFromVirtual = obj.metaObject();

    //属性를读写
    obj.setProperty("Var", QVariant::fromValue<int>(10));                       
    QVariant var = obj.property("Var");
    qDebug() << "Property : " << var.value<int>();

    //函数을调用
    qDebug() << "Invoke Method Begin:";
    metaObjectFromStatic->invokeMethod(&obj, "sayHello",Q_ARG(QString,"Boy"));
    qDebug() << "Invoke Method End";

    //MetaType操作
    QMetaType metaType = var.metaType();
    qDebug() << "Meta Type : " << metaType.name() <<" ID: " << metaType.id();

    //MetaObject中属性를遍历及读写하고属性类型을打印
    for (int i = metaObjectFromStatic->propertyOffset() ; i < metaObjectFromStatic->propertyCount(); i++) {
        const QMetaProperty& metaProperty = metaObjectFromStatic->property(i);
        metaProperty.write(&obj, QVariant::fromValue<int>(15));
        QVariant varFromMetaObject = metaProperty.read(&obj);
        qDebug() << "Meta Property : " << metaProperty.name() << varFromMetaObject;
    }

    //MetaObject中函数을遍历하고参数信息을打印
    for (int i = metaObjectFromStatic->methodOffset(); i < metaObjectFromStatic->methodCount(); i++) {
        const QMetaMethod& metaMethod = metaObjectFromStatic->method(i);
        QByteArrayList paramNames = metaMethod.parameterNames();
        QStringList paramsDefineList;
        for (int j = 0; j < metaMethod.parameterCount(); j++) {
            paramsDefineList << metaMethod.parameterTypeName(j) +" " + paramNames[j];
        }
        qDebug() << QString("Meta Method : %1 %2(%3)")
            .arg(metaMethod.typeName())
            .arg(metaMethod.name())
            .arg(paramsDefineList.join(',')).toLatin1().data();
    }

    //MetaObject中枚举을遍历하고枚举信息을打印
    for (int i = metaObjectFromStatic->enumeratorOffset(); i < metaObjectFromStatic->enumeratorCount(); i++) {
        const QMetaEnum& metaEnum = metaObjectFromStatic->enumerator(i);
        qDebug()<< "Meta Enum : " << metaEnum.name();
        for (int j = 0; j < metaEnum.keyCount(); j++) {
            qDebug() << "-- " << metaEnum.key(j) << " : " << metaEnum.value(j);
        }
    }
    return a.exec();
}

    Signal-Slot¶

    信号槽机制은对象之间的通信에用于하며 Qt的核心特性이다.其作用에 대한伪代码示例如下:

    class Student{
    Signal nameChanged(string OldName, string NewName);
public:
    void setName(string inName){
        nameChanged.Emit(mName，inName);
        mName = inName;
    }
private:
    string mName;
};

class Tearcher{
public:
    void OnStudentNameChanged(string OldName, string NewName){
        //do something
    }
};

class Class{
protected:    
    void connectEveryone(){
         for(auto Student:mStudents){       
             Student.nameChanged.Connect(mTeacher,&Tearcher::OnStudentNameChanged);
         }
    }
private:
    Teacher mTeacher;
    TArray<Student> mStudents;
};

    Event System¶

    Qt中事件는抽象类QEvent子类的实例对象을指하며应用程序内部或外部活动的结果을描述하기 위해用于한다.作用上它可以重量级的Single-Slot으로看做하며 QWigdet中的交互机制은 모두事件을通过하여实现된다.

    一个事件가发生时 Qt는适当的QEvent子类实例을构造하여其를表示하고 다음을调用한다:

    • static bool QCoreApplication::sendEvent(QObject* receiver, QEvent event)

    对应的QObject에事件를发送하며 QObject는虚函数을拥有한다:

    • virtual bool QObject::event( QEvent* e )

    event를覆写하여其中에事件를处理或者进一步其他函数에分发할 수 있다.

    此外 Qt는事件监听器机制을支持하며 QObject的虚函数을覆写할 수 있다:

    • bool QObject:: eventFilter ( QObject * watched , QEvent* event )

    使之可以filterObj로作为再 다음을调用한다:

    • void QObject:: installEventFilter ( QObject* filterObj )

    从而该对象能其他的对象的事件监听者로作为할 수 있다.

    Garbage Collection¶

    上一节内存管理中 Qt的GC를提过했다.其GC方式는很简单하다. QObject는唯一的parent를指定할 수 있으며 parent가释放时 children도释放한다.此外 QObject::deleteLater를使用하여 QObject的释放을延迟할 수 있다.

    QWidget中子控件을加入하면隐式적으로 parent를设置한다.绝大多数情况下手动으로 delete할 필요가 없지만 parent的生命周期을控制해야 한다.对象树中的某个节点에纰漏가出现하면整个子树的对象都无法被释放한다.

    Qt中的QWidget, UE中的 SWidget에对应

    Widget은轻量级的Window로看做할 수 있으며以下特性을具有한다:

    • 显示上 Widget은一个块으로看做할 수 있으며本质上 Window的客户区域을分割한다.该区域은 Widget自行绘制한다.
    • 逻辑上 Widget은树状层级를具有하며事件는往往自顶向下传递한다.

    WindowOption¶

    一般情况下开发者는甚至 QWindow에接触하지 않는다.最外层(or最顶级)的 QWidget은自动으로 QWindow을生成하기 때문이다.这个QWidget에一些设置을做하여 Window的生成에影响할 수 있다:

    • WindowFlag : Window的标识을调整한다.比如弹窗,对话框,提示框,无边框...
    • WindowModality :模态窗口을设置한다.模态窗口은其他窗口的输入을阻塞한다.一般用于用户가当前强制某些选项을选择해야继续执行할 수 있게 한다.
    • WindowState : Window的状态은 默认, 最小化, 最大化, 全屏(无边框), 激活이 있다. setWindowState를调用할 수 있으며 Qt는一些便捷API를提供한다. 예를 들어 activateWindow()

    比如这样的代码:

    QWidget widget;
widget.setWindowFlags(Qt::FramelessWindowHint|Qt::Tool);
widget.resize(200,200);
widget.show();

    屏幕上 200*200的灰色方块을看到할 수 있으며下方的任务栏中其图标도隐藏된다.

    需要注意的是 Widget的创建时 Window를创建하지 않는다. Widget的设置은绝大多数时候只是其参数状态机를调整하는 것이다.事件执行时这些状态에根据하여实际的操作을进行한다. 예를 들어 show之后才能 Window的句柄을拿到한다.

    Attribute¶

    Qt命名空间下 WA_로开头的一组枚举值을使用하여 WidgetAttribute를设置할 수 있다. QWidget에很多有用的属性를设置할 수 있다.其中常用的:

    • Qt::WA_DeleteOnClose :窗口关闭时该对象을销毁
    • Qt::WA_TranslucentBackground :窗口的背景을透明하게 만듦

    Event¶

    GUI的显示은 QWidget的 paintEvent에在于한다.其를覆写하여里面에 QPainter를使用하여想要的任何图形을绘制할 수 있다.

    GUI的本质은无非各类交互事件을借助하여属性状态机를调整하고 paintEvent的绘制结果을切换하는 것이다.

    这是一个很好的例子:

    #include <QApplication>
#include <QWidget>
#include <QMouseEvent>
#include <QPainter>

class QExmapleWidget:public QWidget {
    Q_OBJECT
private:
    QPoint mMousePressPos;
    bool bIsHovered = false;
protected:
    void mousePressEvent(QMouseEvent* event) override {
        if (event->button() == Qt::LeftButton)      //鼠标左键按下时的位置을记录
            mMousePressPos = event->pos();          
    }
    void mouseMoveEvent(QMouseEvent* event) override {
        if (event->buttons() & Qt::LeftButton)      //鼠标左键按下拖拽时 Widget的位置을调整
            move(event->pos() + this->pos() - mMousePressPos);
    }

    void enterEvent(QEnterEvent* event) override {
        bIsHovered = true;                          //鼠标进入Widget中
        setCursor(Qt::ClosedHandCursor);            //鼠标光标的形状을设置
        update();                                   //界面刷新를请求
    }

    void leaveEvent(QEvent* event) override {
        bIsHovered = false;                         //鼠标离开Widget
        setCursor(Qt::ArrowCursor);                 //鼠标光标的形状을设置
        update();                                   //界面刷新를请求
    }

    void paintEvent(QPaintEvent* event) override {
        QPainter painter(this);

        painter.fillRect(this->rect(),bIsHovered ? Qt::green : QColor(0,100,200));  //区域内에颜色을填充

        painter.setPen(QPen(Qt::white));
        painter.setFont(QFont("",20,90));                                           //缺省字体를使用하고字号和权重을设置
        painter.drawText(this->rect(), Qt::AlignCenter, "Hello Qt");                //文字을绘制
    }
};

int main(int argc, char* argv[]) {
    QApplication a(argc, argv);
    QExmapleWidget widget;
    widget.setWindowFlags(Qt::FramelessWindowHint);         //无边框
    widget.setAttribute(Qt::WA_TranslucentBackground);      //背景透明      
    widget.setAttribute(Qt::WA_AlwaysStackOnTop);           //置顶
    widget.resize(200,200);
    widget.show();
    return a.exec();
}

#include "main.moc"

    Layout¶

    一个程序中往往一个QWidget만 있는 것은 아니다.所以这些Widget的布局을组织할 필요가 있다. Qt中常用的布局은 BoxLayout이다.这里有一个简单的示例:

    #include <QApplication>
#include <QWidget>
#include <QHBoxLayout>
#include <QPushButton>

class QMainWidget :public QWidget {
    Q_OBJECT
public:
    QMainWidget() {
        createUI();
    }
private:
    void createUI() {
        QHBoxLayout* hLayout = new QHBoxLayout(this);
        // QHBoxLayout* hLayout = new QHBoxLayout();            //等价
        //setLayout(hLayout);

        hLayout->setContentsMargins(5, 5, 5, 5);                //外边距를设置
        hLayout->setSpacing(10);                                //内部元素间隔를设置
        hLayout->setAlignment(Qt::AlignLeft|Qt::AlignVCenter);  //左对齐且垂直居中를设置
        hLayout->addWidget(new QPushButton("A"));
        hLayout->addSpacing(20);                                //空白填充을加入
        hLayout->addWidget(new QPushButton("B"));
        hLayout->addWidget(new QPushButton("C"));
    }
};

int main(int argc, char* argv[]) {
    QApplication a(argc, argv);
    QMainWidget widget;
    widget.resize(300, 300);
    widget.show();
    return a.exec();
}

#include "main.moc"
