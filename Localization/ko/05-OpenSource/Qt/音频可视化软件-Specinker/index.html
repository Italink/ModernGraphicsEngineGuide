    오디오 시각화 소프트웨어—Specinker（이미闭源됨）¶

    서론¶

    많은 친구들이 음악을 좋아할 거라 믿어요. 저도 음악 애호가로, 아무것도 하지 않고 혼자서 음악을 듣는 것을 좋아합니다.

    여러분은 아마 이미 AE, WallpaperEngine, Rainmeter（레이인미터）, Avee 등 오디오 시각화 소프트웨어를 접해봤을 겁니다. AE의 스펙트럼 효과는 정말 강력하지만 렌더링 시간이 너무 길어 고통스럽고, WE와 레이인미터는 월페이퍼 소프트웨어를 주로 하기 때문에 스펙트럼 자료가 너무 적습니다. Avee는 좋은 선택입니다. 만약 Spec이 요구를 충족시키지 못한다면 이를 강력 추천합니다. 이 소프트웨어는 오디오를 입력받아 비디오로 인코딩할 수 있고, 효과도 좋습니다.

    Spec의 초기 목적은 저도 몰래 음악 시각화를 하기 위해 만들었습니다. 처음에는 단순히 스펙트럼을 보여주는 음악 플레이어였지만, 점점 기능이 확장되어 스펙트럼 디자이너로 변했고, 현재는 오디오 시각화 그래픽 엔진으로 발전했습니다. 왜 그래픽 엔진이라고 부를 수 있을까요? 바로 엔진의 기능을 거의 다 가지고 있기 때문입니다.

    만약 up主와 spec의 개발 과정에 관심이 있다면, 마지막에 간단한 설명이 있습니다.

    Specinker란?¶

    Specinker는 up主가 1년 동안 만든 오디오 시각화 그래픽 엔진입니다. 여러 그래픽 효과를 가지고 있으며, 기본적인 스펙트럼 그래픽, 특수 효과 필터, 입자 시스템, 3D 모델 등을 포함합니다. 저는 이러한 그래픽을 패키지화하고 조정 가능한 매개변수를 공개했습니다. 심지어 Lua 스크립트를 작성하여 이러한 매개변수에 적용하여 동적인 효과를 구현할 수 있습니다（예: 자동 회전, 마우스 추적, 리듬에 맞춰 이동 등）.

    간결하고 효율적인 UI¶

    Spec의 GUI 프레임워크는 소프트웨어 위치 변경에 따라 총 5개의 버전이 있었습니다. 아래는 4개의 역사적 인터페이스의 일부 설계 스케치입니다. 현재 Spec은 더 간결한 GUI를 사용하며, 단일 창, 높은 제어 가능성입니다.

    여기서 저는 고성능의 경량 조절 컨트롤을 다시 구현했습니다.

    자료 관리¶

    【调整】 인터페이스에서 【+】를 클릭하여 자료를 추가할 수 있습니다. 추가 후 자료에 기본 ID가 할당되며, 마우스 오른쪽 버튼으로 자료에 대한 작업을 수행할 수 있고, 한 번 클릭하면 자료 위치 조절 컨트롤이 열립니다.

    그룹화: 키보드 Ctrl을 누르면 자료 블록을 여러 개 선택할 수 있습니다. 선택 후 마우스 오른쪽 버튼으로 메뉴를 열어 그룹화할 수 있으며, 그룹화 후 전체 이동이 가능합니다.

    속성 관리¶

    어떤 자료의 속성에 대해 마우스 오른쪽 버튼으로 메뉴를 열 수 있습니다. 복사【Ctrl+C】, 붙여넣기【Ctrl+V】, 실행 취소【Ctrl+Z】, 다시 실행【Ctrl+Y】 등을 수행할 수 있습니다. 이 작업은 현재 속성에 대해 수행된다는 점에 유의해야 합니다.

    또한 속성을 【添加到常用值】할 수 있습니다. 그러면 이 속성은 동일한 이름의 속성의 【常用值】 목록에 계속 표시됩니다. 저는 몇 가지 추가했는데, 예를 들어 【旋转角度】의 【自动旋转】입니다.

    Spec【设置】 인터페이스의 【常用值管理】에서 이러한 값을 관리할 수 있습니다.

    실시간 필터¶

    spec에는 많은 실시간 필터가 구현되어 있습니다. 필터를 사용하면 그래픽이 아주 멋지게 보입니다. 하지만 필터의 리소스 사용량이 높으므로 필터 영역을 가능한 작게 유지해야 합니다.

    스크립트 엔진¶

    자료의 특정 속성을 동적으로 변경하기 위해, 예를 들어 그래픽을 자동으로 회전시키고 싶을 때, 초기 Spec은 【旋转速度】 옵션과 【旋转角度】를 결합하여 구현했습니다. 이 구현 방식에는 많은 문제점이 있습니다.

    • 【旋转速度】와 【旋转角度】가 충돌하기 쉽고, 동기화하기 어렵습니다.
    • 단순한 자동 회전만 구현할 수 있으며, 예를 들어 그래픽이 리듬에 맞춰 자동으로 회전하는 등의 확장이 불가능합니다.

    Spec은 현재 Lua 스크립트를 사용하여 자료의 속성을 동적으로 변경할 수 있습니다. 코드를 사용할 수 있는 속성 앞에는 체크박스가 있으며, 다음과 같습니다.

    체크하면 속성이 코드를 사용하여 계산됩니다. 예를 들어 자동 회전 효과를 구현하려면 다음과 같이 합니다.

    1. 코드 체크박스를 선택합니다.

    1. 코드 편집 버튼을 클릭하여 코드 편집기를 열고 코드를 작성합니다.

    1. 【测试运行】을 클릭하면 그래픽이 자동으로 회전하는 것을 볼 수 있습니다.

    1. 자체 매개변수를 공개할 수 있습니다. 마우스 오른쪽 버튼으로 위치를 클릭하여 float1 변수를 추가합니다.

    1. 이름을 【旋转速度】로 변경합니다.

    1. 코드의 100을 【旋转速度】 매개변수로 대체합니다.

    1. 【旋转速度】 매개변수를 사용하여 조절할 수 있습니다.

    입자 시스템¶

    Spec은 스크립트 엔진과 OpenGL을 기반으로 프로그래밍 가능한 GPU 입자 시스템을 구현했습니다.

    기본 입자 시스템에는 중력과 인력 코드가 추가되어 마우스 추적 기능이 있습니다. 이에 빛나는 효과 필터를 추가하면 효과가 아주 좋습니다.

    다음은 입자 시스템 사용 방법에 대한 상세 설명입니다.

    입자 형태 제어:

    입자 형태는 【图元类型】과 【顶点数据】로 제어됩니다. 기본적으로 【图元类型】은 삼각형 팬을 사용하며, Lua 코드를 사용하여 n각형을 생성합니다.

    코드가 이해하기 어려울 수 있지만, Spec이 정점 데이터 형식을 어떻게 파싱하는지 알아야 합니다. Lua 배열을 구성해야 하며, 세 개의 데이터가 하나의 정점의 xyz를 나타냅니다. 다음 두 가지를 유의해야 합니다.

    • 정점 좌표는 표준화된 좌표를 사용합니다. 즉, xyz의 값 범위는 [-1,1]입니다.
    • Lua 배열의 시작 인덱스는 1입니다.

    예를 들어 정사각형 입자 형태를 만들려면 코드에서 다음과 같이 데이터를 구성합니다.

    【测试运行】을 클릭하고 【图元类型】을 【三角带】로 변경하면 입자 형태가 정사각형으로 변합니다.

    【生成数量】: 초당 생성되는 입자 수를 나타냅니다.

    【生命周期】: 각 입자의 생존 시간을 나타냅니다.

    입자 프로그래밍 가능성 설명:

    입자는 일부 상태 데이터 조합(예: 속도, 크기, 위치, 회전 등)을 가진 것으로, 입자 운동은 이러한 입자 상태를 변경하는 것입니다. Spec의 입자 시스템은 두 가지 코드 인터페이스를 사용합니다.

    【粒子生成器】: 입자의 초기 상태를 생성하는 데 사용되며, 첫 번째 프레임 상태로 간주합니다.

    【运动处理器】: 입자가 생성된 후 매 프레임마다 이 코드를 호출하여 입자 상태를 처리합니다.

    특별히 유의해야 할 점:

    • 이것은 Lua 코드를 통해 구현되지 않습니다. Spec은 GPU 입자를 사용하며, 변환 피드백을 통해 구현되므로 이 코드는 GPU에서 실행됩니다. 따라서 코드 형식은 GLSL(셰이더 언어)입니다.
    • 운동 프로세서의 콘솔 로그를 자세히 읽어야 합니다. 여기서 in은 입력 변수를 나타내며, 구분하기 위해 i로 시작하는 이름을 사용합니다. 예를 들어 변수 【iPosition】은 이전 프레임의 【position】을 나타내며, 코드에서 【position】에 값을 할당하기만 하면 됩니다.

    GLSL 코드를 통해 입자 운동 규칙을 정의할 수 있습니다. 예를 들어 중력, 저항을 추가하거나 충돌 효과를 구현할 수 있습니다. 내용이 많으므로 이후 up主가 자세한 글을 통해 설명할 것입니다.

    UP主와 Specinker에 대해¶

    **UP主**는 구석에서 '흑기사'를 만드는 사람입니다. 처음으로 음악 스펙트럼을 접한 것은 친구의 바탕 화면에서 우연히 본 것이었습니다. 정말 멋졌습니다! 여러분은 이미 어떤 소프트웨어인지 알 것입니다. 바로 Rainmeter（레이인미터）입니다. 집에 돌아온 후 즉시 자료를 찾아 공부했지만, 레이인미터의 프로그래밍 구문은 제가 배운 C/C++와 전혀 다르고 너무 오래된 것 같아 "이걸 배워서 쓸모가 있을까?"라는 생각이 들었습니다. 물론 포기했고, 직접 만들어보려고 했지만 방법이 없었습니다.

    나중에 Qt를 배우면서 공식 예제에서 스펙트럼 분석기 프로젝트를 찾았을 때, 너무 기댔습니다. 하지만 7,000~8,000줄의 코드는当时의 나에게는 산처럼 무거웠습니다. 저는 오디오/비디오 인코딩, 멀티미터 디바이스, 심지어 Qt도 배운 지 몇 달밖에 안 됐지만, 이 프로젝트를 따라할 수 없을까요?

    그래서 코드 로직에 따라 불필요한 코드를 지우기 시작했습니다. 폭탄 해체처럼 코드가 깨지면 이전 백업을 사용하여 다시 삭제했습니다. 2주 동안 노력한 끝에 1,000줄 정도의 핵심 코드로 수정했습니다. 이 과정에서 오디오 처리 흐름에 대한 대략적인 인식을 얻었고, 이 코드를 Qt 그래픽 메커니즘과 결합하여 Specinker의 첫 번째 버전을 완성했습니다.

    지금 보면 정말 초라하지만, 이 작은 것도 2개월이 걸렸습니다.当时 동기들의 격려를 받아 기댔고, 이 프로젝트를 인터넷에 올렸습니다. 놀랍게도 정말로 사람들이 사용했습니다! 그래서 저는 마치 약을 쓴 것처럼疯狂하게 확장하기 시작했습니다. 원래의 스펙트럼 플레이어를 스펙트럼 디자이더로 변경했습니다.

    하지만 중간에 갑자기 생각했습니다. "이건 바탕 화면에 보여주는 거고, 왜 바탕 화면에서 직접 디자인하지 않고 미리보기 창을 만들어야 할까?" 그래서 일부 코드를 버리고 다시 작성했습니다.

    그리고 다음 버전이 나왔습니다（즉, '동음'으로 인터넷에서 많이 사용되는 버전입니다. 많은 분들의 홍보 감사합니다）.

    이 버전은 사용 경험이 많이 개선되었고, 간단하며 사용하기 쉬웠습니다. 코드량도 많아져 10,000줄을 넘었습니다.当时는 선생님에게 "Qt의 색상 선택기를 너무 못생겼다고 생각해서 직접 만든 것이야. 2,000줄 정도 코드를 썼어"라고 말했습니다. 이 버전에서 계속 확장하려 했지만 문제가 발생했습니다. "博主, 바탕 화면 스펙트럼이 약간 지연되고, 그래픽이 약간 끊깁니다." 저는 "이것은 성능을 많이 소모하므로 약간의 끊김이 정상입니다"라고 설명했습니다. 저는 이렇게 믿었지만, 누군가 spec과 wallpaper engine을 비교했을 때, 저는 C++를 과소평가하고 자신을 과대평가했음을 깨달았습니다. 어떻게 해야 할까요? 고쳐야 합니다. 포기할 수 있을까요? 원래 Qt 공식 예제에서 가져온 핵심 코드를 거의 다시 작성했습니다. Qt 멀티미디어 프레임워크를 사용하지 않고 Windows 하위 레벨의 사운드 카드 드라이버 API(IMMDevice)를 사용하여 사운드 카드 데이터를 수집하고, 신호 처리 기술을 사용하여 오디오 데이터를 평활화했습니다. 그 결과 오디오 리듬감이 급격히 향상되었습니다! 지연이 사라지고 리듬감도 좋았습니다.当时 정말 대단하다고 생각했습니다. 하지만 다시 전환점이 왔습니다.

"아, Qt에 흐림 효과가 있지 않나? 그 코드를 가져와 사용해 볼까?" 몇 시간을 소모했지만 여전히 1~2초가 걸렸습니다. 그래서 "이미지 처리에는 opencv를 사용한다고 하지 않나?"라고 생각했습니다. 다시 시도해보니 시간이 확 줄었지만 100ms에 가깝고, 실시간 렌더링은 끊깁니다. 마침내 고성능 렌더링에는 GPU를 사용해야 한다는 것을 알게 되었습니다.知乎에서 검색해보니 GPU 렌더링에는 OpenGL을 사용한다는 것을 알게 되었습니다. 이렇게 밤을 새웠고, 방학 때 집에 돌아와 OpenGL 학습을 시작했습니다.那段时间很枯燥，写着写着就趴桌子上睡着了，不过好在我拉我弟弟垫背，我学OpenGL的时候他也得看书，QQ微信也没怎么用，跟人间蒸发了一样，不过好在坚持了下来，学完OpenGL我没有直接动手，而是去简单学了3d max，UE4，没有学的很深入，但是特别留意他们的架构和功能，最后才开始写代码的，刚好，也到大四了，这个项目也成为了我的毕业设计，然后，也就有了现在的Spec。
